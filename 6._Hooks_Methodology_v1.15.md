**Введение**  
Хуки позволяют перехватывать и модифицировать вызовы browser API (элемент `<canvas>`, 2D-контекст, OffscreenCanvas и WebGL/WebGL2 contexts) без нарушения внешнего нормативного контракта API. Это используется для защиты от fingerprinting, добавления детерминированных корректировок результата, диагностики и доменных runtime-эффектов.
Данное руководство описывает архитектуру модульной системы `ContextPatchModule` / `CanvasPatchModule` / `WebglPatchModule`: как разделены компоненты, как регистрируются и выполняются хуки, где находится hidden state `FernwehContext`, как сохраняется `descriptor/receiver/apply path`, и какие текущие runtime-маршруты используются в [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js), [canvas.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/canvas.js), [webgl.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/webgl.js). Исторические формулы через `safeInvoke`, возврат Proxy-контекста и старые chain-пути сохранены только как контекст эволюции; текущая норма описана через `Reflect.apply`, Core preflight/wrapper path и issued-owner installation.


# Сводные принципы формирования системы

**Единая цель**: каждый файл хуков должен отвечать за одну область (Canvas, WebGL и т.п.).

## 1. Модули и экспорт

Файл [canvas.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/canvas.js) публикует в window realm:

- Функцию-инициализатор `CanvasPatchModule`.
- Объект `FernwehHooks` — набор реализаций конкретных функций-хуков, потребляемый [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) через `registerAllHooks()`.

Важно: [canvas.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/canvas.js) не заменяет identity уже существующего объекта `window.FernwehHooks`. Если контейнер отсутствует, модуль создаёт его; если контейнер уже существует, модуль сохраняет его identity и дополняет свойствами. Позднее [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) потребляет эти экспорты через `registerAllHooks()`. `FernwehHooks` при этом остаётся отдельным window-level export-контейнером, а не вложенным пространством `FernwehContext`.

### Разделение на части

- Инициализация доменного Canvas state из `FernwehContext.state.__CANVAS__.__STATE__`.
- Утилитарные функции (stable keyed coordinate offsets для `fillText` / `strokeText`, квантование `q256` для `fillRect`, PNG ancillary chunk builder, TextMetrics Proxy/cache helpers, drawImage stamp).
- Core hooks (`patchToDataURLInjectNoise`, `patchToBlobInjectNoise`, `patchConvertToBlobInjectNoise`, `applyMeasureTextHook`, `applyDrawImageHook` и др.).
- Регистрация через `C.register...Hook(...)` и применение через issued/prototype routes в [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js).

## 1.2. Именование хуков

- Префикс `patch` или `apply`: `patchToDataURLInjectNoise`, `applyDrawImageHook`.
- Чистые, описательные имена.
- Не смешивать значение и логику (не `fooBar`).

## 1.3. Содержимое хуков

- Идпотентность: повторный вызов не должен накапливать эффект.
- Безопасный apply path: обращения к оригинальным Web IDL methods выполняются через сохранённый `orig` и `Reflect.apply(orig, thisArg, argsArray)`.
- Минимальный охват: хук выполняет только одну задачу.

## Принципы формирования Canvas-хуков

1. Стабильный seed: шум/коррекция должны зависеть от единого seed owner-space `Core.__internal.prng.seed` и профильного state, а не от локального hardcode.
2. Параметризуемость: параметры силы шума, размера блока должны передаваться через аргументы или конфиг.
3. Безопасность: каждый хук проверяет контекст и (если применимо) не вызывает рекурсию.
4. Декомпозиция: отделять executor route от доменного эффекта; для текущего `drawImage` активен native-first hook со single stamp, а не набор сложных фильтров.

# 2. Рекомендации по формированию хуков и патчей для Canvas

## 2.1. Общий принцип формирования хуков

1. Выделить метод-мишень: определить, какой метод Canvas API нуждается в патче.
2. Определить цель хука: noise, искажение, измерение, логирование.
3. Реализовать чистую обёртку:
   - Сохранить оригинал.
   - Выполнить пре-/пост-обработку.
   - Вернуть результат, не изменяя сигнатуру.
4. Зарегистрировать в контексте:
   - Через `C.registerCtx2DFillTextHook(...)`, `C.registerCtx2DMeasureTextHook(...)` и т.д.
5. Протестировать:
   - Проверить, что оригинальное поведение не сломано.

## 2.2. Принципы разделения логики

- Core vs Hooks:
  - Core обеспечивает безопасный доступ.
  - Хуки отвечают за конкретные трансформации.
- Слои ответственности:
  1. Контекстный слой (`ContextPatchModule`): регистрация.
  2. Хуки (`FernwehHooks`): собственно логика.
- Изоляция: общие утилиты (`stableNoiseFromString`, `q256`, PNG ancillary chunk builder, TextMetrics Proxy/cache helpers) должны оставаться отделены от executor routes.


## Архитектура модулей и разделение ответственности

**Обзор компонентов.** Система Canvas-хуков организована многослойно, с чётким разделением ответственности между несколькими модулями:

- **CanvasPatchModule** – доменный модуль Canvas hooks/state. Он проверяет `FernwehContext`, читает `C.state.__CANVAS__.__STATE__`, `C.state.__SCREEN__`, `Core.__internal.prng`, публикует функции в `window.FernwehHooks`, создаёт контейнер при его отсутствии и сохраняет identity уже существующего допустимого контейнера.
- **FernwehHooks** – набор функций-хуков, реализующих конкретные модификации Canvas. Эти функции определяют логику перехвата для отдельных методов (например, `patchToDataURLInjectNoise`, `applyDrawImageHook` и др.). Каждый хук выполняет свою задачу (например, добавление шума, искажение изображения) и может быть зарегистрирован в системе для соответствующего метода Canvas.
- **ContextPatchModule** – слой применения hook registries и descriptor-sensitive runtime routes. В текущем коде он использует issued-owner installation для canvas/offscreen instances, prototype patch для 2D methods через `Core.__wrapNativeApply`, issued-instance WebGL methods после `getContext`, `Core.preflightTarget`, сохранённые native refs и `Reflect.apply`. Он не возвращает Proxy вместо 2D-контекста.
- **Регистраторы хуков** – инфраструктура для хранения и подключения функций-хуков. Глобальный объект (например, `window.FernwehContext` или сокращённо `C`) содержит списки хуков для каждой категории методов и функции-регистраторы для их добавления. Например, `C.ctx2DDrawImageHooks` – массив хуков для `CanvasRenderingContext2D.drawImage`, а `C.registerCtx2DDrawImageHook(fn)` – функция, добавляющая новый хук в этот список. Такие регистраторы позволяют модульно подключать/отключать конкретные хуки, не меняя основного кода патчей.
- **Proxy / carrier-инфраструктура** – не универсальная обёртка над 2D-контекстом. Proxy допустим там, где он является фактическим и нормативно допустимым carrier. В текущем Canvas 2D runtime Proxy применяется для `TextMetrics` result-wrapper в `applyMeasureTextHook`; 2D context сам остаётся реальным host object.

Ниже мы подробнее разберём роль каждого из этих компонентов.

### CanvasPatchModule – инициализация патчей

**CanvasPatchModule** – это входная точка доменной логики Canvas. При инициализации этот модуль выполняет следующие шаги:

1.  **Проверка owner-routes:** требует существующий `FernwehContext`, `FernwehContext.state`, `FernwehContext.state.__CANVAS__.__STATE__`; отсутствие обязательного route является fail-fast для модуля.
2.  **Чтение source-of-truth:** screen metrics берутся из `C.state.__SCREEN__`, seed и PRNG helpers – из `Core.__internal.prng`, font-related state – из `C.state.__FONTS__.__STATE__`. Значения не берутся "ниоткуда".
3.  **Публикация функций-хуков:** модуль создаёт `window.FernwehHooks`, если контейнер отсутствует; если допустимый контейнер уже существует, сохраняет его identity и обновляет свойства. Required exports должны совпадать с [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) `registerAllHooks()`.
4.  **Патчинг выполняет context-layer:** применение к `getContext`, `toDataURL`, `toBlob`, 2D methods и WebGL methods выполняется в [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) через issued/prototype routes. `CanvasPatchModule` не является местом, где напрямую переопределяются runtime methods.

Таким образом, **CanvasPatchModule** предоставляет доменную библиотеку эффектов и state checks, а **ContextPatchModule** связывает её с runtime surfaces.

### FernwehHooks – реализация логики хуков

**FernwehHooks** – это коллекция функций, каждая из которых реализует конкретный хук для Canvas. Эти функции содержат непосредственную логику модификации поведения Canvas API. При проектировании хуков соблюдаются следующие правила:

- **Чистое предназначение:** каждый хук решает одну четко обозначенную задачу: post-process DataURL/Blob, args-transform, TextMetrics wrapper, drawImage stamp, WebGL mask/override или диагностика. Логика должна быть _минимальной и изолированной_, не смешивающей разные эффекты. Это упрощает отладку и замену отдельных хуков при необходимости.
- **Без побочных эффектов и идемпотентность:** повторный вызов одного и того же хука на одних и тех же данных не должен накапливать эффект или приводить к непредсказуемым изменениям. Хук должен стремиться изменить только то, что требуется по его задаче, и использовать текущие guards/markers контекстного слоя, если route допускает повторный вход.
- **Reflect.apply для оригинальных методов:** внутри hook/runtime wrapper нельзя терять receiver. Если хук получает `orig` или `callOrig`, вызов должен сохранять `thisArg` через `Reflect.apply` или предоставленный context-layer callback. Нативный bad-receiver path не подменяется userland-логикой.
- **Минимальное влияние на сигнатуру:** хук-обёртка должен, по возможности, возвращать тот же результат, что и оригинальный метод, и принимать те же аргументы (или совместимые). Хук не должен менять тип возвращаемых данных или порядок параметров – он как бы _прозрачен_ для остальной системы. Например, если `ctx.drawImage()` по спецификации ничего не возвращает, хук после выполнения тоже не должен возвращать ничего особенного (кроме случая, когда он сознательно подменяет результат функции вроде `measureText`).
- **Документирование и поддержка:** каждый хук сопровождается комментарием или JSDoc с описанием его цели, параметров и возвращаемого значения. Важно фиксировать, в каком порядке и где регистрируется данный хук (например: _«этот хук должен регистрироваться **до** базового шума, но **после** X»_), чтобы при изменении порядка регистрации система функционировала правильно.

Примеры функций из `FernwehHooks`:

- `patchToDataURLInjectNoise`: в текущем коде PNG-only post-process строки DataURL через добавление private ancillary `tEXt` chunk; пиксели и IHDR не меняются.
- `patchCanvasIHDRHook`: сейчас disabled/non-required export, оставлен закомментированным как operational switch и не входит в required list `registerAllHooks()`.
- `applyDrawImageHook`: вызывает native draw через переданный `callOrig`, затем при валидных metrics/seed ставит single-pixel deterministic stamp; сложные фильтры blur/pixelate/colorShift/waveDistort не являются текущей runtime-нормой.
- `patchToBlobInjectNoise` / `patchConvertToBlobInjectNoise`: в текущем коде post-process `Blob` для PNG через тот же ancillary chunk builder, без pixel readback.
- `measureTextNoiseHook`, `applyMeasureTextHook`, `fillTextNoiseHook`, `strokeTextNoiseHook`: `measureTextNoiseHook` сейчас даёт metadata path без mutation (`widthNoise = 0`), `applyMeasureTextHook` может вернуть TextMetrics Proxy, а text drawing hooks выполняют малые stable keyed offsets координат.

FernwehHooks – это **«библиотека эффектов»** для Canvas API. Эти функции сами по себе ничего не патчат; они становятся активными только после регистрации в системе (через `C.register...Hook`). Таким образом, можно конфигурировать поведение: добавляя или убирая определенные хуки из регистрации, мы меняем то, как Canvas будет себя вести.

### ContextPatchModule – issued routes, Core wrappers и патчинг методов

**ContextPatchModule** отвечает за низкоуровневое связывание hook registries с браузерными surfaces. Он не создаёт `FernwehContext` заново: `C = window.FernwehContext` должен уже существовать. Downstream recreation `window.FernwehContext = {}` или `|| (window.FernwehContext = {})` запрещена.

Основные задачи текущего [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js):

- **Инициализация hook registries и patch state:** `C.htmlCanvasToDataURLHooks`, `C.htmlCanvasToBlobHooks`, `C.offscreenConvertToBlobHooks`, `C.ctx2DMeasureTextHooks`, `C.ctx2DDrawImageHooks`, WebGL hook arrays, `C.__patchState`, `C.__hookModeStore`, `C.__KEEP_NATIVE_WL__`, `C.__GATEWAY_METHODS__`.
- **Сохранение native refs:** исходные methods сохраняются в `C.__keptNativeRefs__` до patch. Повторное чтение `obj[key]` после patch не считается допустимым способом получить `orig`.
- **Issued canvas/offscreen routes:** `toDataURL`, `toBlob`, `convertToBlob`, `getContext` устанавливаются как own methods на issued canvas/offscreen owners с descriptor flags исходного prototype descriptor.
- **2D prototype route:** 2D methods (`getImageData`, `putImageData`, `measureText`, `fillText`, `strokeText`, `fillRect`, `drawImage`) патчатся на prototype через `Core.__wrapNativeApply` и `definePatchedMethod(...)`, после `Core.preflightTarget(...)`.
- **WebGL issued-instance route:** WebGL/WebGL2 methods (`getParameter`, `getSupportedExtensions`, `getExtension`, `readPixels`, `getShaderPrecisionFormat`, `shaderSource`, `getUniform`) устанавливаются на issued WebGL context instance после `getContext(...)`.

В коде ContextPatchModule предусмотрены **предохранители**:

- `Core.preflightTarget(...)` проверяет descriptor/kind/wrapLayer до descriptor-sensitive define.
- `definePatchedMethod(...)` требует явный `wrapLayer`; отсутствие corridor является contract error.
- `guardInstance(proto, self)` используется как runtime guard; invalid receiver должен уходить в native path через `Reflect.apply(orig, self, args)`, а не в userland-имитацию `Illegal invocation`.
- Для issued routes используются `WeakSet` guards (`issuedSerializationPatchedOwners`, `issuedWebGLPatchedContexts`, `issuedGetContextPatchedOwners`) и per-call reentrancy guards.
- Все controlled failures должны идти через `emitContextDiag(...)` -> `C.__logger.__DEGRADE__.diag(...)`.

**Итого, ContextPatchModule создает уровень перехвата**, где сохраняется внешний surface contract: descriptor flags, receiver/apply path, native bad-receiver behavior, toString bridge через Core и API-specific return value.

### Carrier / Proxy для CanvasRenderingContext2D и TextMetrics

Исторически этот раздел описывал `createSafeCtxProxy(ctx)` как Proxy над `CanvasRenderingContext2D`. Это больше не соответствует текущему runtime.

Фактическое состояние:

- `createSafeCtxProxy(ctx)` сохраняет историческое имя, но возвращает реальный `ctx`, а не `new Proxy(ctx, ...)`.
- Для 2D-context methods carrier создаётся через `Core.__wrapNativeApply(orig, method, applyImpl)`.
- Вызов оригинала выполняется как `Reflect.apply(target, thisArg, argList || [])`.
- `Function.prototype.toString` / wrapper bridge обслуживаются Core, а не локальным `safeInvoke`/Proxy-layer.
- Proxy над browser host object не используется как общий способ "починить" detached method call; detached/bad receiver должен проходить через нормативный native path.

Схематично текущий 2D method path:

```js
const orig = resolveKeptNative(proto, method) || proto[method];
const wrapped = Core.__wrapNativeApply(orig, method, (target, thisArg, argList) => {
  // hook logic
  return Reflect.apply(target, thisArg, argList || []);
});
definePatchedMethod(proto, method, wrapped, {
  wrapLayer: 'core_wrapper',
  policy: 'throw',
  invokeClass: 'brand_strict'
});
```

Proxy в текущем Canvas 2D path применяется точечно для `TextMetrics`:

- `measureText` сначала вызывает native method;
- `applyMeasureTextHook(nativeMetrics, text, font)` может вернуть `Proxy(nativeMetrics)`;
- Proxy меняет/кэширует только чтение поддерживаемых numeric fields и не мутирует engine-owned `TextMetrics`;
- если fonts state не готов, возвращается native `TextMetrics`.

Таким образом, актуальная формула не "Canvas.getContext возвращает Proxy", а "getContext возвращает real ctx; методы ctx проходят через Core apply wrapper; TextMetrics может быть result Proxy".

### Хук-регистраторы и списки вызовов

**Глобальный объект C (FernwehContext).** `ContextPatchModule` использует `C = window.FernwehContext` как hidden root / hidden container bootstrap-уровня для hook-layer state. Он не является публичным API и не должен пересоздаваться downstream-модулями. В нём присутствуют массивы-хранилища для каждого вида хуков. Например:

- `C.htmlCanvasToDataURLHooks` – список хуков для `HTMLCanvasElement.prototype.toDataURL`.
- `C.ctx2DDrawImageHooks` – список хуков для `CanvasRenderingContext2D.drawImage`.
- `C.ctx2DMeasureTextHooks`, `C.ctx2DFillTextHooks`, `C.ctx2DStrokeTextHooks`, `C.ctx2DFillRectHooks`.
- `C.htmlCanvasToBlobHooks`, `C.offscreenConvertToBlobHooks`.
- WebGL списки: `C.webglGetParameterHooks`, `C.webglGetSupportedExtensionsHooks`, `C.webglGetExtensionHooks`, `C.webglReadPixelsHooks`, `C.webglGetShaderPrecisionFormatHooks`, `C.webglShaderSourceHooks`, `C.webglGetUniformHooks`.

Каждый такой список наполняется через соответствующую функцию-регистратор:

```js
C.registerCtx2DDrawImageHook = fn => registerOnce(C.ctx2DDrawImageHooks, fn);
```

Подобные функции существуют для всех типов хуков: `registerHtmlCanvasToBlobHook`, `registerCtx2DMeasureTextHook`, `registerWebGLGetContextHook`, и т.д. В текущем коде они используют `registerOnce(...)`: не-функция не регистрируется, дубликат не добавляется.

**Порядок регистрации имеет значение.** Поскольку хуки хранятся в массивах и выполняются последовательно, **важно документировать порядок, в котором регистрируются хуки**. Текущий `toDataURL` регистрирует `masterToDataURLHook`. Для WebGL `getParameter` регистрируются `webglGetParameterMask`, затем `webglWhitelistParameterHook`; для `readPixels` используется mode `C.__hookModeStore.post_orig_once`. При добавлении новых хуков порядок должен соответствовать фактическому hook executor path.

**Лёгкое отключение хуков.** Благодаря централизации регистраций, при необходимости можно отключить определенный хук или все сразу. Несколько стратегий:

- _Глобальный флаг:_ новый публичный `window.CanvasHookEnabled` не является текущей нормой. Управление должно идти через профиль/state/registries, а не через новый public hardcode-флаг.
- _Удаление из списка:_ Убрать функцию из массива `C.ctx2DDrawImageHooks` или очистить массив – тогда она не будет вызываться. Так как сами методы уже пропатчены, важно убирать аккуратно (в идеале до инициализации или переинициализируя модуль).
- _Перепривязка оригиналов:_ текущий источник original refs — `C.__keptNativeRefs__` и local closure refs, полученные до patch. Пометка `CanvasGlobal` не является актуальной нормой; для idempotency используются `C.__patchState`, `WeakSet` guards и `patchedMethods`.

Итак, **регистраторы хуков обеспечивают модульность**: логика хуков отделена от места их применения. Можно иметь несколько файлов с реализацией хуков (например, отдельный файл для WebGL-хуков), которые через API регистратора подключаются к общей системе, не вмешиваясь в сам механизм патчей. Это согласуется с принципом "_каждый файл хуков отвечает за свою область (Canvas, WebGL и т.п.)_".

## Принципы разработки и реализации Canvas-хуков

При создании новых хуков для Canvas API следует придерживаться методического подхода. Ниже приведён **пошаговый процесс разработки хука** и ключевые принципы, гарантирующие корректность и безопасность патчей.

### Шаги создания хука (workflow)

1.  **Выбрать целевой метод:** Определите, какой метод Canvas API требует перехвата. Обычно выбор основан на анализе того, какие действия могут использоваться для нежелательного поведения (например, снятие отпечатков). Примеры: `HTMLCanvasElement.toDataURL`, `CanvasRenderingContext2D.drawImage`, `getImageData`, `fillText` и т.д..
2.  **Определить цель хука:** Что вы хотите сделать при перехвате этого метода? Варианты: post-process результата, deterministic args-transform, измерение параметров вызова, WebGL override или post-native действие. Чётко сформулируйте задачу в терминах фактического executor path: _«После native `ctx.drawImage` поставить deterministic stamp при валидном state»_ или _«После native `canvas.toDataURL` добавить PNG ancillary chunk, не меняя pixels/IHDR»_.
3.  **Сохранить оригинал метода:** Перед тем как патчить метод, обязательно сохранить ссылку на исходную функцию. В текущем pipeline это делает context-layer через `captureKeepNativeRefs()` / `resolveKeptNative(...)` и closure refs. Хук не должен искать original через `obj[key]` после patch. Если хук должен вызвать native operation, он получает `orig` или `callOrig` от context-layer.
4.  **Реализовать чистую hook function:** Напишите функцию, которая обрабатывает вызов метода в конкретном executor mode. Общие текущие подходы:
    - **Post-result processing:** `toDataURL` получает уже native строку `res`; hook может вернуть новую строку. `toBlob`/`convertToBlob` получают `Blob` после native encode и могут вернуть `Blob`/Promise<Blob>.
    - **Args-transform:** `fillText`, `strokeText`, `fillRect` hooks могут вернуть массив аргументов, который будет передан native method через `Reflect.apply`.
    - **Post-native with callOrig:** `drawImage` hook получает `callOrig`, сам вызывает native draw и затем выполняет доменную post-обработку.
    - **Override/result path:** WebGL issued hooks получают `[orig, ...args]`; non-`undefined`, non-`Array` result становится override return, `Array` result меняет args. Для `post_orig_once` сначала выполняется native call, hook не имеет права повторно вызывать orig.
    - **Сохранение сигнатуры:** Ваша функция должна соответствовать фактическому executor path. Например, `applyMeasureTextHook(nativeMetrics, text, font)` работает после native `measureText`, а `measureTextNoiseHook` сейчас является info/helper hook и сам не мутирует metrics.

    После выполнения нужной логики **верните результат по режиму executor**: изменённые аргументы, конкретное override-значение, post-processed DataURL/Blob/Promise или `undefined`, если обработка завершена и native result должен остаться источником истины.

5.  **Зарегистрировать хук:** В соответствующем месте инициализации добавьте hook в [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) `registerAllHooks()` и убедитесь, что [canvas.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/canvas.js) / [webgl.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/webgl.js) публикует required export в соответствующем `window.FernwehHooks` / `window.webglHooks` export-контейнере. Для `window.FernwehHooks` действует отдельное правило: создать контейнер при отсутствии, но сохранить identity уже существующего допустимого контейнера. Нельзя добавлять export без синхронизации required list.
6.  **Применить/обновить patch route:** Убедитесь, что целевой метод действительно имеет route в [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js): issued serialization, issued getContext, 2D Core wrapper или issued WebGL method. Если route descriptor-sensitive, нужен `Core.preflightTarget`, явный `wrapLayer`, сохранение descriptor flags и observed failure path.
_Примечание:_ `CanvasRenderingContext2D.getImageData` и `putImageData` сейчас проходят через native pass-through wrapper.

7.  **Тестирование:** После подключения хука, протестируйте его в различных сценариях:
    - Вызов целевого метода в штатном режиме (ожидается корректный результат, возможно с вашим эффектом). Например, для `toDataURL` проверить тип строки и корректность PNG ancillary chunk, а не ожидать pixel diff как обязательный текущий эффект.
    - Граничные случаи: вызов метода вне контекста (например, сохранённой функцией), в разных браузерах, с разными аргументами. В идеале написать unit-тесты, но здесь отмечено, что мы не фокусируемся на них – однако простые проверки вручную очень желательны.
    - Проверьте, **не сломано ли оригинальное поведение**: если отключить эффекты, результат должен быть идентичен исходному. Например, ваш хук `measureTextNoiseHook` не должен вдруг менять тип возвращаемого значения или кидать исключения.

Следуя этим шагам, вы создадите хук, который встроится в общую инфраструктуру без регрессий.

### Ключевые принципы проектирования хуков (резюме)

Помимо описанного процесса, используйте такие принципы при проектировании архитектуры хуков:

- **Carrier/Core wrapper vs Hooks – разделение задач:** низкоуровневый слой отвечает за descriptor/receiver/apply path, сохранение native refs, preflight и маршрутизацию вызова. В текущем Canvas 2D runtime это не Proxy-контекст, а Core wrapper и `Reflect.apply`. Все доменные преобразования выполняются в функциях-хуках (`FernwehHooks`). Proxy допустим только как точечный carrier там, где это фактически реализовано и не ломает host object invariants, например для `TextMetrics`.
- **Слои ответственности:** Можно мысленно выделить три слоя:
  1.  _Контекстный слой перехвата_ – `ContextPatchModule`, выполняющий issued-owner/prototype/issued-instance установку методов, preflight и native apply route.
  2.  _Слой логики хуков_ – FernwehHooks, где реализованы конкретные эффекты.
  3.  _Утилиты и общие функции_ – вспомогательные функции для stable keyed coordinate offsets, квантования `q256`, PNG ancillary chunk builder, TextMetrics Proxy/cache wrapper, drawImage stamp и WebGL masks. Эти утилиты должны брать данные из `FernwehContext.state`/Core PRNG, а не из новых публичных hardcode-глобалов.

- **Локальность и минимальный охват:** если хук вносит изменения, он должен затрагивать только свой результат/аргументы. В текущем `drawImage` это один deterministic stamp после native draw при валидном state, а не full-region filter pipeline. В `toDataURL`/`toBlob` это PNG ancillary chunk post-process, а не readback всех пикселей canvas.
- **Стабильность и повторяемость:** псевдослучайность должна идти из одного источника истины: `Core.__internal.prng.seed`, профильные словари и `FernwehContext.state`. Старые формулы через `window.__GLOBAL_SEED`, `window._rand`, `window._NEW_WIDTH/_NEW_HEIGHT` не являются текущей нормой этого pipeline.
- **Безопасность от рекурсии и повторной инициализации:** текущая идемпотентность обеспечивается `C.__patchState`, WeakSet/WeakMap guards, `patchedMethods`, saved native refs и mode store. Метки `CanvasGlobal`/`__isChain_method` не должны рассматриваться как действующий контракт.
- **Декомпозиция эффектов:** сложный эффект следует разбивать на domain hooks и утилиты, но документ должен фиксировать только реально активные ветки. В текущем `applyDrawImageHook` активен native-first path с deterministic stamp; `blur`/`pixelate`/`colorShift`/`waveDistort` не являются фактическим runtime path.
- **Проверка типа контекста:** Убеждайтесь, что ваш хук выполняется только в уместном контексте. В коде часто встречается проверка `if (!(this instanceof HTMLCanvasElement || ... OffscreenCanvas)) return res;` внутри хуков для canvas, или проверка `type === '2d'` при getContext. Это нужно, чтобы, например, не пытаться применить 2D-шум к WebGL-контексту. Наш guardInstance также работает на это.

Придерживаясь этих принципов, вы получите систему, которая **расширяема, безопасна и поддерживаемая**. Добавление новых хуков не сломает старые, а снятие всех патчей вернет Canvas к нормальному поведению без побочных эффектов.

## Поток вызовов в системе Canvas-хуков

Теперь рассмотрим, как происходит **прохождение вызова** через текущую инфраструктуру – от момента, когда сторонний код вызывает метод Canvas API, до выполнения хуков и получения результата. Важная актуализация: текущая архитектура не строится как “Canvas.getContext → Proxy context → safeInvoke → chain”. Фактическая формула:

**issued owner / Core wrapper → Reflect.apply(native orig, receiver, args) → hook phase → API result**.

### 1\. Перехват `canvas.getContext('2d')`

<small>_Диаграмма: текущая последовательность при вызове getContext_</small>

1.  **Пользовательский код:**

```js

const canvas = document.getElementById('myCanvas');
const ctx = canvas.getContext('2d');
```

Разработчик вызывает стандартный метод получения контекста.

2.  **Issued owner method:** текущий [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) устанавливает own `getContext` на issued canvas/offscreen owner через `installIssuedGetContextMethod(owner, ...)`, если owner ещё не имеет own `getContext`.

```js

const res = Reflect.apply(orig, self, args);
```

Native original вызывается с тем же receiver (`self`), который пришёл от пользовательского вызова. Userland не исправляет bad receiver.

3.  **2D context path:** если `type === '2d'` и контекст получен:
    - вызывается `createSafeCtxProxy(ctx)`, но эта функция возвращает реальный `ctx`, а не Proxy;
    - внутри `createSafeCtxProxy` once-per-method устанавливаются prototype wrappers для 2D methods через `Core.__wrapNativeApply`;
    - сохраняется default font в `C.state.__CANVAS__.__STATE__.defaultCtx2dFont`;
    - затем исполняются `C.ctx2DGetContextHooks`, если они зарегистрированы:

```js

ctx = hook.call(self, ctx, type, ...rest) || ctx;
```

4.  **WebGL path:** если `type` начинается с `webgl`, `installIssuedWebGLMethods(ctx)` устанавливает own methods на issued WebGL context instance, затем исполняются `C.webglGetContextHooks`.

5.  **HTML canvas getContext hooks:** после domain-specific path исполняются `C.htmlCanvasGetContextHooks`.

6.  **Возврат значения:** наружу возвращается реальный CanvasRenderingContext2D/WebGL context object или native result. Для 2D это не Proxy-контекст.

```js

const ctx = canvas.getContext('2d'); // ctx is real context object, not Proxy
```

Для внешнего кода `ctx` должен сохранять нормальные свойства host object: `instanceof`, prototype owner, native receiver checks. OffscreenCanvas получает аналогичный issued-owner route, но также не обязан возвращать Proxy-контекст.

**Итог:** После `getContext` у нас есть реальный контекст, а его method-family route подготовлен context-layer через Core wrappers / issued WebGL methods.

### 2\. Вызов методов контекста через Core wrapper и хуки

Рассмотрим теперь, что происходит, когда пользовательский код начинает работать с полученным контекстом. В качестве примера возьмём популярные действия:

- Рисование изображения: `ctx.drawImage(img, x, y)`
- Получение данных: `ctx.getImageData(x, y, w, h)`
- Прочие, вроде текста: `ctx.fillText("Hello", x, y)`

**Сценарий: `ctx.drawImage(image, dx, dy)`** (текущий post-native hook path):

1.  **Пользовательский код:**

```js

    ctx.drawImage(imageElement, 10, 20);
```

Вызывает метод рисования на реальном 2D-контексте.

2.  **Core wrapper:** на prototype уже установлен wrapper, созданный через `Core.__wrapNativeApply`. Он получает `target`, `thisArg`, `argList` и не использует Proxy `get` trap.

```js

const callOrig = (...a) => Reflect.apply(target, thisArg, a);
return H.applyDrawImageHook.call(thisArg, callOrig, ...args);
```

3.  **Native call внутри hook:** `applyDrawImageHook` получает `callOrig`, вызывает native draw и только после этого выполняет доменную post-обработку:

```js

function applyDrawImageHook(callOrig, ...args) {
  const beforeSize = readDrawTargetBitmapSize(this, 'drawImage:pre');
  const out = callOrig(...args);
  const afterSize = readDrawTargetBitmapSize(this, 'drawImage:post');
  // if state is valid and size is stable: single-pixel deterministic stamp
  return out;
}
```

4.  **Fallback path:** если `applyDrawImageHook` отсутствует, wrapper в этом случае вызывает native target:

```js
return Reflect.apply(target, thisArg, args);
```

Текущая доменная post-обработка `drawImage` ставит один детерминированный stamp при валидном state; при missing metrics/seed или нестабильном bitmap size текущий код диагностирует и возвращает native draw result.

5.  **Возврат в пользовательский код:** Для вызывающего кода `ctx.drawImage(...)` завершается как нативный method (`undefined` при успехе). Receiver/apply path сохраняется через Core wrapper и `Reflect.apply`.

**Другие методы:**

- `ctx.getImageData(x,y,w,h)`: текущий wrapper вызывает native path через `Reflect.apply(target, thisArg, argList || [])`.

```js
return Reflect.apply(target, thisArg, argList || []);
```

- `ctx.putImageData(imgData, dx, dy)`: текущий wrapper также является native pass-through.

- `ctx.fillText(text, x, y)` / `strokeText`: wrapper вызывает соответствующий hook, hook может вернуть новый array аргументов, затем native method вызывается через `Reflect.apply`.

```js
let callArgs = [text, x, y, ...rest];
const a = H.fillTextNoiseHook.apply(thisArg, callArgs);
if (Array.isArray(a)) callArgs = a;
return Reflect.apply(target, thisArg, callArgs);
```

- `measureText`: native `target` вызывается первым. `applyMeasureTextHook(nativeMetrics, text, fontStr)` может вернуть `Proxy(nativeMetrics)`, но `measureTextNoiseHook` сам не мутирует metrics и сейчас держит `widthNoise = 0`.

```js
const m = Reflect.apply(target, thisArg, [txt]);
const r = Reflect.apply(H.applyMeasureTextHook, thisArg, [m, txt, fontStr]);
return r ?? m;
```

Текстовые хуки не должны мутировать engine-owned objects напрямую и не должны заменять receiver path. Их допустимый эффект: stable keyed coordinate offsets для draw-text methods и result-wrapper для `TextMetrics`.

**Asynchronous path (`toBlob`):** Рассмотрим еще отдельно `canvas.toDataURL()` и `canvas.toBlob()`:

- `canvas.toDataURL()`: текущий issued method сначала вызывает native `orig` через `Reflect.apply`, получает строку result, затем post-process hooks получают `res`. `masterToDataURLHook` вызывает `patchToDataURLInjectNoise`, который для PNG добавляет private ancillary `tEXt` chunk. Pixel readback и IHDR mutation не являются текущим runtime path.

- `canvas.toBlob(callback, type, quality)`: native `toBlob` вызывается с wrapped callback. Hook получает `Blob` после native encode и может вернуть `Blob`/Promise<Blob>. Текущий `patchToBlobInjectNoise` для PNG использует shared ancillary chunk builder, без `getImageData`/`putImageData`.

Итак, **архитектура вызовов** выглядит строго и последовательно:

- **Регистрация:** Сначала нужные хук-функции добавляются в списки.
- **Патчинг:** methods получают issued-owner route или Core prototype wrapper.
- **Вызов метода:** → _Перехват обёрткой:_
  - serialization methods: native result first, then post-process hook;
  - 2D methods: Core wrapper, hook phase, `Reflect.apply`;
  - WebGL methods: issued-instance hook executor.

- **Reflect.apply в ключевых местах:** сохраняет receiver/apply path.
- **Выполнение хуков:** Каждый зарегистрированный хук-функция выполняется либо **до**, либо **после** оригинала, в зависимости от типа обёртки:
  - post-result hooks для serialization;
  - args-transform hooks для text/fillRect;
  - callOrig/post-native hook для drawImage;
  - override/args-transform или `post_orig_once` для WebGL.

- **Результат:** Возвращается результат, который ожидается по спецификации. (Если метод не возвращал ничего, так и есть; если должен вернуть данные – возвращаются модифицированные данные или слегка измененные объекты).

Это архитектура “issued/Core wrapper → native apply → hook → result” по каждому вызову. Ключевое: **все происходит прозрачно для вызывающей стороны**, но каждый шаг контролируется нашей системой и наблюдаем через `__DEGRADE__.diag`.

## Хуки для ключевых методов Canvas API

В предыдущем разделе мы уже частично рассмотрели, как обрабатываются разные методы. Сведём воедино основные Canvas/WebGL surfaces, которые обслуживаются хуками, и зафиксируем текущий runtime contract: `issued owner / Core wrapper → Reflect.apply(native original, receiver, args) → hook phase → API result`.

### HTMLCanvasElement.prototype.getContext

- **Цель перехвата:** сохранить нативный `getContext` receiver path, получить реальный context object, затем подключить нужные issued/prototype routes для 2D или WebGL без замены context identity.
- **Как патчится:** [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) устанавливает own `getContext` на issued canvas/offscreen owner. Нативный метод вызывается через `Reflect.apply(orig, this, args)`. Для `2d` вызывается `createSafeCtxProxy(ctx)`, но это историческое имя: функция возвращает реальный `ctx`, а не `Proxy`. Внутри один раз устанавливаются Core wrappers для 2D prototype methods.
- **2D path:** `ctx2DGetContextHooks` получает реальный 2D context; дополнительно сохраняется default font. `getImageData`, `putImageData`, `measureText`, `fillText`, `strokeText`, `fillRect`, `drawImage` идут через prototype wrappers.
- **WebGL path:** после native `getContext` вызывается `installIssuedWebGLMethods(ctx)`, который ставит issued-instance wrappers на конкретный WebGL context.
- **Ожидаемое поведение:** `canvas.getContext('2d')` возвращает host object, совместимый с `CanvasRenderingContext2D`; `instanceof`, prototype owner и native receiver checks не должны ломаться. Proxy-контекст не является текущей нормой.

### CanvasRenderingContext2D.prototype.drawImage

- **Цель хука:** сохранить нативное рисование и при валидном state добавить минимальный детерминированный post-effect, достаточный для anti-fingerprint, без full-region filter pipeline.
- **Реализация:**
  - wrapper установлен на prototype через `Core.__wrapNativeApply` и `definePatchedMethod(...)`;
  - hook получает `callOrig = (...a) => Reflect.apply(target, thisArg, a)`;
  - `applyDrawImageHook` вызывает native draw первым, затем читает размер target bitmap до/после и при валидных `screen metrics`, `seed`, `bitmap size` ставит один deterministic stamp;

- **Ожидаемое поведение:** метод возвращает нативный результат (`undefined` при успешном draw). Если post-condition для stamp не выполнена, текущий код диагностирует ситуацию и возвращает native draw result; это место важно учитывать как degrade/return-native path.

### CanvasRenderingContext2D.prototype.getImageData

- **Цель текущего wrapper:** сохранить descriptor/receiver/apply path и native bad-receiver behavior.
- **Реализация:** текущий [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) вызывает native `getImageData` через `Reflect.apply(target, thisArg, argList || [])`.
- **Ожидаемое поведение:** результатом остаётся нативный `ImageData` с теми байтами, которые возвращает движок. Если нужен readback-noise hook, его надо проектировать отдельно и явно, не описывать как уже действующий.

### CanvasRenderingContext2D.prototype.putImageData

- **Цель текущего wrapper:** сохранить нативную запись `ImageData` и корректный receiver path.
- **Реализация:** текущий wrapper является native pass-through через `Reflect.apply`. 
- **Ожидаемое поведение:** `putImageData` ведёт себя как нативный метод. Любой будущий hook должен отдельно доказывать, что не ломает mutability/ownership `ImageData`, dirty rectangle semantics и native exception path.

### HTMLCanvasElement.prototype.toDataURL

- **Цель хука:** пост-обработать уже полученную строку результата, не трогая canvas pixels перед native encode и не нарушая синхронный контракт `toDataURL`.
- **Реализация:**
  - issued own method сначала вызывает native `orig` через `Reflect.apply(orig, this, patchedArgs)` и получает строку `res`;
  - hooks из `C.htmlCanvasToDataURLHooks` получают `res` и могут вернуть новую строку;
  - текущий `masterToDataURLHook` вызывает `patchToDataURLInjectNoise`;
  - `patchToDataURLInjectNoise` для PNG добавляет private ancillary `tEXt` chunk через PNG chunk builder;
  - pixel readback, pre-encode mutation и IHDR mutation не являются текущим route;
- **Ожидаемое поведение:** наружу возвращается строка DataURL. Для PNG она может отличаться за счёт ancillary chunk, но размеры IHDR и bitmap pixels не должны описываться как изменяемые текущим активным hook.

### HTMLCanvasElement.prototype.toBlob

- **Назначение метода:** `HTMLCanvasElement.prototype.toBlob(callback, type, quality)` асинхронно формирует `Blob`, содержащий растеризованное изображение текущего состояния canvas. Если `type` не указан, браузер использует формат по умолчанию `image/png` (см. MDN: https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob).

- **Цель хука:** пост-обработать `Blob` после native encode, сохраняя callback-сигнатуру и native receiver path.
- **Фактический механизм:**
  1. Issued own method создаёт wrapped callback.
  2. Нативный `toBlob` вызывается через `Reflect.apply(orig, this, patchedArgs)`.
  3. Когда движок вызывает callback, hooks получают уже готовый `Blob`.
  4. Текущий `patchToBlobInjectNoise` для PNG использует тот же PNG ancillary chunk builder, что и DataURL path.
- **Риск/несостыковка:** при failure post-processing текущий callback path может вернуть original blob после diag. Это следует считать фактическим return-native/degrade path и отдельно сверять с fail-fast контрактом, если задача касается исправления runtime code.

### OffscreenCanvas.prototype.convertToBlob

- **Назначение метода:** promise-based serialization для `OffscreenCanvas`.
- **Фактический механизм:** issued own `convertToBlob` вызывает native method, затем post-process hooks в promise `.then(...)`. Текущий `patchConvertToBlobInjectNoise` работает по той же PNG ancillary chunk модели, без pixel readback.
- **Ожидаемое поведение:** наружу возвращается `Promise<Blob>`; hook не должен превращать promise contract в синхронный путь.

### CanvasRenderingContext2D.prototype.fillText / strokeText / fillRect / measureText

_(Рассматриваем вместе, так как цель общая – защита текстовых характеристик.)_

- **Цель хуков:** затруднить fingerprinting по текстовому рендерингу, метрикам и простым fill operations, сохраняя совместимость Canvas-API.

- **Ключевой принцип совместимости:** мы **не мутируем** объекты, которые движок возвращает как read-only/engine-owned, и не меняем сигнатуры методов:
  - `measureText()` возвращает `TextMetrics` (см. MDN: https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/measureText).
  - `TextMetrics.width` является read-only (см. MDN: https://developer.mozilla.org/en-US/docs/Web/API/TextMetrics/width).
  - `fillText()`/`strokeText()` ничего не возвращают (`undefined`) и воздействие производится через аргументы вызова (см. MDN: https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/fillText и https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/strokeText).

---

#### measureText(text) — native first + optional Proxy над `TextMetrics`

- **Механизм:**
  1. Оригинальный `measureText` вызывается первым через `Reflect.apply` и возвращает native `TextMetrics`.
  2. `applyMeasureTextHook(nativeMetrics, text, fontStr)` может вернуть `Proxy(nativeMetrics)`.
  3. `measureTextNoiseHook` сейчас является metadata/info hook и держит `widthNoise = 0`; документ не должен описывать активное смещение width как факт runtime.

Пример (схематично):

```js
const nativeMetrics = Reflect.apply(nativeMeasureText, thisArg, args);
const wrapped = applyMeasureTextHook(nativeMetrics, String(args[0]), thisArg.font);
return wrapped || nativeMetrics;
```

---

#### fillText(text, x, y, maxWidth?) / strokeText(text, x, y, maxWidth?) — stable keyed offsets координат

- **Механизм:** hook может вернуть новый массив аргументов. Текущие `fillTextNoiseHook`/`strokeTextNoiseHook` вычисляют малые детерминированные смещения `(Δx, Δy)` из Core PRNG/stable string noise и добавляют их к координатам. Остальные аргументы передаются без изменений.

Пример (схематично):

```js
const nextArgs = hook.call(thisArg, args, fontState, seedState);
return Reflect.apply(nativeMethod, thisArg, Array.isArray(nextArgs) ? nextArgs : args);
```

- **Почему это безопасно:**
  - возвращаемое значение остаётся `undefined` (как в нативном API);
  - смещения малые и обычно визуально незаметны, но меняют субпиксельное позиционирование/сглаживание, что разрушает пиксель-перфект совпадения, используемые в fingerprinting.

---

- **Ожидаемое поведение:** визуально текст остаётся «тем же», но:
  - `measureText(...).width` сейчас не обязан отличаться, потому что активный `measureTextNoiseHook` держит `widthNoise = 0`;
  - `fillText`/`strokeText` рисуют текст с микросмещением координат, что влияет на пиксельный результат при последующем readback (`getImageData`).
  - `fillRect` проходит через args-transform hook (`fillRectNoiseHook` / `q256`) и сохраняет native return semantics.

### Примечание: OffscreenCanvas и WebGL

Хотя вопрос сосредоточен на Canvas 2D, аналогичные принципы применяются к OffscreenCanvas и WebGL, но route отличается:

- **OffscreenCanvas 2D:** использует issued-owner route для `getContext` и serialization methods. Документ не должен утверждать, что OffscreenCanvas `getContext('2d')` возвращает Proxy: текущая норма такая же, как для HTMLCanvasElement, то есть real context object.
- **WebGL:** после `getContext` на конкретный WebGL context ставятся issued-instance methods: `getParameter`, `getSupportedExtensions`, `getExtension`, `readPixels`, `getShaderPrecisionFormat`, `shaderSource`, `getUniform`. `readPixels` работает в mode `C.__hookModeStore.post_orig_once`: native вызывается первым, hook не должен сам повторно вызывать orig.

## Фактическая карта текущего pipeline

### [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js)

- Требует уже существующий `window.FernwehContext`; не пересоздаёт root object и не меняет его identity.
- Держит runtime state: `C.__READY__`, `C.__patchState`, `C.__hookModeStore.post_orig_once`, `C.__KEEP_NATIVE_WL__`, `C.__GATEWAY_METHODS__`, `C.__keptNativeRefs__`.
- Сохраняет native refs через `captureKeepNativeRefs(...)` / `resolveKeptNative(...)`; позднее чтение `obj[key]` после patch не является источником истины для original method.
- Диагностика идёт через `emitContextDiag(...)` в `C.__logger.__DEGRADE__.diag`.
- `definePatchedMethod(...)` требует explicit `wrapLayer`, preflight, descriptor flags и `Core.__wrapNativeApply`.
- Issued serialization routes: own methods на issued canvas/offscreen owner для `toDataURL`, `toBlob`, `convertToBlob`.
- `installIssuedGetContextMethod(...)` ставит own `getContext`; 2D возвращает real context object, WebGL получает issued-instance wrappers.
- 2D prototype methods: `getImageData`, `putImageData`, `measureText`, `fillText`, `strokeText`, `fillRect`, `drawImage`.
- `registerAllHooks` живёт на `FernwehContext` как non-enumerable method и валидирует required Canvas hooks.

### [canvas.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/canvas.js)

- Требует `G.FernwehContext`, `C.state`, `C.state.__CANVAS__`, `C.state.__CANVAS__.__STATE__`; screen data читает из `C.state.__SCREEN__`.
- Использует PRNG из `Core.__internal.prng` (`seed`, `strToSeed`, `mulberry32`); новые публичные seed globals не являются нормой.
- Публикует `CanvasPatchModule` и `FernwehHooks`: создаёт export-контейнер `window.FernwehHooks` при отсутствии, сохраняет identity существующего допустимого контейнера и дополняет его hook-функциями; hooks потребляются [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) `registerAllHooks`.
- Не создаёт скрытый DOM/offscreen canvas для issued routes; lifecycle issued canvas/offscreen обслуживает [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js).
- `patchToDataURLInjectNoise`, `patchToBlobInjectNoise`, `patchConvertToBlobInjectNoise` используют PNG ancillary chunk builder; pixel readback и IHDR mutation не активны.
- `applyMeasureTextHook` может вернуть `Proxy(nativeMetrics)` для чтения numeric fields; `measureTextNoiseHook` не мутирует metrics.
- `applyDrawImageHook` вызывает native draw через переданный `callOrig`, затем ставит deterministic stamp при валидных условиях.

### [webgl.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/webgl.js)

- Использует `const C = window.FernwehContext`; canonical state route — `C.state.__WEBGL_STATE__`.
- Требует `C.state.__ENV_PROFILE__`, словари/whitelists `WEBglDICKts`, Core PRNG, Core toString wrapper registry и WeakMap/WeakSet инфраструктуру.
- Экспортная поверхность — `window.webglHooks`.
- Основные hooks: `webglGetParameterMask`, `webglWhitelistParameterHook`, extension hooks, shader precision/source hooks, `readPixels` post-native hook.
- `readPixels` mode задаётся через `C.__hookModeStore.post_orig_once`.

### `FernwehContext`

- Каноническое имя hidden root в этом документе: `FernwehContext`.
- Если новый код или документация добавляют hook, он должен указывать, в какой registry `FernwehContext` он регистрируется, какой hook mode использует и где берёт профильные/state значения.

## Чеклист верификации архитектуры

Ниже приведён контрольный список для проверки реализации Canvas/WebGL hooks по текущему контракту:

- **Разделение по файлам и областям:** [canvas.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/canvas.js) содержит доменные Canvas hooks и экспортирует `CanvasPatchModule`/`FernwehHooks`; [webgl.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/webgl.js) содержит WebGL hooks и экспортирует `window.webglHooks`; [context.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/context.js) применяет hooks к runtime surfaces.
- **Hidden state root:** `window.FernwehContext` существует до запуска модулей, не заменяется новым объектом и остаётся one point of truth для state/registries/native refs.
- **Оригиналы методов сохранены до patch:** используются local closure refs и `C.__keptNativeRefs__`; wrapper не должен вызывать уже заменённый `obj[key]` как original.
- **Descriptor/receiver/apply path:** wrappers должны сохранять descriptor flags, prototype owner, implementation-checked receiver и native bad-receiver behavior. Норма вызова — `Reflect.apply(nativeOriginal, thisArg, args)`.
- **Proxy не является 2D context carrier:** `getContext('2d')` возвращает real context object. Proxy допустим только там, где он фактически используется и не ломает invariants, сейчас это `TextMetrics` result wrapper.
- **Идемпотентность:** повторный patch контролируется `C.__patchState`, WeakSet/WeakMap guards, `patchedMethods`, issued-owner markers и hook registration guards, а не `CanvasGlobal`.
- **Корректность последовательности хуков:** `registerAllHooks` должен соответствовать required exports. `masterToDataURLHook` является активным DataURL hook; WebGL `readPixels` должен оставаться `post_orig_once`.
- **Возврат значений:** `toDataURL` возвращает string, `toBlob` вызывает callback с `Blob`, `convertToBlob` возвращает `Promise<Blob>`, `getImageData` возвращает native `ImageData`, `measureText` возвращает `TextMetrics` или допустимый wrapper, draw/text/fill methods сохраняют native return semantics.
- **Диагностика:** failures должны идти в `__DEGRADE__.diag` с классификацией, совместимой с `DEGRADE_Contract`. Места return-native после failure должны быть явно отмечены как риск, если внешний контракт требует fail-fast.
- **Практическая проверка:** статически проверить descriptors, own/prototype placement, wrapper `toString`, detached method/native bad-receiver behavior, WebGL issued-instance methods и отсутствие silent `catch {}` без diag.
