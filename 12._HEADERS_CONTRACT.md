# Headers pipeline contract

## 1. Назначение

Этот документ фиксирует контракт работы headers-pipeline в текущей реализации `sunami`. Он описывает не отдельные файлы изолированно, а сквозную цепочку:

```js
profile / expected_client_hints / seed
  -> tools/tools_runtime/headers_adapter.py
  -> main.py: Chrome language preferences / CDP Network.setUserAgentOverride.acceptLanguage
  -> main.py: CDP Network.setExtraHTTPHeaders (non-language headers)
  -> main.py: FernwehContext.state.__HEADERS__.__STATE__
  -> headers_interceptor.js: window fetch / XHR patch
  -> headers_bridge.js: sync allow/ignore lists для CDP Fetch path
  -> main.py: prepared Fetch.requestPaused path
```

Headers-pipeline нужен для согласования сетевого отпечатка браузера с тем же профилем, который используется для `navigator`, UA-CH, device metrics, language, memory/DPR и других fingerprint surfaces. Контрактный принцип: значения не появляются в runtime сами по себе. Они идут из профильных данных и `expected_client_hints`, затем раскладываются в два управляемых набора: CDP outbound headers и JS hidden-state headers.

## 2. Файлы зоны ответственности

[main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py):

- импортирует `headers_adapter_module`;
- назначает seed-детерминированный RNG для headers-модуля;
- строит `profile["http_accept_language"]` для HTTP `Accept-Language` header value;
- передаёт Chrome q-free список языковых предпочтений через `--lang` и `intl.accept_languages`;
- вызывает `build_runtime_header_sets(...)`;
- применяет `Network.setExtraHTTPHeaders` только для non-language outbound headers;
- создаёт hidden owner-state `FernwehContext.state.__HEADERS__.__STATE__`;
- регистрирует [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js) и [headers_bridge.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_bridge.js) через `Page.addScriptToEvaluateOnNewDocument`;
- подготавливает `Fetch.requestPaused` перехватчик через `_install_fetch_interceptor(...)`.

[headers_adapter.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/tools_runtime/headers_adapter.py):

- производит header-наборы из `profile`, `expected_client_hints`, `user_agent`, `browser_brand`;
- строит `Accept-Language`;
- выбирает семейство браузера для language/header policy;
- синхронизирует twin headers `Sec-CH-Device-Memory` / `Device-Memory`;
- возвращает два набора: `cdp_outbound_headers` и `js_safelisted_headers`.

[headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js):

- публикует `window.HeadersInterceptor` всегда, даже если сам patch не применён;
- создаёт/читает hidden state `FernwehContext.state.__HEADERS__.__STATE__`;
- патчит `window.fetch` и `XMLHttpRequest.prototype.open/send`;
- управляет allow/ignore suffix lists;
- фильтрует cross-origin JS-injected headers;
- эмитит diagnostics через `FernwehContext.__logger.__DEGRADE__`.

[headers_bridge.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_bridge.js):

- связывает публичный runtime API `window.HeadersInterceptor` с hidden state;
- синхронизирует `allowSuffixes` и `ignoreSuffixes`;
- добавляет challenge-domain ignore defaults;
- оборачивает `HeadersInterceptor.addAllow/addIgnore`, чтобы дальнейшие изменения списков попадали в hidden state, читаемый Python Fetch path.

## 3. Source of truth

Канонический source of truth для значений headers находится на Python-стороне:

```js
profile
expected_client_hints
user_agent
browser_brand
headers RNG
```

Эти данные формируются до запуска runtime header stage. В [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) профиль получает:

- `profile["browser_brand"]`;
- `profile["browser_major_version"]`;
- `profile["http_accept_language"]`, вычисленный через `headers_adapter_module.derive_accept_language(...)`;
- `expected_client_hints`, построенный через `build_expected_client_hints(...)`;
- `profile["deviceMemory"]`, выровненный после чтения `navigator.deviceMemory`;
- `expected_client_hints["deviceMemory"]`.

Headers RNG задаётся отдельно:

```python
headers_rng = seed_int["headers"]
headers_adapter_module._pick_nav_template.cache_clear()
headers_adapter_module.random = headers_rng
```

Контракт: если header-значение зависит от случайности, случайность должна идти через headers RNG, привязанный к `global_seed`. Если значение зависит от профиля, оно должно идти из `profile` или `expected_client_hints`, а не из локального hardcode в runtime.

Нейминг разделён строго:

- `profile["language"]` — значение для `navigator.language`, не HTTP header;
- `profile["languages"]` — значение для `navigator.languages`, не HTTP header;
- `profile["http_accept_language"]` — кастомное profile-поле только для HTTP `Accept-Language` header value;
- `intl.accept_languages` / `--lang` / `Network.setUserAgentOverride.acceptLanguage` — browser/native language corridor; сюда передаётся q-free language preference list, а не HTTP q-string;
- `"Accept-Language"` — браузерное HTTP header name.

## 4. Генерация headers в [headers_adapter.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/tools_runtime/headers_adapter.py)

### 4.1. Browser family

`_accept_language_family(...)` определяет семейство:

- `chromium` для Chrome/Chromium/Edge;
- `safari` для Safari без Chrome/Chromium/Edge в UA;
- `firefox` для Firefox;
- `chromium` как default.

Семейство влияет на порядок `Accept-Language` и на состав header-наборов.

### 4.2. Accept-Language

`derive_accept_language(...)` строит язык из:

1. `profile["languages"]`;
2. `expected_client_hints["languages"]`;
3. `expected_client_hints["language"]`;
4. fail-fast, если ни один upstream source не дал валидный language list.

Для Chromium/Safari после конкретного locale может добавляться language-only fallback:

```js
en-GB -> en-GB,en;q=0.9
```

Для Firefox language-only fallback не добавляется этим helper path.

Если после нормализации список пустой, [headers_adapter.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/tools_runtime/headers_adapter.py) выбрасывает `ValueError("HeadersStage: Accept-Language source missing")`. Fallback `en-GB` больше не является допустимым скрытым источником значения.

### 4.3. Accept

`generate_accept_header(browser_brand, major_version, kind)` умеет генерировать:

- navigation Accept из browser-specific template;
- XHR Accept: `application/json, text/plain, */*`;
- fetch Accept: `*/*`.

В текущей header stage `build_runtime_header_sets(...)` использует `expected_client_hints["accept"]`, а не вызывает `generate_accept_header(...)` напрямую. Поэтому `expected_client_hints["accept"]` должен быть уже согласован с профилем до входа в headers stage.

### 4.4. Twin headers

Контрактная пара:

```text
Sec-CH-Device-Memory <-> Device-Memory
```

`_synchronize_header_twins(...)` гарантирует, что если присутствует хотя бы один из пары и значение не `None`, оба ключа получают один canonical value. Canonical value выбирается из `Sec-CH-Device-Memory`, если он есть, иначе из `Device-Memory`.

## 5. Два выходных набора

`build_runtime_header_sets(...)` возвращает:

```python
{
    "cdp_outbound_headers": ...,
    "js_safelisted_headers": ...,
}
```

### 5.1. `cdp_outbound_headers`

Это главный outbound-набор. Он применяется через:

```python
driver.execute_cdp_cmd("Network.setExtraHTTPHeaders", {"headers": cdp_outbound_headers})
```

Назначение: передать браузеру сетевые non-language headers на CDP-level, до JS fetch/XHR patch и до навигации.

Для Chromium-family набор включает:

- `Accept`;
- `User-Agent`;
- `Sec-CH-UA`;
- `Sec-CH-UA-Mobile`;
- `Sec-CH-UA-Platform`;
- `Sec-CH-Save-Data`;
- `Sec-CH-UA-Platform-Version`;
- `Sec-CH-UA-Full-Version`;
- `Sec-CH-UA-Full-Version-List`;
- `Sec-CH-UA-Arch`;
- `Sec-CH-UA-Bitness`;
- `Sec-CH-UA-WoW64`;
- `Sec-CH-UA-Model`;
- `Sec-CH-UA-Form-Factors`;
- `Sec-CH-Device-Memory`;
- `Device-Memory`;
- viewport/width/DPR headers.

Для Firefox/Safari-family набор уже:

- `Sec-CH-UA`;
- `Sec-CH-UA-Mobile`;
- `Sec-CH-UA-Platform`;

Для Chromium-family `build_runtime_header_sets(...)` fail-fast проверяет наличие непустого `Sec-CH-UA-Full-Version`.

### 5.2. `js_safelisted_headers`

Это набор, который Python кладёт в hidden state:

```js
FernwehContext.state.__HEADERS__.__STATE__.headers
```

Он не является основным сетевым каналом. Основной канал для non-language headers — CDP `Network.setExtraHTTPHeaders`. JS-набор нужен для optional JS-side fetch/XHR injection, если профиль `HeadersInterceptor` будет переведён в режим, где JS реально добавляет headers.

В текущей конфигурации этот набор содержит HTTP-представление `Accept-Language` как safelisted JS value, но штатные профили `min` и `default` его не инжектят. Фактический browser-owned source для wire `Accept-Language` при top-level/navigation requests — native language corridor (`intl.accept_languages` / `--lang` / `Network.setUserAgentOverride.acceptLanguage`) с q-free language preference list.

Важно: в [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js) default profile `min` и `default` не инжектят ничего из JS. `full` берёт `Object.keys(RAW_H)` и может использовать safelisted `Accept-Language` для JS fetch/XHR path; все `Sec-CH-*`, `Accept`, `User-Agent`, DPR/viewport/device-memory остаются CDP-only.

## 6. Main pipeline stage

### 6.1. Порядок подключения

Контрактный порядок в [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py):

1. Собрать `page_js = build_page_bundle(init_params)`.
2. Применить UA/UA-CH через `apply_ua_overrides(...)`.
3. Прочитать page-side `navigator.deviceMemory` и синхронизировать `profile["deviceMemory"]` / `expected_client_hints["deviceMemory"]`.
4. Зарегистрировать основной page bundle через `Page.addScriptToEvaluateOnNewDocument`.
5. Построить runtime header sets.
6. Применить `Network.setExtraHTTPHeaders` с `cdp_outbound_headers` без `Accept-Language`.
7. Собрать `headers_window_js`, который:
   - требует `window.FernwehContext`;
   - требует `FernwehContext.state`;
   - создаёт `state.__HEADERS__`;
   - создаёт `state.__HEADERS__.__STATE__`;
   - кладёт туда `headers`;
   - нормализует `allowSuffixes`, `ignoreSuffixes`, `bridgeReady`;
   - подмешивает текст [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js);
   - вызывает `HeadersInterceptor(window)`.
8. Зарегистрировать `headers_window_js` через `Page.addScriptToEvaluateOnNewDocument`.
9. Зарегистрировать [headers_bridge.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_bridge.js) через `Page.addScriptToEvaluateOnNewDocument`.
10. Вызвать `_install_fetch_interceptor(...)` с `fetch_rules = []`; при пустом списке rules Python path не вызывает `Fetch.enable` и не ставит listener.

Этот порядок важен: [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js) должен видеть уже созданный hidden state, а [headers_bridge.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_bridge.js) должен видеть уже опубликованный `window.HeadersInterceptor`.

### 6.2. Hidden owner-state

Канонический path:

```js
window.FernwehContext.state.__HEADERS__.__STATE__
```

Форма:

```js
{
  headers: { ... },
  allowSuffixes: [],
  ignoreSuffixes: [],
  bridgeReady: false | true
}
```

Все поля создаются через `Object.defineProperty(..., enumerable:false)` в owner-state setup. Это соответствует hidden-state контракту: state не является public browser API и не должен участвовать в обычной enumeration. Перед переопределением `headersState.headers` stage проверяет существующий descriptor; non-configurable slot является fail-fast ошибкой, а не silent overwrite.

### 6.3. CDP outbound path

`Network.setExtraHTTPHeaders` — главный path для headers, которые должны уходить как сетевые outbound headers, кроме browser-owned `Accept-Language`. Это особенно важно для `Sec-CH-*`, `User-Agent`, `Accept`, DPR/viewport и device-memory headers.

Контракт: если header является browser/CDP-owned или forbidden/sensitive для JS, он должен идти через CDP/native browser corridor, а не через `fetch`/XHR monkey patch. Для `Accept-Language` активный owner — native language corridor (`intl.accept_languages` / `--lang` / `Network.setUserAgentOverride.acceptLanguage`), где значение передаётся как q-free list (`de-DE,de`). `Network.setExtraHTTPHeaders["Accept-Language"]` не используется, потому что в текущем Chromium/CDP corridor это второй независимый setter и не является надёжным финальным setter для wire header.

## 7. JS interceptor contract

### 7.1. Export API

[headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js) всегда публикует:

```js
window.HeadersInterceptor = {
  setProfile,
  addAllow,
  addIgnore,
  listAllow,
  listIgnore
};
```

Даже если dependencies отсутствуют и patch не применён, API должен быть доступен. Это нужно, чтобы дальнейший owner-state inject или bridge мог повторно синхронизироваться.

### 7.2. Guard lifecycle

Patch использует:

```js
Core.guardFlag('__PATCH_HEADERS_INTERCEPTOR__', 'headers_interceptor')
```

Если guard/core отсутствует или preflight не проходит, модуль пишет diagnostics и выходит до patch side effects. При successful apply guard остаётся latched для текущего document.

### 7.3. Preconditions

Для установки fetch/XHR patch требуются:

- `window.Core`;
- `Core.guardFlag`;
- `window.FernwehContext`;
- `FernwehContext.state`;
- `FernwehContext.state.__HEADERS__.__STATE__`;
- `FernwehContext.state.__HEADERS__.__STATE__.headers`.

Если `headers` отсутствует, модуль делает observed skip через `__DEGRADE__` и не патчит network API.

### 7.4. Header profiles

Внутренний `headerProfile`:

- `min` — JS не добавляет headers;
- `default` — JS не добавляет headers;
- `full` — JS берёт ключи из hidden `RAW_H`.

`setProfile(name)` принимает только `min`, `default`, `full`. Неизвестное имя даёт diagnostic и возвращает `false`.

### 7.5. JS-side forbidden/CDP-only policy

[headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js) содержит:

```js
const CDP_ONLY = new Set([
  'accept',
  'user-agent',
  'device-memory',
  'dpr',
  'viewport-width',
  'sec-ch-dpr',
  'sec-ch-viewport-width',
  'sec-ch-viewport-height',
  'sec-ch-width',
]);
```

Дополнительно `isCdpOnlyHeader(name)` блокирует любой `sec-ch-*` по prefix rule. Эти ключи не добавляются через JS даже в profile `full`.

`Accept-Language` намеренно не входит в `CDP_ONLY`: это CORS-safelisted header для JS fetch/XHR path. Для top-level/navigation wire header активный source — native language corridor, а не `Network.setExtraHTTPHeaders`.

### 7.6. CORS / allow / ignore

Есть два списка:

```js
ALLOW_SUFFIXES
IGNORED_SUFFIXES
```

`IGNORED_SUFFIXES` содержит сервисные и challenge-домены, для которых JS patch пропускает запросы без изменения. `ALLOW_SUFFIXES` пустой по умолчанию и управляется через `HeadersInterceptor.addAllow(...)`.

Логика JS:

- same-origin: можно использовать профильный JS-набор;
- cross-origin + allow-list: можно использовать профильный JS-набор;
- cross-origin + not-allowed: оставить только `SAFE_LISTED`;
- ignored host: native pass-through;
- image/font/media request: native pass-through;
- `no-cors` cross-origin not-allowed: native pass-through.

Текущий `SAFE_LISTED` в JS:

```js
accept-language
```

`Accept-Language` не входит в `CDP_ONLY`, но штатные JS profiles `min/default` его не инжектят. Это важно не путать со штатным browser-owned path, где `Accept-Language` выводится из q-free language preferences.

## 8. Fetch/XHR patch mechanics

### 8.1. fetch

`window.fetch` заменяется на `patchedFetch`.

Алгоритм:

1. Собрать `baseReq`.
2. Определить target URL/host.
3. Если host ignored — вызвать native fetch.
4. Если image/font/media — вызвать native fetch.
5. Если `no-cors` cross-origin not-allowed — вызвать native fetch.
6. Получить profiled headers из hidden `RAW_H`.
7. Если набор пуст — вызвать native fetch.
8. Предвалидировать разрешённые headers через `collectInjectableHeaders(...)`.
9. Собрать `new Headers(baseReq.headers)`.
10. Добавить разрешённые headers атомарно для будущего `Request`; при ошибке diagnostic уже записан и выполняется native fetch без mutated request.
11. Если ничего не изменилось — вызвать native fetch.
12. Создать `new Request(baseReq, { headers: mergedHeaders })`.
13. Вызвать native `_fetch.call(this, finalReq)`.

При ошибке модуль пишет diagnostic с `data.outcome: 'skip'` / `action: 'native'` и возвращается к native `_fetch.apply(this, arguments)`.

### 8.2. XHR

`XMLHttpRequest.prototype.open` сохраняет `{ method, url }` в `WeakMap`.

`XMLHttpRequest.prototype.send`:

1. Читает state из `WeakMap`.
2. Проверяет image/font/media.
3. Проверяет ignored host.
4. Берёт profiled headers.
5. Фильтрует через CORS policy и предвалидирует headers через `collectInjectableHeaders(...)`.
6. Пытается вызвать `this.setRequestHeader(k, value)` для каждого разрешённого header.
7. При apply failure пишет diagnostic с `data.outcome: 'skip'` / `action: 'native'` и сразу возвращает native `XHRSend.apply(this, arguments)`.
8. В конце всегда возвращает native `XHRSend.apply(this, arguments)`.

Ошибки state или `setRequestHeader` пишутся в diagnostics. В текущем hidden JS-наборе есть safelisted `Accept-Language`, но JS header mutation в `min/default` фактически отсутствует, потому что эти профили не выбирают headers для инъекции.

## 9. Bridge contract

[headers_bridge.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_bridge.js) не генерирует headers. Его зона ответственности — списки host suffixes.

Порядок:

1. Найти `window.HeadersInterceptor`.
2. Найти или создать `FernwehContext.state.__HEADERS__.__STATE__`.
3. Прочитать текущие `allowSuffixes` / `ignoreSuffixes`.
4. Прочитать `HeadersInterceptor.listAllow()` / `listIgnore()`.
5. Объединить списки.
6. Добавить challenge pass list:
   - `.cloudflare.com`;
   - `.challenge.cloudflare.com`;
   - `.challenges.cloudflare.com`;
   - `.akamaihd.net`;
   - `.perimeterx.net`;
   - `.hcaptcha.com`;
   - `.recaptcha.net`.
7. Обернуть `HeadersInterceptor.addAllow/addIgnore`, чтобы будущие изменения попадали в hidden state.
8. Поставить `headersState.bridgeReady = true`.
9. Записать diagnostic `headers_bridge:init:apply:ready`.

Если `HeadersInterceptor` отсутствует, bridge пишет `headers_bridge:init:preflight:headers_interceptor_missing` через `__DEGRADE__.diag` и выполняет observed skip.

## 10. Python Fetch interceptor path

`_install_fetch_interceptor(driver, rules, extra_headers_fn, blocked_headers)` подготавливает CDP Fetch path. Если `rules` пустой, функция пишет Python `logger.info(...)` через overseer logger и возвращает управление без `Fetch.enable` и без listener.

При непустом `rules` path:

- вызывает `Fetch.enable` с `patterns`;
- подписывается на `Fetch.requestPaused`;
- на каждом paused request читает `allowSuffixes` / `ignoreSuffixes` из hidden state через `Runtime.evaluate`;
- удаляет blocked headers;
- добавляет extra headers, но с учётом allow/ignore и safelisted policy;
- продолжает request через `Fetch.continueRequest`.

Blocked policy в Python:

- explicit `blocked_headers`;
- `accept`;
- `origin`;
- `cookie`;
- `authorization`;
- все `sec-ch-*`;
- `dpr`;
- `viewport-width`;
- `sec-ch-dpr`;
- `sec-ch-viewport-width`.

Python `SAFE_LISTED`:

```python
{"accept-language"}
```

В текущем [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py):

```python
fetch_rules = []
_install_fetch_interceptor(..., extra_headers_fn=lambda ...: safelisted_headers)
```

При `rules=[]` Fetch interception не устанавливается явно. Контракт больше не опирается на поведение `Fetch.enable` с пустым `patterns`.

## 11. Mitmproxy-related helper

[headers_adapter.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/tools_runtime/headers_adapter.py) содержит `import_headers(headers, keys, flow)`.

Он переносит значения из `headers` в `flow.request.headers`. Empty string допускается как значение; `None`, отсутствующий ключ или не-dict `headers` являются fail-fast ошибкой с Python `logger.error(...)` через overseer logger. Это отдельный helper для mitmproxy path, но в рассматриваемой [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) цепочке основным каналом является CDP `Network.setExtraHTTPHeaders`.

## 12. Диагностика и swallow map

Контрактный diagnostic owner:

```js
FernwehContext.__logger.__DEGRADE__.diag(level, code, ctx, err)
```

Текущие JS-модули пишут diagnostics через этот route. Python-side события пишутся через [overseer.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/tools_infra/overseer.py) logger:

- [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py), `_get_lists()`: `Runtime.evaluate` errors пишутся в Python warning через overseer logger, затем используется empty suffix list для продолжения controlled Fetch path.
- [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py), `_install_fetch_interceptor()`: при `rules=[]` Fetch path не устанавливается и пишет Python info; при handler error пишет Python exception и пытается native continue request.
- [headers_bridge.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_bridge.js), `wire()`: если `window.HeadersInterceptor` отсутствует, пишет `headers_bridge:init:preflight:headers_interceptor_missing` через `__DEGRADE__.diag`.
- [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js), `__emit()`: сбой самого logging path проглатывается через `catch (_)`. По DEGRADE-контракту это допустимо только как fail-safe logging-path, но не должно считаться успешным применением patch.
- [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js), `buildMergedHeaders()`: ошибка `Headers.set(...)` диагностируется, `buildMergedHeaders()` возвращает `null`, а fetch уходит в native path без mutated request.
- [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js), `fetch` catch: при apply failure идёт diagnostic с `action: 'native'` и native fallback.
- [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js), `XHR.send`: header preflight/apply failures диагностируются; при failure выполняется native send.
- [headers_adapter.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/tools_runtime/headers_adapter.py), `derive_accept_language(...)`: отсутствие language chain даёт fail-fast `ValueError`.
- [headers_adapter.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/tools_runtime/headers_adapter.py), `import_headers(...)`: missing/None/non-dict values дают Python logger error и exception.

Где не доказано:

- Не доказано без external request inspection, что все `Network.setExtraHTTPHeaders` значения реально выходят в сеть в том же виде для всех request types.
- Не доказано без browser verification, как Chromium нормализует wire `Accept-Language`, когда source идёт через q-free native language corridor без `Network.setExtraHTTPHeaders["Accept-Language"]`.

## 13. Контракт изменения

Любое изменение headers-pipeline должно сохранять следующие инварианты:

1. Source of truth остаётся в `profile` / `expected_client_hints` / seed-derived RNG.
2. `cdp_outbound_headers` остаётся главным каналом для outbound browser/CDP-owned non-language headers.
3. JS hidden-state path остаётся `FernwehContext.state.__HEADERS__.__STATE__`.
4. Hidden state создаётся non-enumerable через `Object.defineProperty`.
5. `window.HeadersInterceptor` может быть публичным API entrypoint, но не становится owner-state.
6. [headers_bridge.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_bridge.js) синхронизирует только allow/ignore lists, а не генерирует header values.
7. `Sec-CH-*`, `User-Agent`, `Accept`, DPR/viewport/device-memory policy должна быть согласована между CDP path и JS path до включения любого нового JS profile; `Accept-Language` остаётся отдельно закреплён за native language corridor и не должен возвращаться в `Network.setExtraHTTPHeaders`.
8. При невозможности применить stage должен быть observed exit через `__DEGRADE__.diag` или явный Python fail-fast, а не silent fallback.
9. Изменения не должны переносить state в `window` как public enumerable storage.
10. При конфликте local pipeline convenience и нормативного browser behavior приоритет у browser/MDN/Web IDL/ECMAScript behavior.

## 14. Минимальная проверка после изменений

Без браузера можно проверить только static contract:

- `build_runtime_header_sets(...)` возвращает оба набора;
- Chromium-family имеет непустой `Sec-CH-UA-Full-Version`;
- twin headers синхронизированы;
- `headers_window_js` создаёт `FernwehContext.state.__HEADERS__.__STATE__.headers`;
- [headers_interceptor.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_interceptor.js) сохраняет API export до preflight exits;
- [headers_bridge.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/stealth/headers_bridge.js) не меняет values headers, только suffix lists.
