# DEGRADE contract: unified diagnostics, observed exits, and Guard integration

Документ фиксирует нормативную роль `__DEGRADE__.diag` в текущем pipeline и его связь с GuardFlag/Seed-контрактом.

Главное разделение ответственности:
- `DEGRADE` владеет диагностическим каналом, `ctx` shape, централизованной сериализацией и классификацией observed events;
- `GuardFlagSEED` владеет entrypoint lifecycle, idempotency, rollback/release semantics и seed owner-space;
- `APPENDIX_MODULE_CODE_TEMPLATE.md` является module projection: таблицей соответствия модулей общей модели, но не переопределяет нормы этого документа и `5._GuardFlagSEED.md`.

При конфликте с внешним нормативным контрактом приоритет остается у `ECMAScript spec`, `Web IDL Standard`, MDN/Chromium observable behavior: descriptor shape, prototype owner, implementation-checked receiver, native bad-receiver path, observable `Function.prototype.toString`, proxy observability.

## 2. Core Terms

`diag channel`:
`CanvasPatchContext.__logger.__DEGRADE__.diag(level, code, ctx, err)`.

`base callable fallback`:
`CanvasPatchContext.__logger.__DEGRADE__(code, err, extra)`.

`safe-noop`:
If neither channel exists, adapter returns without `console.*` and without throwing. This is allowed only for logging-path failure; it does not make the patch itself successful.

`Observed Exit`:
Any controlled `return`, `skip`, `rollback`, or `throw` path emitted before leaving the controlled step.

`Native path`:
For public API hooks, the module must preserve native receiver/apply behavior. Service diagnostics must not replace a native `TypeError`, `Illegal invocation`, promise rejection, or engine result.

## 3. Unified Roles: DEGRADE vs Guard

`DEGRADE` is the observation plane:
- receives structured events;
- serializes unsafe host/DOM/cyclic data;
- normalizes `level`, `code`, `key`, `scope`, `scopeKind`, and final `extra.type`;
- classifies guard/preflight/apply/rollback/native events for logger views;
- stores entries only in private logger/degrade state.

`GuardFlagSEED` is the lifecycle plane:
- acquires a module entrypoint token through `Core.guardFlag(flagKey, codePrefix)`;
- keeps successful applies idempotent by not releasing the guard;
- releases only on pre-apply skip or clean rollback;
- locks on partial/failed rollback;
- uses `Core.__internal.prng` for deterministic token tagging.

Neither contract may override the other:
- Guard lifecycle events must be emitted through `DEGRADE` route.
- `DEGRADE` classification must not imply that guard may be released.
- `ctx.type` must not rewrite module `policy`.
- `policy` must not suppress required observed diagnostics.

## 5. `.diag` API

Normative call:

```js
CanvasPatchContext.__logger.__DEGRADE__.diag(level, code, ctx, err);
```

Current implementation in `set_log.js`:
- valid `level`: `info | warn | error | fatal`; invalid level becomes `info`;
- `code` is stringified, default `unknown`;
- non-plain `ctx` becomes `{}`;
- `ctx.data === null` is preserved;
- missing `ctx.data` becomes `{}`;
- non-object/non-function `ctx.data` becomes `{}`;
- data is serialized centrally with host/cycle/string limits;
- explicit `ctx.key: null` is preserved;
- omitted `ctx.key` is synthesized from `ctx.diagTag`, then `ctx.module`;
- final `extra.type` is produced by centralized `normalizeDiagType(...)`;
- `.diag` is fail-safe and must not throw into module code.

Important: modules pass raw `ctx.type`; logger may classify final `extra.type` into values such as `guard_failed`, `guard_exit`, `preflight_failed`, `apply_failed`, `rollback_failed`, `native_throw`, `pipeline diagnostic`, or `browser diagnostic`. This classification is for observation and filtering only. It does not change `policy`, does not release guard, and does not authorize retry.

## 6. Required `ctx` Shape

Module events must pass:

```js
{
  module,
  diagTag,
  surface,
  key,
  stage,
  message,
  type,
  data
}
```

Required conventions:
- `module`: stable module id.
- `diagTag`: stable event producer tag; default is module id.
- `surface`: stable owner-route/lane label, not necessarily filename.
- `key`: string or `null`; omit only when central key synthesis is intended.
- `stage`: one of the allowed stage values below.
- `message`: stable human-readable message.
- `type`: cause category input, not policy.
- `data`: object or `null`; include `data.outcome` for controlled exits.

Allowed `ctx.stage`:

`bootstrap | preflight | guard | apply | rollback | contract | hook | runtime | cleanup | audit`

Stage ownership:
- `bootstrap`: bootstrap owner-transfer / bootstrap cleanup.
- `guard`: guard acquisition, guard absence, already-patched exits, or guard-read/write failure before module apply.
- `preflight`: read-only capability/data checks before write side effects.
- `apply`: descriptor/property/wrapper installation and post-apply checks.
- `rollback`: descriptor/state restoration and guard release after pre-apply skip or rollback.
- `contract`: normative invariant checks.
- `hook`: runtime hook chain diagnostics.
- `runtime`: runtime/native pass-through diagnostics.
- `cleanup`: logger/bootstrap cleanup paths.
- `audit`: synthetic logger/probe audit events.

Do not invent local stage strings.

## 7. `type` and Missing Data

For missing-data causes, use exactly:
- `pipeline missing data`: our profile/seed/meta/bridge/internal expected data is missing or inconsistent;
- `browser structure missing data`: engine/browser structure is missing, changed, non-configurable, receiver/brand incompatible, or native path throws unexpectedly.

Other stable input types currently used by the pipeline include:
- `ok`
- `contract violation`
- `pipeline telemetry`
- module-specific stable cause labels

The logger may normalize final `extra.type` for filtering. Missing-data input strings still matter because they allow central classification into `pipeline diagnostic` / `browser diagnostic` when no stricter event classifier applies.

## 8. `data.outcome`

Controlled exits must include:

`data.outcome` in:

`return | skip | rollback | throw`

Meaning:
- `return`: controlled success/native/no-op return.
- `skip`: controlled non-apply or non-retry path.
- `rollback`: clean rollback was completed or rollback path is the intended observed path.
- `throw`: fail-fast or native/engine throw path is intentionally preserved.

Recommended stable `data.reason` values for shared filtering:
- `already_patched`
- `missing_dep_core_guard`
- `guard_failed`
- `guard_exception`
- `guard_write_failed`
- `guard_release_failed`
- `guard_release_exception`
- `rollback_failed`
- `rollback_ok`
- `preflight_failed`
- `apply_failed`
- `native_throw`
- `bootstrap_seed_missing`

## 9. Guard Events Through DEGRADE

Guard acquisition events:
- `guard_missing`: `stage: 'guard'`, `outcome: 'skip'`, `reason: 'missing_dep_core_guard'`
- `guard_failed`: `stage: 'guard'`, `outcome: 'skip'`, `reason: 'guard_failed'`
- `already_patched`: `stage: 'guard'`, `outcome: 'skip'`, `reason: 'already_patched'`

Core release events:
- `guard_release_skipped`: `stage: 'rollback'`, `outcome: 'skip'`, `reason: 'rollback_failed'`, `rollbackOk: false`
- `guard_release_failed`: `stage: 'rollback'`, `outcome: 'skip'`, `reason: 'guard_release_failed'`
- `guard_release_exception`: `stage: 'rollback'`, `outcome: 'skip'`, `reason: 'guard_release_exception'`
- `guard_released`: `stage: 'rollback'`, `outcome: 'rollback'`, `reason: 'rollback_ok'`, `rollbackOk: true`

Current logger classification:
- guard failures collapse to final `extra.type: 'guard_failed'`;
- `already_patched` collapses to final `extra.type: 'guard_exit'`;
- `guard_release_skipped` with `reason: 'rollback_failed'` classifies as `rollback_failed`.

This is expected. Final logger classification is not a lifecycle decision.

## 10. Minimal Module Flow

Allowed sequence:

1. Bootstrap/read-only resolution of logger/Core references.
2. Guard acquisition before write side effects.
3. Read-only preflight under guard.
4. Apply descriptor/property/wrapper changes.
5. Post-apply contract checks.
6. Success `return` with guard kept locked.

Pre-apply skip:

1. Emit observed skip.
2. Call `releaseGuardFlag(..., true, ...)`.
3. Return.

Post-apply fatal:

1. Emit/apply failure as appropriate.
2. Roll back descriptor/state changes.
3. Call `releaseGuardFlag(..., rollbackOk, ...)`.
4. Throw or preserve native path as required.

Do not read this as `releaseGuardFlag(true)` after success. Successful apply means guard remains installed for the document/realm.

## 11. Policy Priority

`policy` belongs to target/group planning, not to `ctx.type`.

Rules:
- `policy: 'throw'` or `policy: 'strict'` is fail-fast for the patch step.
- `policy: 'skip'` may skip a target/group only if native behavior remains intact and the skip is observed.
- `rollback` is required after partial apply where the module owns restoration.
- Public API hooks must preserve native receiver/apply path; service errors must not leak instead of native engine behavior.
- If `throw` would leak service internals from a public API hook, use native pass-through/engine throw path and emit diagnostics out-of-band.

## 12. Module-local Adapter

Purpose: route `.diag -> callable fallback -> safe-noop` without `Illegal invocation`, without `console.*`, and without local policy decisions.

Normative adapter properties:
- binds `.diag` with `__D.diag.bind(__D)`;
- does not throw;
- does not call `console.*`;
- does not mutate caller-provided `extra`;
- may shape module defaults (`module`, `diagTag`, `surface`, `key`) before calling `.diag`;
- does not locally classify `ctx.type` or invent `ctx.stage`.

Canonical pattern:

```js
const __loggerRoot = (C && C.__logger && typeof C.__logger === 'object') ? C.__logger : null;
const __D = (__loggerRoot && typeof __loggerRoot.__DEGRADE__ === 'function') ? __loggerRoot.__DEGRADE__ : null;
const __diag = (__D && typeof __D.diag === 'function') ? __D.diag.bind(__D) : null;

function __emit(level, code, ctx, err) {
  try {
    const safeErr = (typeof err === 'undefined') ? null : err;
    if (__diag) return __diag(level, code, ctx || null, safeErr);
    if (typeof __D === 'function') {
      const safeCtx = (ctx && typeof ctx === 'object') ? ctx : {};
      const safeLevel = (level == null) ? 'info' : level;
      return __D(code, safeErr, Object.assign({}, safeCtx, { level: safeLevel }));
    }
  } catch (emitErr) {
    return undefined;
  }
  return undefined;
}
```

Bootstrap exception:
`bootstrap_hide.js` may execute before logger installation. Its adapter may safe-noop until `CanvasPatchContext.__logger.__DEGRADE__` exists. This does not authorize any alternative logging channel.

## 13. Constraints

Forbidden:
- `console.*` as the only diagnostic path;
- new stage strings outside the allowed set;
- local reclassification that disagrees with `set_log.js`;
- treating `ctx.type` as policy;
- releasing guard after successful apply;
- retrying after partial apply without clean rollback;
- storing guard state in `window` or `CanvasPatchContext.state`;
- describing export surfaces as owner-state;
- hiding service failures by returning non-native public API values.
