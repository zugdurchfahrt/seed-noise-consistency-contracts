## Purpose

PRNG Seed is the deterministic backbone of the runtime profile. The pipeline needs controlled randomness because many browser surfaces must look variable across sessions while staying stable inside one session: profile selection, plugins, permissions, headers, VPN helper choices, font manifest generation, canvas noise, WebGL masks, navigator-derived jitter and worker-local patches.

The contract is not "make everything random". The contract is: one session seed is created once, every downstream random branch is derived from it by a named branch label, and every runtime consumer reads the already materialized hidden PRNG owner instead of inventing its own seed path.

Current canonical principle:

```txt
Python global_seed
  -> named Python RNG pools
  -> browser bootstrap seed input
  -> Core.__internal.prng
  -> Core.__internal.prng.rand.use(label)
  -> module-local deterministic random streams
```

The seed is a bootstrap input. The PRNG owner is `Core.__internal.prng`. Those are different roles.

## Source Of The Session Seed

`main.py` owns the session seed creation. At process/session start it creates:

```txt
global_seed = uuid.uuid4().hex
```

This value is the only root input for controlled project randomness during that run.

`main.py` then derives Python-side random pools through `_build_rng_pools(global_seed)`. The derivation root is the shared string:

```txt
__RAND_SEED_POOL__
```

For each Python label, `main.py` builds material in this shape:

```txt
__RAND_SEED_POOL__|<label>|<global_seed>
```

The material is hashed with SHA-256, the first 8 digest bytes become a numeric seed, and `random.Random(numeric_seed)` becomes the module-local RNG.

Current Python pool labels:

- `profile`
- `plugins`
- `permissions`
- `headers`
- `vpn`

These pools are then assigned into the relevant Python modules. The important contract point is that Python modules do not own independent ambient randomness; they receive a branch derived from the one session seed.

## rand_met Derivative

`rand_met.py` has a separate branch because font generation needs several internal substreams while remaining tied to the same session seed.

`main.py` derives:

```txt
_derive_rand_met_seed_material(global_seed, "rand_met")
```

using:

```txt
sha256("__RAND_SEED_POOL__|rand_met|<global_seed>")
```

and assigns it to:

```txt
rand_met_module.RAND_MET_DERIVATIVE
```

`rand_met.py` must not import `main.py` back and must not create a second independent root seed. Its root is only `RAND_MET_DERIVATIVE`. Inside `rand_met.py`, local branches are derived with:

```txt
__RAND_MET_POOL__|<label>|<RAND_MET_DERIVATIVE>|<extra parts...>
```

Current important local labels:

- `manifest_rng` for selecting and sampling the font fingerprint set.
- `meta_rng` for generated font metadata and helper random strings.
- `cache_namespace` for derivative-scoped base64 side-cache isolation.

`_derive_local_rng(...)` hashes local material, takes the first 16 hex characters as the numeric seed, and creates a local `random.Random`. That means font randomness is deterministic for the same `global_seed` and platform/index inputs, but it is branch-isolated from profile/plugins/headers/VPN randomness.

## Window Bootstrap Transport

`main.py` passes the session seed into the window bundle as:

```txt
window.__GLOBAL_SEED
```

The property is a bootstrap transport surface. It is intentionally non-enumerable in the bootstrap object definition and exists so that the PRNG producer can initialize the hidden owner early.

Normative rule:

```txt
window.__GLOBAL_SEED is a producer input only.
It is not a downstream consumer path after Core.__internal.prng is ready.
```

The page bundle order is part of the contract:

```txt
init_params with __GLOBAL_SEED
-> BootstrapHideModule(window)
-> LOGGingModule(window)
-> CoreWindowModule(window)
-> prng_seed.js source is loaded
-> RNGsetModule(window)
-> PRNG-dependent modules
```

`bootstrap_hide.js` creates the hidden owner-space before `RNGsetModule(window)` runs. `core_window.js` validates and uses that owner-space. `prng_seed.js` fills it.

## Canonical Owner

The only canonical runtime PRNG owner is:

```txt
Core.__internal.prng
```

Its normalized shape is:

```js
{
  seed: "",
  strToSeed: null,
  mulberry32: null,
  rand: null,
  pools: Object.create(null),
  marker: "envrand",
  version: "1.1.1"
}
```

`bootstrap_hide.js` is responsible for creating this owner-space hidden-first. It does not fill real PRNG runtime data. It only makes sure the owner exists and has the correct initial shape.

`core_window.js` must treat `Core.__internal.prng` as required infrastructure. If it is missing, this is pipeline missing data, not a reason to create an alternate PRNG owner somewhere else.

`prng_seed.js` is the producer that fills the owner with:

- `seed`
- `strToSeed`
- `mulberry32`
- frozen `rand`
- named `pools`
- `marker`
- `version`

## RNGsetModule

`RNGsetModule(realm)` is a thin execution shell. It is not an owner-state path.

Allowed role:

- run during bundle orchestration;
- read the realm bootstrap seed input;
- fill the already existing `Core.__internal.prng`;
- expose a temporary callable through `FernwehContext.__prngRuntime__.RNGsetModule` if orchestration needs it.

Forbidden role:

- store PRNG state in `RNGsetModule`;
- make `RNGsetModule` the consumer route;
- publish public `window.rand`, `window.strToSeed`, or `window.mulberry32` as normative runtime API.

The current producer reads seed input by realm:

```txt
window realm: __GLOBAL_SEED
worker realm: CDP_GLOBAL_SEED
```

Then it writes only to:

```txt
Core.__internal.prng
```

If the seed is missing, the current producer reports `rng_set:preflight:global_seed_missing` and keeps the guard locked so a late seed cannot silently replace the branch after consumers may already have observed state.

## JavaScript PRNG Branches

`Core.__internal.prng.rand` exposes:

```js
rand.use(label)
```

The label is the branch name. Runtime branch material is:

```txt
__RAND_SEED_POOL__|<label>|<seed>
```

`strToSeed(material)` converts that material into a uint32 seed. `mulberry32(numericSeed)` creates the deterministic `[0, 1)` generator. `pools[label]` caches the generator so repeated `rand.use(label)` calls return the same branch stream for the realm.

Every module must choose an explicit label that describes its branch. A label collision intentionally means a shared stream; accidental label reuse is a contract bug.

The producer may coerce non-string labels and report a diagnostic, but modules should pass stable strings. Consumer code must not rely on object identity, timestamps, current URL, wall-clock time, Math.random, or fresh UUIDs as hidden randomness.

## Consumers

PRNG-dependent window consumers read only:

```txt
Core.__internal.prng
Core.__internal.prng.rand.use(label)
```

Current examples:

- `canvas.js` reads `Core.__internal.prng.seed`, `strToSeed`, and `mulberry32` for deterministic canvas noise keyed by stable inputs.
- `webgl.js` requires `Core.__internal.prng.rand.use`.
- `nav_total_set.js` requires `Core.__internal.prng.rand`.
- `audiocontext.js` requires `Core.__internal.prng.rand.use("audio")`.
- `core_window.js` uses the PRNG owner for guard seed-tag derivation.

Forbidden current consumer paths:

- `window.__GLOBAL_SEED`
- `G.__GLOBAL_SEED`
- `window.rand`
- `window.strToSeed`
- `window.mulberry32`
- `C.__PRNG_STATE__`
- `C.state.__PRNG_STATE__`
- `CanvasPatchContext.__PRNG_STATE__`
- `CanvasPatchContext.state.__PRNG_STATE__`

Those names may appear in historical notes, old cuts, migration plans, or old development snapshots. They must not be treated as active contract routes.

## Worker And Service Worker Seed

Worker realms do not use the window bootstrap name as their normative seed name. The worker seed source is:

```txt
CDP_GLOBAL_SEED
```

`main.py` calls `cdp.enable_seed_inject(global_seed)`. `cdp_catapult.py` stores that value as `CDP_GLOBAL_SEED` and injects a worker/service-worker prelude that defines it in the target realm.

Worker normative chain:

```txt
Python global_seed
-> CDP_GLOBAL_SEED in WorkerGlobalScope
-> local Core.__internal.prng
-> local RNGsetModule(self)
-> worker-local consumers
```

The worker does not consume `window.__GLOBAL_SEED`. It does not restore PRNG through env snapshot. It does not use `CanvasPatchContext` as PRNG storage. Nested workers must receive their own local `CDP_GLOBAL_SEED` before local PRNG initialization.

Service worker compatibility follows the same principle: seed is local to worker scope as `CDP_GLOBAL_SEED`, and PRNG state belongs to local `Core.__internal.prng`.

## Guard Seed Tag

Guard tokens must be deterministic for the realm and tied to the canonical PRNG owner. The intended source is:

```txt
Core.__internal.prng.seed
Core.__internal.prng.strToSeed
```

`core_window.js` caches the derived guard tag on the PRNG owner as `__guardSeedTag`. This cache belongs to the owner-space and must not become a second seed source.

Current implementation note: `core_window.js` still contains a local hash fallback if `Core.__internal.prng.strToSeed` throws or is unavailable. That fallback is diagnostic compatibility material, not a separate normative PRNG branch. The contract target remains: guard seed derivation should be satisfied by the canonical PRNG owner, and missing/failed hasher must be observable through `__DEGRADE__.diag`.

## Diagnostics And Fail-Fast

PRNG failures are pipeline integrity failures, not ordinary feature absence.

Required diagnostic behavior:

- missing `global_seed` in Python seed builders raises immediately;
- missing `Core.__internal.prng` is `pipeline missing data`;
- missing worker `CDP_GLOBAL_SEED` is a worker seed inject failure;
- missing PRNG helpers for a consumer must not silently fall back to public globals;
- producer readiness and failure paths must report through `__DEGRADE__.diag`.

The public/native browser surface must not expose project-internal seed mechanics as a feature API. Diagnostics are internal pipeline telemetry, not public API behavior.

## Determinism Boundaries

Same seed plus same profile inputs should produce the same deterministic branch outputs within the same pipeline version.

Different labels must produce isolated streams:

```txt
__RAND_SEED_POOL__|canvas|seed
__RAND_SEED_POOL__|webgl|seed
__RAND_SEED_POOL__|audio|seed
```

Python and JavaScript share the same conceptual root and label material shape, but they do not promise byte-for-byte identical RNG algorithms:

- Python pools use SHA-256 material into `random.Random`.
- JavaScript runtime pools use `strToSeed` plus `mulberry32`.
- `rand_met.py` uses its own `__RAND_MET_POOL__` subtree from the Python `rand_met` derivative.

The normative invariant is branch ownership and deterministic derivation, not algorithm identity between languages.

## Forbidden Patterns

Do not add:

- ambient `random` / `Math.random` in deterministic modules;
- independent UUID/time-based seeds after `global_seed` exists;
- module-local seed roots not derived from `global_seed`;
- direct consumer reads from `window.__GLOBAL_SEED`;
- worker seed aliases named `__GLOBAL_SEED` as normative path;
- PRNG state under `FernwehContext.state`;
- PRNG state under `CanvasPatchContext`;
- public global helpers `window.rand`, `window.strToSeed`, `window.mulberry32`;
- soft fallback from a missing canonical owner into legacy state.

## Verification Checklist

The PRNG contract is satisfied when:

- `main.py` creates exactly one non-empty `global_seed` per session.
- `_build_rng_pools(global_seed)` derives all Python RNG pools from `__RAND_SEED_POOL__`.
- `rand_met_module.RAND_MET_DERIVATIVE` is set before font manifest generation.
- `window.__GLOBAL_SEED` exists only as bootstrap input for the window producer.
- `BootstrapHideModule(window)` creates `Core.__internal.prng` before `RNGsetModule(window)`.
- `RNGsetModule(window)` fills `Core.__internal.prng`.
- window consumers read `Core.__internal.prng`, not `window.__GLOBAL_SEED`.
- worker/service-worker seed input is `CDP_GLOBAL_SEED`.
- worker consumers read local `self.Core.__internal.prng`.
- no active runtime route uses `C.__PRNG_STATE__`, `C.state.__PRNG_STATE__`, or `CanvasPatchContext.__PRNG_STATE__`.
