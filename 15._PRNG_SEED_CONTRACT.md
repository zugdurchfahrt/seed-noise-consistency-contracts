# PRNG Seed / global_seed contract

## Назначение

PRNG Seed - это детерминированная основа runtime-профиля. Pipeline должен создавать контролируемую псевдослучайность: разные сессии могут выглядеть по-разному, но внутри одной сессии все зависящие от seed поверхности должны оставаться согласованными. Это касается выбора профиля, permissions, headers, VPN-helper веток, генерации font manifest, canvas noise, WebGL masks, navigator-derived jitter и worker-local patches.

Контракт не означает "рандомизировать все подряд". Контракт означает: один session seed создается один раз, каждая downstream-random ветка выводится из него через именованный label, а каждый runtime-consumer читает уже материализованный hidden PRNG owner, а не придумывает собственный seed path.

Канонический принцип текущего pipeline:

```txt
Python global_seed
  -> named Python RNG pools
  -> browser bootstrap seed input
  -> Core.__internal.prng
  -> Core.__internal.prng.rand.use(label)
  -> module-local deterministic random streams
```

`seed` и PRNG owner - разные роли. `seed` является bootstrap input. Runtime-владелец PRNG-состояния - только `Core.__internal.prng`.

## Сводное состояние seed pipeline

Текущий поток:
1. Python генерирует `global_seed`.
2. [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) внедряет `__GLOBAL_SEED` в инициализацию window.
3. Seed-путь worker/service-worker использует `CDP_GLOBAL_SEED`.
4. [bootstrap_hide.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/bootstrap_hide.js) создает `Core.__internal.prng`.
5. [prng_seed.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/prng_seed.js) резолвит bootstrap seed и устанавливает:
   - `Core.__internal.prng.seed`;
   - `Core.__internal.prng.strToSeed`;
   - `Core.__internal.prng.mulberry32`;
   - `Core.__internal.prng.rand`;
   - `Core.__internal.prng.pools`.
6. Нижестоящие graphics/media/navigator модули используют `Core.__internal.prng` как единственный owner-space pipeline.

Специальная seed policy:
- если bootstrap seed отсутствует в `rng_set`, текущий код emits `rng_set:preflight:global_seed_missing`;
- producer ставит внутренний seed-missing lock (`producerLock: 'locked'`), чтобы предотвратить позднюю замену seed;
- это документированное policy-исключение, и оно не должно молча конвертироваться в release/retry.

## Источник session seed

[main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) владеет созданием session seed. На старте процесса/сессии он создает:

```py
global_seed = uuid.uuid4().hex
```

Это значение является единственным root input для контролируемой project randomness в рамках данного запуска.

После этого [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) выводит Python-side random pools через `_build_rng_pools(global_seed)`. Общий derivation root:

```py
__RAND_SEED_POOL__
```

Для каждого Python label собирается material:

```py
__RAND_SEED_POOL__|<label>|<global_seed>
```

Material хешируется через SHA-256. Первые 8 байт digest становятся numeric seed, после чего создается module-local RNG:

```py
random.Random(numeric_seed)
```

Текущие Python pool labels:

- `profile`
- `permissions`
- `headers`
- `vpn`

Эти pools передаются в соответствующие Python modules. Важная контрактная норма: Python-модули не владеют независимой ambient randomness. Они получают ветку, выведенную из единственного session seed.

### Headers RNG и navigation Accept cache

`headers` pool обслуживает [headers_adapter.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/tools_runtime/headers_adapter.py): он выбирает navigation `Accept` template и переставляет image-типы внутри него через `_pick_nav_template(key, major)`.

`_pick_nav_template` кэшируется через `@lru_cache` по `(browser family, major version)`, чтобы `Accept` не менялся между запросами одной session. Так как `global_seed` не входит в cache key, [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) обязан при новой seed-сессии сначала назначить `headers_adapter_module.random = headers_rng`, а затем очистить cache через `headers_adapter_module._pick_nav_template.cache_clear()`.

`cache_clear()` здесь является method, добавленным `@lru_cache`, а не отдельной pipeline-функцией. Его роль - удалить cached выбор navigation `Accept` template перед новой session seed, чтобы headers branch реально обслуживалась текущим `headers_rng`, а не предыдущим cached результатом.

Это правило специфично для `headers`, потому что это единственная текущая Python RNG branch, где random-dependent result закрыт `@lru_cache` поверх key, не содержащего `global_seed`. `profile_rng`, `permissions_rng` и `vpn_rng` потребляются напрямую без persistent function cache между session. `rand_met` получает derivative seed и строит local branches из derivative material; JavaScript PRNG пересоздается в новом realm через `Core.__internal.prng`. Поэтому для них отдельный `cache_clear()` contract не нужен.

Persistent cache для RNG branch допустим только если одновременно выполняются три условия:
1. результат зависит от RNG;
2. функция может вызываться повторно в одной session;
3. cache живет дольше seed-session или его key не содержит `global_seed`.

`profile_rng` не должен иметь такой cache: он последовательно собирает один `profile` в [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py), после чего результат материализуется в profile object. `permissions_rng` собирает один `devices_conf`, который затем хранится в profile/runtime state. `vpn_rng` выбирает VPN config на стороне `VPNClient`; если нужно закрепить конкретный config на session, его следует сохранять как выбранный session value, а не кэшировать random-dependent function. Нормативная модель для этих веток - выбрать один раз и читать материализованный результат.

## Производная ветка rand_met

[rand_met.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/generators/rand_met.py) получает отдельную ветку, потому что генератор шрифтов должен иметь несколько внутренних substreams, но при этом оставаться привязанным к тому же session seed.

[main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) выводит:

```py
_derive_rand_met_seed_material(global_seed, "rand_met")
```

через:

```py
sha256("__RAND_SEED_POOL__|rand_met|<global_seed>")
```

и записывает результат в:

```py
rand_met_module.RAND_MET_DERIVATIVE
```

[rand_met.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/generators/rand_met.py) не должен импортировать [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) обратно и не должен создавать второй независимый root seed. Его root - только `RAND_MET_DERIVATIVE`. Внутри [rand_met.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/generators/rand_met.py) локальные ветки выводятся по схеме:

```py
__RAND_MET_POOL__|<label>|<RAND_MET_DERIVATIVE>|<extra parts...>
```

Важные текущие local labels:

- `manifest_rng` - выбор и sampling font fingerprint set.
- `meta_rng` - генерация font metadata и helper random strings.
- `cache_namespace` - изоляция derivative-scoped base64 side-cache.

`_derive_local_rng(...)` хеширует local material, берет первые 16 hex-символов как numeric seed и создает локальный `random.Random`. Это значит, что font randomness детерминирована для одного и того же `global_seed` и тех же platform/index inputs, но branch-isolated от profile/permissions/headers/VPN randomness.

## Window bootstrap-транспорт

[main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) передает session seed в window bundle как:

```js
window.__GLOBAL_SEED
```

Это bootstrap transport surface. Свойство намеренно создается non-enumerable в bootstrap object definition и нужно только для ранней инициализации hidden PRNG owner.

Нормативное правило:

```txt
window.__GLOBAL_SEED / G.__GLOBAL_SEED разрешены только как bootstrap seed input для producer-модуля prng_seed.js.
После owner-transfer в Core.__internal.prng они запрещены как downstream consumer path.
```

Иными словами, запрет относится не к самому факту существования `__GLOBAL_SEED` в bootstrap-слое, а к чтению этого значения downstream-модулями после того, как `RNGsetModule(window)` наполнил `Core.__internal.prng`.

Порядок page bundle является частью контракта:

```js
init_params with __GLOBAL_SEED
-> BootstrapHideModule(window)
-> LOGGingModule(window)
-> source definitions are loaded
-> CoreWindowModule(window)
-> RNGsetModule(window)
-> any module that calls Core.guardFlag(...)
-> PRNG-dependent modules
```

[bootstrap_hide.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/bootstrap_hide.js) создает hidden owner-space до вызова `RNGsetModule(window)`. [core_window.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/core_window.js) валидирует owner-space и публикует GuardFlag infrastructure. [prng_seed.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/prng_seed.js) наполняет owner runtime-данными PRNG.

Так как `Core.guardFlag(...)` строит seed-derived token через `Core.__internal.prng.strToSeed`, любой модуль, вызывающий `Core.guardFlag(...)`, является downstream consumer относительно `RNGsetModule(window)` и не должен выполняться раньше него. `RNGsetModule(window)` сам является producer-исключением и не вызывает `Core.guardFlag(...)`.

## Канонический owner

Единственный канонический runtime-владелец PRNG:

```js
Core.__internal.prng
```

Нормализованная форма:

```js
{
  seed: "",
  strToSeed: null,
  mulberry32: null,
  rand: null,
  pools: Object.create(null),
  marker: "envrand",
  version: "1.1.1"
}
```

[bootstrap_hide.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/bootstrap_hide.js) отвечает за hidden-first создание этого owner-space. Он не наполняет реальные PRNG runtime-data, а только гарантирует, что owner существует и имеет корректную начальную форму.

[core_window.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/core_window.js) обязан трактовать `Core.__internal.prng` как обязательную infrastructure. Если owner отсутствует, это `pipeline missing data`, а не повод создавать альтернативный PRNG owner в другом месте.

[prng_seed.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/prng_seed.js) является producer-модулем и наполняет owner следующими полями:

- `seed`
- `strToSeed`
- `mulberry32`
- frozen `rand`
- named `pools`
- `marker`
- `version`

## RNGsetModule

`RNGsetModule(realm)` - это thin execution shell. Он не является owner-state path.

`RNGsetModule` является producer-исключением из обычного GuardFlag lifecycle: он не вызывает `Core.guardFlag(...)`, потому что именно он первым наполняет `Core.__internal.prng.strToSeed`, необходимый для seed-derived guard tokens. Его idempotency проверяется через canonical PRNG owner (`rand.__marker === 'envrand'` / `rand.use`) и producer-local seed-missing lock.

Разрешенная роль:

- выполняться во время bundle orchestration;
- читать bootstrap seed input текущего realm;
- наполнять уже существующий `Core.__internal.prng`;
- при необходимости публиковать временный callable через `FernwehContext.__prngRuntime__.RNGsetModule` для orchestration.

Запрещенная роль:

- хранить PRNG state внутри `RNGsetModule`;
- делать `RNGsetModule` consumer route;
- публиковать public `window.rand`, `window.strToSeed` или `window.mulberry32` как нормативный runtime API.

Текущий producer читает seed input по realm:

```js
window realm: __GLOBAL_SEED
worker realm: CDP_GLOBAL_SEED
```

После этого он пишет только в:

```js
Core.__internal.prng
```

Если seed отсутствует, текущий producer репортит `rng_set:preflight:global_seed_missing` и ставит producer-local lock на `Core.__internal.prng`, чтобы late seed не мог молча заменить branch после того, как consumers уже могли увидеть состояние.

## JavaScript PRNG-ветки

`Core.__internal.prng.rand` публикует:

```js
rand.use(label)
```

`label` - имя ветки. Runtime branch material:

```js
__RAND_SEED_POOL__|<label>|<seed>
```

`strToSeed(material)` превращает этот material в uint32 seed. `mulberry32(numericSeed)` создает детерминированный `[0, 1)` generator. `pools[label]` кеширует generator, поэтому повторный `rand.use(label)` возвращает тот же branch stream в рамках realm.

Каждый модуль обязан выбирать явный label, описывающий его ветку. Label collision означает намеренно общий stream; случайное повторное использование label является contract bug.

Producer может привести non-string label к строке и выдать diagnostic, но модули должны передавать stable strings. Consumer code не должен использовать object identity, timestamps, current URL, wall-clock time, `Math.random` или свежие UUID как скрытый источник randomness.

- [webgl.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/graphics/webgl.js) требует `Core.__internal.prng.rand.use`.
- [nav_total_set.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/patches/navigator/nav_total_set.js) требует `Core.__internal.prng.rand`.

Запрещенные downstream consumer paths:

Разрешенные текущие вхождения `__GLOBAL_SEED` в active pipeline:

- [bootstrap_hide.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/bootstrap_hide.js) - перечисляет `__GLOBAL_SEED` среди bootstrap input keys для раннего capture/cleanup lifecycle.
- [prng_seed.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/prng_seed.js) - producer читает `window.__GLOBAL_SEED` / `G.__GLOBAL_SEED` до owner-transfer и записывает seed в `Core.__internal.prng`.

Любое другое чтение `window.__GLOBAL_SEED` / `G.__GLOBAL_SEED` в PRNG-dependent modules должно считаться contract violation.


## Worker и Service Worker seed

Worker realms не используют window bootstrap-name как нормативное имя seed. Источник seed в worker:

```js
CDP_GLOBAL_SEED
```

[main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) вызывает `cdp.enable_seed_inject(global_seed)`. [cdp_catapult.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/generators/cdp_catapult.py) сохраняет это значение как `CDP_GLOBAL_SEED` и inject-ит worker/service-worker prelude, который определяет его в target realm.

Нормативная worker-цепочка:

```txt
Python global_seed
-> CDP_GLOBAL_SEED in WorkerGlobalScope
-> local Core.__internal.prng
-> local RNGsetModule(self)
-> worker-local consumers
```

Worker не потребляет `window.__GLOBAL_SEED`. Worker не восстанавливает PRNG через env snapshot.  Nested workers должны получать собственный local `CDP_GLOBAL_SEED` до local PRNG initialization.

Service worker compatibility следует тому же принципу: seed локален для worker scope как `CDP_GLOBAL_SEED`, а PRNG state принадлежит local `Core.__internal.prng`.

## Guard Seed Tag

Guard tokens должны быть deterministic для realm и связаны с canonical PRNG owner. Intended source:

```js
Core.__internal.prng.seed
Core.__internal.prng.strToSeed
```

[core_window.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/core_window.js) кеширует derived guard tag на PRNG owner как `__guardSeedTag`. Этот cache принадлежит owner-space и не должен становиться вторым seed source.

[core_window.js](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/assets/scripts/window/core/core_window.js) строит guard seed tag только через `Core.__internal.prng.strToSeed`. Отсутствующий или упавший hasher означает нарушение целостности canonical PRNG owner. В обоих случаях pipeline обязан записать diagnostic `core_window:guard_seed_hash_failed` через `__DEGRADE__.diag` и выполнить fail-fast throw.

## Диагностика и Fail-Fast

PRNG failures являются нарушением целостности pipeline, а не обычным отсутствием feature.

Обязательное diagnostic behavior:

- отсутствующий `global_seed` в Python seed builders должен сразу давать исключение;
- отсутствующий `Core.__internal.prng` является `pipeline missing data`;
- отсутствующий worker `CDP_GLOBAL_SEED` является worker seed inject failure;
- отсутствующие PRNG helpers у consumer не должны молча заменяться public globals;
- producer readiness и failure paths должны репортиться через `__DEGRADE__.diag`.

Public/native browser surface не должен раскрывать project-internal seed mechanics как feature API. Диагностика является internal pipeline telemetry, а не public API behavior.

## Границы детерминизма

Один и тот же seed вместе с теми же profile inputs должен давать те же deterministic branch outputs внутри той же версии pipeline.

Разные labels должны давать изолированные streams:

```js
__RAND_SEED_POOL__|canvas|seed
__RAND_SEED_POOL__|webgl|seed
__RAND_SEED_POOL__|audio|seed
```

Python и JavaScript разделяют общий концептуальный root и форму label material, но не обещают byte-for-byte identity алгоритмов RNG:

- Python pools используют SHA-256 material и `random.Random`.
- JavaScript runtime pools используют `strToSeed` и `mulberry32`.
- [rand_met.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/tools/generators/rand_met.py) использует собственное subtree `__RAND_MET_POOL__` от Python derivative `rand_met`.

Нормативный invariant - branch ownership и deterministic derivation, а не идентичность алгоритмов между языками.

## Запрещенные patterns

Запрещено добавлять:

- ambient `random` / `Math.random` в deterministic modules;
- независимые UUID/time-based seeds после появления `global_seed`;
- module-local seed roots, не выведенные из `global_seed`;
- direct downstream consumer reads из `window.__GLOBAL_SEED` / `G.__GLOBAL_SEED` после owner-transfer в `Core.__internal.prng`;
- worker seed aliases с именем `__GLOBAL_SEED` как нормативный path;
- PRNG state под `FernwehContext.state`;
- public global helpers `window.rand`, `window.strToSeed`, `window.mulberry32`;

## Проверочный чек-лист

PRNG contract выполнен, если:

- [main.py](https://github.com/zugdurchfahrt/seed-noise-consistency/blob/borderline/main.py) создает ровно один non-empty `global_seed` на сессию.
- `_build_rng_pools(global_seed)` выводит все Python RNG pools из `__RAND_SEED_POOL__`.
- `rand_met_module.RAND_MET_DERIVATIVE` установлен до font manifest generation.
- `window.__GLOBAL_SEED` / `G.__GLOBAL_SEED` существуют только как bootstrap input для window producer и не читаются downstream consumers.
- `BootstrapHideModule(window)` создает `Core.__internal.prng` до `RNGsetModule(window)`.
- `RNGsetModule(window)` выполняется до любого window module, который вызывает `Core.guardFlag(...)`.
- `RNGsetModule(window)` наполняет `Core.__internal.prng`.
- Guard seed tag строится только через `Core.__internal.prng.strToSeed`; missing/failed hasher дает `core_window:guard_seed_hash_failed` и fail-fast throw.
- Window consumers читают `Core.__internal.prng`, а не `window.__GLOBAL_SEED`.
- Worker/service-worker seed input - `CDP_GLOBAL_SEED`.
- Worker consumers читают local `self.Core.__internal.prng`.
