# Fonts Compound Contract

## 1. Зачем существует шрифтовой compound

Шрифтовой compound - это не отдельный "патч шрифтов", а сквозной контур: Python-генератор подготавливает управляемый набор `.woff2`, generated JS переносит runtime-config в hidden state, `font_module.js` регистрирует managed `FontFace`, а `canvas.js` и `context.js` используют готовность шрифтов как часть canvas/text metrics pipeline.

Главная идея compound: шрифты должны быть не случайным набором, появляющимся из кода "ниоткуда", а детерминированным профильным материалом. Один общий seed создает профиль, профиль задает платформу, генератор выбирает и описывает fonts payload, runtime загружает payload через нативные browser APIs, а consumers читают только canonical hidden state.

## 2. Методологическая модель

Compound делится на четыре слоя.

1. Offline generation layer
   `rand_met.py` работает до runtime-инъекции. Он выбирает platform-scoped шрифты, проверяет их, готовит metadata, строит manifest и generated JS transport.

2. Hidden state transport layer
   `bootstrap_hide.js` заранее создает canonical owner `C.state.__FONTS__`. Generated patch не создает root, а только заполняет `C.state.__FONTS__.__CONFIG__.configs`.

3. Runtime loading layer
   `font_module.js` валидирует hidden slots, фильтрует configs по DOM-платформе, грузит `FontFace`, добавляет loaded faces в `document.fonts`, ведет `ready/error/awaitReady/familySnapshot`.

4. Consumer layer
   `context.js` является carrier для `measureText`, а `canvas.js` применяет post-processing только когда fonts state готов. Canvas не владеет config и не чинит шрифтовую ветку.

Принципиальная граница: generator создает данные, runtime применяет данные, consumers читают состояние. Ни один нижний слой не должен пересоздавать источник истины верхнего слоя.

## 3. One Point Of Truth: seed, profile, platform

Общий seed создается в `main.py` как `global_seed`. Из него строятся независимые RNG pools для разных подсистем. Для шрифтов есть отдельная производная:

```js
global_seed
  -> _derive_rand_met_seed_material(global_seed, "rand_met")
  -> rand_met_module.RAND_MET_DERIVATIVE
  -> rand_met.py local derivation
```

В window runtime тот же общий seed прокидывается как hidden/global bootstrap value:

```js
window.__GLOBAL_SEED
```

Но текущий `rand_met.py` не читает `window.__GLOBAL_SEED` напрямую. Его источник - `RAND_MET_DERIVATIVE`, который `main.py` обязан задать до вызова `generate_font_manifest(...)`.

Внутри `rand_met.py` локальная деривация выглядит так:

```js
"__RAND_MET_POOL__" | label | RAND_MET_DERIVATIVE | parts...
  -> sha256
  -> random.Random(int(hash[:16], 16))
```

Зачем так сделано:

- разные подсистемы не расходуют один общий `random` stream;
- fonts manifest RNG и metadata RNG не влияют друг на друга;
- один и тот же seed + платформа + каталог шрифтов дают тот же fonts payload;
- смена seed меняет payload детерминированно, а не хаотически.

Fail-fast правило: если `RAND_MET_DERIVATIVE` отсутствует или пустой, generator бросает `RuntimeError` до filesystem mutations.

## 4. Canonical Ownership

Единственный canonical owner шрифтовой ветки:

```js
FernwehContext.state.__FONTS__
```

Схема slot:

```js
C.state.__FONTS__ = {
  __STATE__: {
    ready: false,
    error: null,
    awaitReady: null,
    awaitReadyStatus: null,
    awaitReadyResolve: null,
    awaitReadyReject: null,
    familySnapshot: {
      allowedFamilies: null,
      runtimeFamilies: new Set(),
      platformDom: null,
      versionToken: null
    }
  },
  __CONFIG__: {
    configs: []
  }
}
```

Ownership:

- `bootstrap_hide.js` создает `C.state`, `C.state.__FONTS__`, `__STATE__`, `__CONFIG__`.
- Generated fonts patch заполняет только `C.state.__FONTS__.__CONFIG__.configs`.
- `font_module.js` читает config и наполняет `__STATE__`.
- `canvas.js` читает `__STATE__` как consumer.
- `context.js` проводит canvas hook, но не владеет fonts config/state.

Запрещенные canonical paths:

- `C.state.__FONTS_STATE__`
- `C.state.__FONTS_CONFIG__`
- `window.fontPatchConfigs`

`window.fontPatchConfigs` был старым transport-подходом. Текущий transport идет через hidden `C.state.__FONTS__.__CONFIG__.configs`.

## 5. Pipeline order

Текущий порядок в `main.py`:

1. `main.py` определяет `dom_platform`.
2. `main.py` задает `rand_met_module.RAND_MET_DERIVATIVE`.
3. Перед сборкой page bundle вызывается:

```py
rand_met_module.generate_font_manifest(MANIFEST_PATH, dom_platform)
```

4. В bundle сначала попадает `bootstrap_hide.js` и выполняется `BootstrapHideModule(window)`.
5. Затем в bundle присутствуют runtime modules, включая `font_module.js`, `canvas.js`, `context.js`.
6. Generated `font_patch.generated.js` выполняется до вызова `FontPatchModule(window)`.
7. Потом вызывается `FontPatchModule(window)`, затем canvas/webgl/worker/webgpu/audio/context modules.

Смысл порядка:

- generated patch должен увидеть уже созданный `C.state.__FONTS__.__CONFIG__`;
- `font_module.js` должен увидеть уже заполненный config;
- `canvas.js` должен стартовать после `font_module.js`, потому что его cache epoch зависит от `familySnapshot.versionToken`;
- `context.js` должен вызывать canvas hook через общий hook registry, не создавая fonts state.

Если этот порядок нарушен, это pipeline missing data, а не штатная деградация.

## 6. Generator layer: что именно делает `rand_met.py`

`rand_met.py` является offline producer. Он не патчит browser API и не решает runtime receiver/descriptor задачи. Его задача - подготовить согласованный набор данных, пригодный для runtime loading.

Выходы:

- `sunami/assets/Manifest/fonts-manifest.json`
- `sunami/assets/JS_fonts_patch/font_patch.generated.js`
- обновленный platform index `assets/generated_fonts/<platform>/fonts_index.json`
- side-cache base64 namespaces в `assets/generated_fonts/<platform>/cache_data`

Платформа нормализуется только в:

- `Win32`
- `MacIntel`

Любая другая platform value вызывает `ValueError`.

### 6.1. Step 0: platform and derivative preflight

До работы с файлами generator обязан:

1. Нормализовать platform к DOM-форме.
2. Проверить `RAND_MET_DERIVATIVE`.
3. Получить platform target dir через `get_target_dir_for(platform)`.

Методологически это защита от "случайного" manifest: если нет seed derivative или platform unknown, нельзя создавать новый transport.

### 6.2. Step 1: raw fonts intake

Raw source:

```js
assets/fonts_raw
```

Platform target:

```js
assets/generated_fonts/Win32
assets/generated_fonts/MacIntel
```

Новые `.woff2` из `fonts_raw` проверяются и переносятся в platform target. Имя в target строится из platform tag, порядкового индекса и md5 salt:

```js
W32_<idx>_<md5-prefix>.woff2
mac_<idx>_<md5-prefix>.woff2
```

После успешного копирования raw файл удаляется. Это делает `generated_fonts/<platform>` рабочим каталогом, а не временной копией raw input.

### 6.3. Step 1 filters: качество и пригодность

Перед попаданием в generated catalog файл проходит проверки:

- non-empty payload;
- header `wOF2`;
- читаемость через `fontTools.ttLib.TTFont`;
- наличие `cmap`;
- наличие basic ASCII letters/digits или допустимых color tables;
- отбраковка icon/emoji traits;
- `fsType` license restrictions;
- sanity metrics check, чтобы экстремальные ascent/descent не ломали layout.

Зачем это нужно:

- invalid WOFF2 не должен попадать в runtime transport;
- icon/emoji/symbol-like fonts могут давать нестабильный или слишком заметный fingerprint;
- экстремальные font metrics могут ломать canvas/layout;
- license-restricted fonts не должны становиться managed payload.

Это фильтр качества до deterministic selection. Seed не должен выбирать из мусора.

### 6.4. Step 2: platform index

`ensure_platform_index(platform)` синхронизирует `fonts_index.json` с фактическими `.woff2` в platform target.

Индекс хранит per-file:

- `size`
- `mtime`
- `md5`

Правила индекса:

- каталог берется только через `get_target_dir_for(platform)`;
- отсутствующие на диске файлы удаляются из index;
- новые/измененные файлы перечитываются, валидируются по `wOF2`, получают md5;
- старые записи без md5 получают backfill;
- obsolete inline field `data` удаляется;
- orphan `.b64` cache entries чистятся после актуализации md5 set.

Методологический смысл: index - это не источник runtime truth, а стабильный inventory platform catalog. Runtime truth появится позже в generated JS config.

### 6.5. Step 3: deterministic selection

После индекса generator собирает:

```py
all_names = list(files_map.keys())
```

Затем строит seed parts через `_manifest_seed_parts(platform, all_names)` и локальный RNG:

```py
_rng = _derive_local_rng("manifest_rng", *_seed_parts)
```

Количество выбирается из:

- `FONTS_MIN_N`, default `56`;
- `FONTS_MAX_N`, default `58`;
- `max_n = len(all_names)`.

Алгоритм:

```js
hi = min(MAX_N, max_n)
lo = 1 if max_n < MIN_N else MIN_N
N = rng.randint(lo, hi)
fingerprint_names = rng.sample(sorted(all_names), k=N)
fingerprint_names.sort()
```

Смысл:

- состав стабилен при том же seed derivative, platform и inventory;
- порядок стабилен после sort;
- если доступных файлов меньше минимума, generator не выдумывает файлы, а сужает lower bound и пишет warning.

Важно: deterministic selection не гарантирует финальное попадание каждого выбранного файла в runtime config. Step 4 может отбросить файл по md5 duplicate, invalid data URL или family repeat limit.

### 6.6. Step 4: data URL, metadata, config entry

Для каждого `fingerprint_name` generator:

1. Берет record из index.
2. Строит data URL через `_get_data_url(...)`.
3. Проверяет наличие `md5`.
4. Отбрасывает duplicate `md5`.
5. Читает исходные `family/subfamily` через `get_font_compare(...)`.
6. Генерирует metadata через `generate_font_metadata(...)`.
7. Вычисляет resolved family.
8. Вычисляет `weight/style`.
9. Вычисляет `cssFamily`.
10. Вычисляет `cssLoadQuery`.
11. Добавляет `cfg` в `temp_configs`.

Data URL:

```js
data:font/woff2;base64,<base64>
```

Base64 кэшируется в:

```js
assets/generated_fonts/<platform>/cache_data/<namespace>/<md5>.b64
```

Кэш не является source of truth. Source of truth для payload identity - md5 в index и config.

### 6.7. Metadata generation

`generate_font_metadata(platform, subfamilies_src)` возвращает name-table-like dictionary:

- nameID 1: `family`
- nameID 2: `subfamily`
- nameID 3: `unique_id`
- nameID 4: `full_name`
- nameID 5: `version`
- nameID 6: `postscript_name`
- nameID 9: `designer`
- nameID 13: `license`

Текущий принцип:

- family выбирается из platform families + common families;
- subfamily выбирается из normalized subfamilies;
- `full_name` выводится из `family/subfamily`;
- `postscript_name` выводится из `family-subfamily`;
- `designer/license` сначала ищутся в family mapping JSON, иначе берутся из fallback pools;
- version генерируется локальным `_META_RNG`.

Важно: metadata RNG отделен от manifest selection RNG. Выбор списка файлов и генерация витринных полей не должны расходовать один и тот же stream.

### 6.9. Family and CSS identity

Runtime family определяется так:

```js
fam = cfg.cssFamily || cfg.family
```

В generator:

```py
cssFamily = _derive_css_family(resolved_family, name_no_ext)
cssLoadQuery = _derive_css_load_query(cssFamily, style, weight)
```

`_derive_css_family(...)` не синтезирует family из filename. Если `resolved_family` пустой, `cssFamily` остается пустым, а `_derive_css_load_query(...)` обязан бросить `RuntimeError`.

Смысл: runtime CSS identity не должна возникать из fallback filename. Filename может быть транспортным именем файла, но не источником CSS family truth.

### 6.10. Current duplicate behavior

Текущие duplicate rules:

- duplicate `md5` - hard skip;
- `family_counter[resolved_family] >= 5` - hard skip;
- duplicate `uniq_triple = (resolved_family, full_name, postscript)` - сейчас только debug "keep", не skip;
- duplicate `cssLoadQuery` - сейчас только debug "keep", не skip.

Это важно для контракта: нельзя писать, что generator строго доказывает уникальность `uniq_triple` или `cssLoadQuery`. Сейчас это диагностируемое/видимое поведение, но не hard invariant.

### 6.11. Step 5: manifest and generated JS

`runtime_font_metadata` собирает runtime identity без `url`. Затем:

```py
configs_for_js = runtime_font_metadata + url
manifest_payload = metadata/diagnostic projection without url
```

Итог:

- `fonts-manifest.json` - metadata/diagnostic artifact;
- `font_patch.generated.js` - runtime transport artifact.

В текущем состоянии manifest payload не содержит `url`. Managed `data:font/woff2;base64,...` переносится в generated JS config.

Generated patch из `font_patch.template.j2`:

1. Находит `globalThis.FernwehContext`.
2. Требует `C.state`.
3. Требует `C.state.__FONTS__`.
4. Требует `C.state.__FONTS__.__CONFIG__`.
5. Присваивает:

```js
slot.configs = <configs_json>;
```

Generated patch не создает missing slots. Если hidden state не подготовлен bootstrap-слоем, patch должен бросить ошибку.

### 6.12. Transport signature

Generator считает:

```py
transport_signature = sha256(json.dumps(runtime_font_metadata))
```

Если signature изменилась, она записывается в platform index. Это служебный контроль изменения transport identity. Он не заменяет runtime state и не является public API.

## 7. Runtime config semantics

`font_module.js` читает только:

```js
C.state.__FONTS__.__CONFIG__.configs
```

Платформенная фильтрация:

```js
cfg.platform_dom === C.state.__ENV_PROFILE__.__PLATFORM__.domPlatform
```

Если хотя бы одна запись имеет `platform_dom`, используется platform-scoped subset. Если у всех записей нет `platform_dom`, используется весь массив.

Runtime family:

```js
const fam = f.cssFamily || f.family;
```

Runtime config должен быть уже готов к этому моменту. `font_module.js` не должен пересоздавать generated config и не должен искать старый `window.fontPatchConfigs`.

## 8. Runtime loading: FontFace + CSS path

Window branch активен только при наличии:

- `document`;
- `document.fonts`;
- `document.fonts.add`.

Для каждой platform-scoped entry:

```js
const fam = f.cssFamily || f.family;
const src = `url(${JSON.stringify(f.url)}) format("woff2")`;
const ff = new FontFace(fam, src, {
  weight: f.weight || 'normal',
  style: f.style || 'normal',
  display: 'swap'
});
await ff.load();
document.fonts.add(loaded);
```

Параллельно текущий `font_module.js` строит CSS branch:

```css
@font-face {
  font-family: "<fam>";
  src: url("<data-url>") format("woff2");
  font-weight: <weight>;
  font-style: <style>;
  font-display: swap;
}
```

Этот CSS пишется в `<style id="font-patch-styles">`.

Зачем нужны оба пути:

- `FontFace` path регистрирует managed faces в `document.fonts`;
- CSS `@font-face` path обеспечивает обычное CSS font matching поведение;
- оба пути используют один и тот же platform-scoped config, поэтому не расходятся по source of truth.

## 9. Ready lifecycle

Перед загрузкой fonts state переводится в loading/pending состояние.

После `Promise.allSettled(...)`:

- если есть failures, state становится failed/rejected;
- если все entries loaded, runtime ждет native `document.fonts.ready`;
- затем ждет double `requestAnimationFrame`;
- затем выставляет `ready = true`;
- резолвит `awaitReady`;
- dispatch `fontsready`;
- обновляет `familySnapshot.versionToken`.

State fields:

- `ready`
- `error`
- `awaitReady`
- `awaitReadyStatus`
- `awaitReadyResolve`
- `awaitReadyReject`
- `familySnapshot`

Почему double RAF важен: он отделяет факт загрузки `FontFace` от момента, когда browser успел применить font state в layout/text metrics observable paths. Это runtime stabilization barrier для consumers вроде canvas.

## 10. Family snapshot

`familySnapshot` - это runtime epoch state для связи fonts с consumers.

Состав:

- `allowedFamilies`: Set из platform-scoped configs, по `cfg.cssFamily` и `cfg.family`;
- `runtimeFamilies`: Set из live `FontFaceSet`;
- `platformDom`: текущий DOM platform;
- `versionToken`: строковый token текущей эпохи.

`versionToken` должен меняться при изменении:

- platform;
- состава configs;
- runtime families;
- `ready`;
- `awaitReadyStatus`;
- `error`.

Методологически это не "список для public API", а cache invalidation signal. `canvas.js` использует token, чтобы text metrics cache не переживал смену шрифтовой эпохи.

## 11. FontFace constructor policy

`font_module.js` патчит `FontFace` как data target через общий `Core.applyTargets` path и `__wrapNativeCtor`.

Задача wrapper: не заменить public API своей моделью, а минимально нормализовать `source` для managed local-only cases, сохранив native constructor/prototype/class-extension behavior.

`sanitizeFontFaceSource(source, family, descriptors)`:

1. Разбирает top-level comma-separated `src`.
2. Выделяет `local(...)`.
3. Оставляет non-local entries.
4. Ищет managed config через `matchRuntimeFontConfig(family, descriptors)`.

Match criteria:

- normalized requested family;
- `cfg.cssFamily || cfg.family`;
- fallback match по `cfg.full_name`;
- fallback match по `cfg.postscript_name`;
- `style`, default `normal`;
- `weight`, default `normal`.

Branches:

- local-only + matched managed config with `data:font/woff2;base64,...` -> replace source with managed `url("<data>") format("woff2")`;
- local-only + no proven match -> native passthrough, diag `fonts:fontface:local_only_passthrough_not_proven`;
- mixed local + url -> strip local entries, keep non-local entries;
- non-local only -> keep source.

Важная формулировка: `local_only_replaced_with_managed_src` не доказывает, что page requested "тот же физический системный шрифт". Оно доказывает только, что runtime request достаточно совпал с managed config по family/style/weight/full/postscript criteria, чтобы заменить local-only source на managed data source.

## 12. FontFaceSet policy

Текущий public carrier status:

- `FontFaceSet.ready` патчится как accessor wrapper и вызывает native getter через `Reflect.apply`.
- `FontFaceSet.check` оставлен native.
- `FontFaceSet.forEach` оставлен native.
- `FontFaceSet.load` оставлен native.

Причина:

- сохранить native abuse/error path;
- не ломать receiver checks;
- не ломать descriptor/prototype invariants;
- не вводить неадмиссимый public method carrier.

Диагностика:

- `fonts:method:check_native_passthrough`
- `fonts:method:forEach_native_passthrough`
- `fonts:promise:load_native_passthrough`


## 13. Canvas and context integration

`context.js` патчит `CanvasRenderingContext2D.prototype.measureText` через общий context path:

```js
native measureText
  -> context.js carrier
  -> FernwehHooks.applyMeasureTextHook
  -> canvas.js applyMeasureTextHook
```

`canvas.js` читает:

```js
C.state.__FONTS__.__STATE__
```

`applyMeasureTextHook(nativeMetrics, text, font)`:

- получает `fontStr`;
- читает `fontsState.ready`;
- если `ready !== true`, возвращает native `TextMetrics`;
- читает `familySnapshot.versionToken`;
- добавляет token в cache key;
- возвращает Proxy над native `TextMetrics`;
- exposes only native-present metric fields.

Canvas не создает `__FONTS__`, не создает `__CONFIG__`, не чинит generated config и не обязан знать generator details. Его контракт - consumer of readiness and epoch.

## 14. DOM override branch

Текущий `font_module.js` содержит macOS-only DOM override:

- активен только при `domPlatform === 'MacIntel'`;
- берет первый filtered font family;
- добавляет/обновляет `<style id="force-font-override">`;
- выставляет `font-family: <managed family>, Helvetica, Arial, sans-serif !important`.

Это runtime branch, а не canonical source of truth. Canonical source остается:

```js
C.state.__FONTS__.__CONFIG__.configs
C.state.__FONTS__.__STATE__
```

## 15. Diagnostics and rollback

Ошибки compound должны идти через `__DEGRADE__.diag`/module logger path, а не через silent swallow.

Классы ошибок:

- pipeline missing data: отсутствует `FernwehContext`, `state`, `__FONTS__`, `__STATE__`, `__CONFIG__`, required config fields;
- browser structure missing data: отсутствует `document.fonts`, native constructor/accessor, browser API shape;
- runtime failure: load/add/settle/event/DOM operation failure.

`font_module.js` сохраняет prior runtime state и при fatal path пытается rollback к clone state.

Коды rollback/fatal:

- `fonts:rollback_failed`
- `fonts:fatal`

Основные runtime diagnostics:

- `fonts:filtered_empty`
- `fonts:filtered_count`
- `fonts:load_item_failed`
- `fonts:document_fonts_add_failed`
- `fonts:load_settled`
- `fonts:load_settled_with_failures`
- `fonts:load_unexpected_rejection`
- `fonts:fontface:local_only_replaced_with_managed_src`
- `fonts:fontface:local_only_passthrough_not_proven`

## 16. Current contract gaps

Ниже фиксируется фактическое состояние repo, где поведение диагностируется, но не является строгим fail-fast:

- Missing `domPlatform` приводит к `fonts:nav_platform_missing`, попытке восстановить `awaitReady` из native `document.fonts.ready` и return.
- Missing/empty filtered configs приводит к `fonts:filtered_empty`, но ветка не становится hard failure в этой точке.
- Duplicate `uniq_triple` и duplicate `cssLoadQuery` в `rand_met.py` сейчас логируются как keep и не являются hard rejection.
- `context.js` при failure `applyMeasureTextHook` пишет `context:ctx2d:hook:measureText_failed` и возвращает native metrics.

Эти пункты не надо трактовать как желаемую норму. Это текущая реализация. Если требуется strict fail-fast по ним, нужна отдельная правка кода.
