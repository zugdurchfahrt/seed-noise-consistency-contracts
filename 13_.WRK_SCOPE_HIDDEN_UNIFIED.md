## 1. Lane для worker scope

Актуальный `/sunami` различает три конечных worker scope:

1. `DedicatedWorkerGlobalScope`
2. `SharedWorkerGlobalScope`
3. `ServiceWorkerGlobalScope`

`Dedicated` и `Shared` идут через общий WRK bootstrap/core lane в [wrk.js](C:/55555/switch/Evensteam/sunami/assets/scripts/workerscope/wrk.js) и consumer patch в [WORKER_PATCH_SRC.js](C:/55555/switch/Evensteam/sunami/assets/scripts/workerscope/WORKER_PATCH_SRC.js).

`ServiceWorker` идёт через отдельный lane в [sw_prelude.js](C:/55555/switch/Evensteam/sunami/assets/scripts/workerscope/sw_prelude.js). `service` не должен попадать в общий dedicated/shared bootstrap core.

`scopeKind` является скрытым runtime-контрактом, а не публичным маркером:

```js
C.state.__WRK__.runtime.workerScopeKind
C.state.__WRK__.runtime.expectedWorkerScopeKind
```

Допустимые значения:

```js
dedicated
shared
service
```

`type` worker script (`classic` / `module`) и `scopeKind` не являются одним и тем же.

## 5. Transport для Dedicated / Shared

Transport path для `Dedicated` / `Shared`:

```js
syncDedicated(worker)
syncShared(port)
EnvHub_init()
publishSnapshot(snap)
subscribe(fn)
BroadcastChannel('__ENV_SYNC__')
```

`DedicatedWorker` получает sync через `worker.postMessage({ __ENV_SYNC__: { envSnapshot } })`.

`SharedWorker` получает sync через `port.postMessage({ __ENV_SYNC__: { envSnapshot } })` и `connect` event path.

Broadcast используется как общий sync contour. Не нужно создавать отдельный ad-hoc transport для `language`, `languages`, `deviceMemory`, `hardwareConcurrency` или screen/env scalars.

## 6. Bootstrap для Dedicated / Shared

[wrk.js](C:/55555/switch/Evensteam/sunami/assets/scripts/workerscope/wrk.js) генерирует bootstrap-source через `mkWorkerBootstrapCore(...)`.

Bootstrap выполняет:

- валидирует `expectedWorkerScopeKind` относительно обнаруженного `workerScopeKind`;
- отклоняет `ServiceWorkerGlobalScope` из общего lane;
- материализует `FernwehContext.state.__WRK__`, `__NAV_TOTAL_SET__`, `__ENV_PROFILE__`, `__SCREEN__`, `__FONTS__`, `__CANVAS__`, `Core.__internal.prng`;
- применяет initial snapshot напрямую в локальный worker owner route `__WORKER_ENV_SNAPSHOT__`;
- при раннем sync до появления `runtime.consumeEnvSnapshot` синхронизирует worker owner route напрямую, без `runtime.pendingEnvSnapshots`;
- буферизует раннюю доставку `message` / `connect` и replay делает через event dispatch.

Bootstrap owner materialization остаётся realm-local и не является дополнительным долгоживущим публичным transport.

## 7. Consumer apply path

[WORKER_PATCH_SRC.js](C:/55555/switch/Evensteam/sunami/assets/scripts/workerscope/WORKER_PATCH_SRC.js) является финальным consumer patch для `Dedicated` / `Shared`.

Текущий порядок apply:

1. Найти hidden `C.state.__WRK__.runtime`.
2. Проверить `bootstrapActive`.
3. Найти `workerScopeKind`; отклонить `service`.
4. Прочитать bootstrap snapshot из `C.state.__NAV_TOTAL_SET__.__DATA_STORE_STATE__.__WORKER_ENV_SNAPSHOT__`.
5. Установить `runtime.consumeEnvSnapshot = applyWorkerSnapshot`.
6. Применить bootstrap snapshot.
7. Подписаться на `BroadcastChannel('__ENV_SYNC__')`.

`applyWorkerSnapshot` обновляет worker-local owner route:

```js
C.state.__NAV_TOTAL_SET__.__DATA_STORE_STATE__.__WORKER_ENV_SNAPSHOT__
```

и синхронизирует скрытых consumers уровня realm-local:

```js
C.state.__ENV_PROFILE__
C.state.__SCREEN__
C.state.__FONTS__.__STATE__
C.state.__FONTS__.__CONFIG__
```

Важно: consumer apply path не пишет в window realm owner-store. Он обновляет только worker-local copy `__WORKER_ENV_SNAPSHOT__`, после чего синхронизирует `__ENV_PROFILE__`, `__SCREEN__` и `__FONTS__` внутри того же worker realm.

## 9. `CDP_GLOBAL_SEED` и inline-delivery loop

Worker seed не является частью env snapshot и не должен перевозиться через `window.__GLOBAL_SEED`, `__ENV_SYNC__`, `postMessage` или `BroadcastChannel`. Для всех worker realms нормативное имя seed:

```js
CDP_GLOBAL_SEED
```

Зачем нужна отдельная inline/CDP-петля:

1. Worker realm стартует отдельно от window realm и не может автоматически наследовать hidden owner-state window scope.
2. PRNG-dependent code должен увидеть seed до выполнения `RNGsetModule(self)` и до downstream canvas/context/WebGL consumers.
3. Dedicated/Shared/ServiceWorker должны иметь одинаковый root seed для session determinism, но каждый realm обязан самостоятельно материализовать local `Core.__internal.prng`.
4. Seed должен быть проверяемым и descriptor-controlled: non-enumerable, non-public contract surface, mismatch по non-configurable value является failure, а не silent replacement.

Нормативная цепочка:

```py
main.py global_seed
-> cdp.enable_seed_inject(global_seed)
-> cdp_catapult.py CDP_GLOBAL_SEED
-> _build__seed_value(global_seed)
-> Object.defineProperty(globalThis, 'CDP_GLOBAL_SEED', ...)
-> prng_seed.js / RNGsetModule(self)
-> self.Core.__internal.prng
```

`_build__seed_value(...)` в [cdp_catapult.py](C:/55555/switch/Evensteam/sunami/tools/generators/cdp_catapult.py) является единственным генератором JS-prelude для materialization `CDP_GLOBAL_SEED`. Он:

- требует non-empty `global_seed`;
- проверяет существующий descriptor `CDP_GLOBAL_SEED`;
- при non-configurable existing value допускает только совпадающее значение;
- выставляет `CDP_GLOBAL_SEED` через `Object.defineProperty`;
- делает property `writable: false`, `configurable: true`, `enumerable: false`;
- при невозможности define допускает только технический assignment fallback внутри того же seed prelude, но не меняет имя seed.

Dedicated/Shared path:

```js
main.py build_page_bundle
-> inlinePrng = _build__seed_value(global_seed) + prng_seed.js
-> inlineReflect = set_reflect.js
-> wrk.js сохраняет inlinePrng / inlineReflect в C.state.__WRK__.runtime
-> mkWorkerBootstrapCore / mkModuleWorkerSource / mkClassicWorkerSource
-> worker-local CDP_GLOBAL_SEED
-> CoreWindowModule(self)
-> RNGsetModule(self)
-> WORKER_PATCH_SRC.js consumers
```

ServiceWorker path:

```py
main.py
-> cdp.enable_seed_inject(global_seed)
-> cdp_catapult.py autoAttach service_worker
-> Runtime.evaluate(_build__seed_value(...))
-> Runtime.evaluate(seed sanity)
-> Runtime.evaluate(sw_bootstrap_prelude)
-> sw_prelude.js validates CDP_GLOBAL_SEED
-> CoreWindowModule -> RNGsetModule -> CanvasPatchModule -> ContextPatchModule
```

`set_reflect.js` не является seed carrier. Он доставляется рядом с seeded PRNG inline chain, потому что worker realm одновременно нуждается в двух ранних local infrastructures: `CDP_GLOBAL_SEED` для PRNG determinism и realm-local `Function.prototype.toString` bridge для native-looking wrapper contract. Эти два слоя нельзя синхронизировать постфактум через snapshot: они должны быть построены до consumer patch execution.

Nested worker path обязан сохранить ту же норму: nested source берет seed из local `self.CDP_GLOBAL_SEED`, заново определяет `CDP_GLOBAL_SEED` внутри nested realm и только после этого запускает user worker source. Любой nested worker без seed является pipeline missing data.



Failure policy:

- missing `CDP_GLOBAL_SEED` до worker PRNG init является pipeline missing data;
- mismatch существующего non-configurable `CDP_GLOBAL_SEED` является fatal seed-routing failure;
- seed sanity в service-worker lane обязана сравнить фактический `CDP_GLOBAL_SEED` с ожидаемым значением;
- silent fallback на другой seed name запрещён.

## 10. Синхронизация формы `Function.prototype.toString` между scopes

`Function.prototype.toString` нельзя синхронизировать между Window, `DedicatedWorkerGlobalScope`, `SharedWorkerGlobalScope` и `ServiceWorkerGlobalScope` как один общий runtime-object. У каждого realm свой `Function.prototype`, свои native function objects, свои WeakMap/WeakSet owners и свои descriptor identities. Следовательно, автоматическая синхронизация `toString` state между scopes невозможна и не является целью pipeline.

Нормативная цель другая: построить одинаковую архитектурную форму в каждом scope.

```txt
Window realm:
  core_window.js -> Core.__internal.coreToStringState

Dedicated/Shared worker realm:
  set_reflect.js -> C.state.__WRK__.runtime.__CORE_TOSTRING_STATE__
  core_window.js -> Core.__internal.coreToStringState

ServiceWorker realm:
  set_reflect.js inside sw_bootstrap_prelude
  -> G.FernwehContext.state.__WRK__.runtime.__CORE_TOSTRING_STATE__
  -> CoreWindowModule service-local coreToStringState
```

`set_reflect.js` обязан работать realm-local:

- читать descriptor `Function.prototype.toString` текущего worker realm;
- восстановить/сохранить текущий native baseline текущего realm;
- создать local `toStringOverrideMap` и `toStringProxyTargetMap`;
- публиковать только marker/API state в `C.state.__WRK__.runtime.__CORE_TOSTRING_STATE__`;
- не экспортировать WeakMap/WeakSet поля как serializable state;
- не пытаться использовать window-native `Function.prototype.toString` object как worker-native baseline.

Синхронизация между scopes допускается только как structural parity:

- одинаковые owner routes;
- одинаковые public descriptor expectations;
- одинаковые wrapper APIs (`__registerToStringWrapper`, `__wrapNativeApply`, `__wrapNativeAccessor`, `__wrapNativeCtor`);
- одинаковая failure policy и diagnostics;
- одинаковый принцип: public `%Function.prototype.toString%` остаётся engine-native baseline текущего realm.

Запрещено:

- переносить `Function.prototype.toString` function object из Window в worker;
- переносить WeakMap/WeakSet bridge maps между scopes;
- считать `__CORE_TOSTRING_STATE__` window realm source-of-truth для worker realm;
- лечить worker toString через postMessage/env snapshot;
- допускать разную форму реализации для Dedicated, Shared и ServiceWorker.

ServiceWorker lane дополнительно проверяется через CDP sanity expression в [cdp_catapult.py](C:/55555/switch/Evensteam/sunami/tools/generators/cdp_catapult.py): проверяется наличие `__CORE_TOSTRING_STATE__`, отсутствие WeakMap fields в опубликованном marker-state, наличие wrapper APIs и корректность текущего `Function.prototype.toString` baseline. Это не cross-realm sync, а проверка local realm parity.

Если один из scopes не может построить ту же форму `Function.prototype.toString`, это contract violation. Правильная реакция - явный diagnostic/failure, а не silent native fallback и не попытка "дотянуть" state из другого realm.

## 11. Lane ServiceWorker

[sw_prelude.js](C:/55555/switch/Evensteam/sunami/assets/scripts/workerscope/sw_prelude.js) владеет service-worker runtime lane.

Он должен:

- требовать `ServiceWorkerGlobalScope`;
- валидировать `scopeKind === 'service'`;
- валидировать `lane === 'runtime'`, если `lane` передан;
- материализовать `C.state.__WRK__.bootstrap` и `C.state.__WRK__.runtime`;
- записывать service-маркеры:

```js
C.state.__WRK__.runtime.workerScopeKind = 'service'
C.state.__WRK__.runtime.expectedWorkerScopeKind = 'service'
C.state.__WRK__.runtime.serviceWorkerLane = 'runtime'
C.state.__WRK__.bootstrap.serviceWorkerLane = 'runtime'

```

`__SW_ENV__` — это service-worker bootstrap env. Это не расширенный transport envelope dedicated/shared.

Window-side registration marker для service worker может использовать:

```js
C.state.__WRK__.runtime.serviceWorkerLane = 'registration'
```

Этот marker является state registration-lane, а не доказательством service runtime.

## 13. Canvas export layer для ServiceWorker

ServiceWorker canvas delivery в актуальном `/sunami` ограничен только export-layer для `OffscreenCanvas.convertToBlob`.

Нормативная граница:

- `HTMLCanvasElement.toDataURL/toBlob` в service worker не добавляются, потому что такого DOM surface там нет;
- PNG/hash logic не копируется в `sw_prelude.js`;
- source of truth для PNG ancillary/export hook остаётся [canvas.js](C:/55555/switch/Evensteam/sunami/assets/scripts/window/patches/graphics/canvas.js);
- service-worker path использует только offscreen branch: `patchConvertToBlobInjectNoise`, `registerOffscreenConvertToBlobHook`, `applyOffscreenPatches`.

Generator path:

[cdp_catapult.py](C:/55555/switch/Evensteam/sunami/tools/generators/cdp_catapult.py) в `_build_sw_bootstrap_prelude(...)` собирает service-worker prelude и добавляет inline sources как lexical constants:

```js
__SW_INLINE_CORE_WINDOW__
__SW_INLINE_PRNG__
__SW_INLINE_CANVAS_PATCH__
__SW_INLINE_CONTEXT_PATCH__
```

Inline sources берутся из:

```js
core_window.js
prng_seed.js
canvas.js
context.js
```

Перед сборкой SW prelude generator сужает `canvas.js` / `context.js` до offscreen-only варианта:

- вырезает DOM `toDataURL` / `toBlob` ветки;
- удаляет `patchToDataURLInjectNoise`, `masterToDataURLHook`, `patchToBlobInjectNoise`;
- оставляет `patchConvertToBlobInjectNoise`;
- оставляет `OffscreenCanvas.getContext` / `OffscreenCanvas.convertToBlob` route;
- проверяет наличие `patchConvertToBlobInjectNoise`, `registerOffscreenConvertToBlobHook`, `applyOffscreenPatches`, `convertToBlob`;
- fail-fast запрещает остатки `HTMLCanvasElement`, `toDataURL`, `patchToBlobInjectNoise`.

Runtime path в [sw_prelude.js](C:/55555/switch/Evensteam/sunami/assets/scripts/workerscope/sw_prelude.js):

```js
__installServiceWorkerWebGLMirror(webgl);
__installServiceWorkerCanvasExportLayer();
```

Порядок важен: сначала ставится WebGL mirror для `OffscreenCanvas.getContext`, затем canvas export layer для `OffscreenCanvas.convertToBlob`. Это сохраняет WebGL parameter mirror и не подменяет его canvas export wrapper-ом.

`__installServiceWorkerCanvasExportLayer()` делает:

1. Проверяет наличие `OffscreenCanvas`.
2. Материализует service-worker local owner graph:

```js
G.FernwehContext
G.FernwehContext.state
G.FernwehContext.state.__WRK__.runtime
G.FernwehContext.state.__ENV_PROFILE__
G.FernwehContext.state.__SCREEN__
G.FernwehContext.state.__FONTS__.__STATE__
G.FernwehContext.state.__FONTS__.__CONFIG__
G.FernwehContext.state.__CANVAS__.__STATE__
G.Core.__internal.prng
```

3. Проверяет `CDP_GLOBAL_SEED`.
4. Выполняет inline module chain:

```js
CoreWindowModule -> RNGsetModule -> CanvasPatchModule -> ContextPatchModule
```

5. Валидирует `G.FernwehHooks.patchConvertToBlobInjectNoise`.
6. Валидирует `G.FernwehContext.registerOffscreenConvertToBlobHook`.
7. Валидирует `G.FernwehContext.applyOffscreenPatches`.
8. Регистрирует только:

```js
patchCtx.registerOffscreenConvertToBlobHook(hooks.patchConvertToBlobInjectNoise);
```

9. Вызывает:

```js
patchCtx.applyOffscreenPatches();
```

10. Пишет hidden markers:

```js
G.FernwehContext.state.__CANVAS__.__STATE__.__SW_CANVAS_EXPORT_LAYER_INSTALLED__ = true
G.FernwehContext.state.__WRK__.runtime.serviceWorkerCanvasExportLayerInstalled = true
```

Failure policy:

- отсутствие inline source, seed, hook, registrar или apply API является pipeline missing data и должно идти через `__fail(...)`;
- отсутствие `OffscreenCanvas` является browser structure absence и допускает diag-reported skip `sw_prelude:canvas_export_skipped`;
- cleanup inline export после `new Function('window', source ...)(G)` best-effort, но cleanup failure обязан идти через `__swDiag`;
- silent native fallback для pipeline missing data запрещён.

## 15. Контрольные критерии валидности WRK lane:

1. `C.state.__WRK__.bootstrap/runtime/hooks` существуют до запуска WRK consumers.
2. Dedicated/shared отклоняют service scope в общем bootstrap.
3. Service worker использует `sw_prelude.js` lane и записывает service runtime-маркеры.
4. Initial dedicated/shared snapshot приходит из `__WORKER_ENV_SNAPSHOT__`.
5. Later dedicated/shared sync использует `__ENV_SYNC__` и `runtime.consumeEnvSnapshot`.
6. Consumer apply path не переписывает canonical owner-store window realm.
7. `scopeKind` остаётся hidden runtime state.
8. Cleanup bootstrap `window.__*` ждёт готовности worker snapshot retention.
9. Ошибки являются явными throw или diag-reported skip; silent swallow остаётся нарушением контракта.
10. Service worker canvas export layer ограничен `OffscreenCanvas.convertToBlob` и не добавляет DOM canvas API.
11. Service worker canvas path переиспользует `canvas.js` / `context.js` через inline offscreen-only sources, а не копирует PNG/export логику в `sw_prelude.js`.
12. Service worker canvas export устанавливается после WebGL mirror и пишет `__SW_CANVAS_EXPORT_LAYER_INSTALLED__` / `serviceWorkerCanvasExportLayerInstalled`.
13. Worker seed transport использует только `CDP_GLOBAL_SEED`; `window.__GLOBAL_SEED` и env snapshot не являются worker seed routes.
14. `inlinePrng` и `inlineReflect` являются ранними prerequisites worker bootstrap: первый строит PRNG determinism, второй строит realm-local `Function.prototype.toString` bridge.
15. `Function.prototype.toString` между Window/Dedicated/Shared/ServiceWorker синхронизируется только через одинаковую архитектурную форму, но не через общий object/state transfer.
