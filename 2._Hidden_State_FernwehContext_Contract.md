# Hidden state-контракт `FernwehContext` и система хранения внутреннего состояния pipeline

## 1. Назначение документа

Документ задаёт единую контрактную методологию хранения внутреннего состояния pipeline и namespace-схему для связки `bootstrap_hide.js`, `set_log.js`, `core_window.js`, `prng_seed.js`, `probe.js`, `context.js`, worker-side частей и downstream-модулей.

`FernwehContext` рассматривается как часть hidden graph state pipeline: это не публичный API, не универсальный storage для всей служебки и не замена `Core.__internal`. Его роль — hidden root / hidden container bootstrap-уровня для module-state и hook-layer related state.

Цель документа — дать практическую карту: где живёт каждая категория состояния, кто её создаёт, кто владеет, кто только читает, где допустим owner-transfer, а где состояние не должно появляться вообще.

---


## 1.1. Граница документа

Документ не легализует compatibility mirrors как финальную норму.

Документ задаёт рабочий контур: по нему проверяется, где должен жить каждый owner-state, какой модуль за него отвечает и какие пути считаются ненормативными.

---

## 2. Главная идея hidden state

Hidden namespace — это принцип организаци owner-state, а не про криптографическую недоступность. Если нужна настоящая приватность, используются closure, `WeakMap` или private fields. Для pipeline-задачи основное требование другое: состояние должно иметь канонический owner-path, понятный lifecycle и наблюдаемый выход при ошибке.


В JavaScript `hidden` не означает “по-настоящему секретный”. В рамках pipeline `hidden state` означает архитектурно скрытое состояние:

* не public API;
* не должно светиться в обычной enumeration;
* не должно быть случайной точкой зависимости;
* не должно восприниматься как внешний браузерный контракт;
* не должно размазываться по `window` как по общему хранилищу.

---

## 3. Базовая карта понятий

Термины `hidden container`, `hidden state`, `hidden graph state`, `hidden root`, `owner-transfer`, `hide-pass`, `producer`, `owner`, `consumer` — это проектные термины уровня pipeline, а не официальный словарь ECMAScript.

Базовая структура:

```js
realm / public target
  -> hidden root
    -> hidden container
      -> state container
        -> slot
          -> hidden state
```

Базовые роли:

```js
producer -> owner -> consumer -> owner-transfer
```

Базовые механики:

```js
hidden-first / hide-pass / string slot / Symbol / WeakMap / closure / private field
```

Для текущего pipeline это раскладывается так:

* `window` — realm и обязательный public/runtime target;
* `window.FernwehContext` / `C` — hidden root и hidden container bootstrap-уровня;
* `C.state` — registry module-state и marker-slots;
* `C.__logger` — logger/degrade infra;
* `C.__patchState` — hook/apply lifecycle `context.js`;
* `window.Core` — public entrypoint core-слоя;
* `Core.__internal` — hidden core-space;
* `Core.__internal.prng` — canonical owner seed/PRNG;
* `Core.__internal.guards` — canonical owner guard lifecycle;
* `Core.__internal.coreToStringState` — internal bridge-state для callable wrappers;
* `C.state.<module-slot>` — module owner-space;
* nested slots — sub-state внутри module owner-space;
* snapshots, flags, values, runtime-derived data — собственно hidden state.

---

## 4. `hidden root`

`Hidden root` — верхняя входная точка внутренней подсистемы. Это корень, от которого начинается внутренняя структура.

Практический смысл root: если root не определён, состояние расползается по `window`, `Core`, случайным helper-ключам и legacy mirrors. После этого невозможно надёжно понять, где canonical owner.

Root должен создаваться hidden-first: через `Object.defineProperty(..., enumerable:false)`, без промежуточного visible assignment.

В pipeline используются основные hidden roots:

* `window.FernwehContext`;
* `window.Core` как public entrypoint core-слоя;
* `Core.__internal` как hidden core-space.

---

## 5. `hidden container`

`Hidden container` — контейнер-организатор. Он предназначен для логического разведения зон ответственности.

Главное правило: container не должен превращаться в общий ящик “для всего”.

Не всякий container является state container. Container может быть namespace-контейнером, logger-контейнером, hook-контейнером, bootstrap-status контейнером или core-infra контейнером.

`FernwehContext` является hidden container bootstrap-уровня. Внутри него живут отдельные role-separated containers:

* `C.state`;
* `C.__logger`;
* `C.__patchState`;
* `C.__hookModeStore`;
* `C.__bootstrapTransitStatus__`;
* bootstrap helper-функции cleanup/sanitize уровня `bootstrap_hide.js`.
---

## 6. `state container`

`State container` — контейнер именно для состояния, которое живёт во времени, читается разными модулями, меняется и участвует в lifecycle.

В текущем pipeline state containers:

* `C.state` — module-state registry;
* `C.__patchState` — hook/apply lifecycle `context.js`;
* `Core.__internal.prng` — owner-space для seed/PRNG;
* `Core.__internal.guards` — owner-space для guard lifecycle;
* `Core.__internal.targets`, `Core.__internal.knownWrapped`, `Core.__internal.__patchGuardSeq`, `Core.__internal.coreToStringState` — core-only runtime registries.

State container должен быть узкоролевым:

* `C.state` не принимает logger/core state;
* `C.__logger` не принимает module-state;
* `C.__patchState` не является registry downstream-модулей;
* `Core.__internal` не принимает module-state;
* `Core.__internal.prng` не дублируется в `C.state`;
* guard lifecycle не хранится в `C.state` и не хранится на `window[key]`.

---

## 7. `hidden slot`

`Hidden slot` — отдельная именованная ячейка внутри state container. Это минимальная unit ownership.

У slot должен быть понятный владелец:

* какой модуль его создаёт;
* какой модуль имеет право менять форму;
* кто отвечает за инварианты;
* кто контролирует rollback состояние при ошибке;
* какие consumers могут читать slot.

Текущие module slots внутри `C.state`:

* `C.state.__FONTS__`;
* `C.state.__CANVAS__`;
* `C.state.__SCREEN__`;
* `C.state.__NAV_TOTAL_SET__`;
* `C.state.__HIDE_WEBDRIVER__`;
* `C.state.__WRK__`;
* `C.state.__GEO_STATE__`;
* `C.state.__LANG_STATE__`;
* `C.state.__ENV_PROFILE__`;
* `C.state.__WEBGL_STATE__`;
* `C.state.__WEBGPU_WL_STATE__`.

Nested slots / sub-state:

* `C.state.__FONTS__.__STATE__`;
* `C.state.__FONTS__.__CONFIG__`;
* `C.state.__CANVAS__.__STATE__`;
* `C.state.__NAV_TOTAL_SET__.__DATA_STORE_STATE__`;
* `C.state.__NAV_TOTAL_SET__.__SCALAR_STATE__`;
* `C.state.__NAV_TOTAL_SET__.__OBJECT_STATE__`;
* `C.state.__WRK__.bootstrap`;
* `C.state.__WRK__.bootstrap.__SW_ENV__`;
* `C.state.__WRK__.runtime`;
* `C.state.__WRK__.runtime.__CORE_TOSTRING_STATE__`;
* `C.state.__WRK__.hooks`;
* `C.state.__ENV_PROFILE__.__PLATFORM__`;
* `C.state.__ENV_PROFILE__.__SCREEN__`.

Старые или условные имена вроде `C.state.__CANVAS_STATE__` не являются текущей актуальной схемой, если код уже использует `C.state.__CANVAS__.__STATE__`.

---

## 8. `hidden state`

`Hidden state` — это не место, а данные внутри slot.

Пример:

* `C.state.__NAV_TOTAL_SET__` — module slot;
* `C.state.__NAV_TOTAL_SET__.__DATA_STORE_STATE__` — nested slot;
* конкретный worker snapshot внутри data-store — hidden state.

Для canvas:

* `C.state.__CANVAS__` — module slot;
* `C.state.__CANVAS__.__STATE__` — nested state;
* `domReady`, `offscreenReady`, `domCanvas`, `domCanvasHost`, `offscreenCanvas`, `defaultCtx2dFont` — hidden state fields.

Для fonts:

* `C.state.__FONTS__` — module slot;
* `C.state.__FONTS__.__STATE__` — readiness/family snapshot;
* `C.state.__FONTS__.__CONFIG__` — configs transit/config state.

---

## 9. `hidden graph state`

`Hidden graph state` — вся внутренняя сеть связанных объектов, а не один объект и не одно дерево.

В него входят:

* roots;
* containers;
* state containers;
* slots;
* nested slots;
* bridge-ссылки;
* transitional aliases;
* owner-path;
* consumer-path;
* cleanup/retention gates;
* core registries;
* worker snapshots.

Почему graph, а не просто tree: разные пути могут временно ссылаться на один underlying object, особенно во время owner-transfer и compatibility stage. Поэтому документ должен фиксировать не только “где лежит объект”, но и какой путь является canonical owner, а какой допустим только как transitional read-path.

---

## 10. Producer / owner / consumer

### Producer

Producer производит данные и кладёт их в owner-space. Producer не обязательно владеет root namespace.
Producer обязан писать в одно каноническое место, а не в несколько зеркал одновременно.

Примеры:

* `bootstrap_hide.js` читает bootstrap inputs с `window.__*` и переносит их в owner slots;
* `prng_seed.js` наполняет `Core.__internal.prng`, но не владеет root namespace;
* worker-side код может сформировать snapshot, но не становится owner-space для window-state.



### Owner

Owner имеет право создать сущность, определить её форму, менять её и отвечать за инварианты.

Текущий ownership:

* `bootstrap_hide.js` — owner bootstrap hidden-bus и создания hidden namespaces: `window.FernwehContext`, `C.state`, `C.__logger`, `window.Core`, `Core.__internal`, `Core.__internal.prng`, bootstrap transfer, cleanup/retention gates;
* `set_log.js` — owner logger/degrade infra внутри `C.__logger`;
* `core_window.js` — owner core infra внутри `Core.__internal`, `Core.applyTargets`, wrapper factories, guard registry, target registry, toString bridge-state;
* `context.js` — owner hook-layer и `C.__patchState`, а также context-owned helper owner-routes на `C` (`__KEEP_NATIVE_WL__`, `__GATEWAY_METHODS__`, `__keptNativeRefs__`, `__issuedContextRegistry__`, `registerAllHooks`);
* `prng_seed.js` — producer PRNG-state, но canonical owner-space остаётся `Core.__internal.prng`;
* `probe.js` — consumer/observer logger-space, не creator и не отдельный storage-owner;
* downstream-модули — owners только своих module slots;
* `WEBGL_DICKts.js` — producer словаря для `C.state.__WEBGL_STATE__`, без отдельного policy-owner identity;
* `webgl.js` / `WebglPatchModule` — owner WebGL domain policy и apply/rollback интеграции словаря в `C.state.__WEBGL_STATE__`;
* `WebgpuWL.js` — owner `C.state.__WEBGPU_WL_STATE__`;
* worker-side (`wrk.js`, `set_reflect.js`, `worker_bootstrap.js`, `WORKER_PATCH_SRC.js`) — owners realm-local bootstrap/runtime owner-routes (`C.state.__WRK__.bootstrap`, `C.state.__WRK__.runtime`, `C.state.__WRK__.hooks`, `C.state.__WRK__.runtime.__CORE_TOSTRING_STATE__`), но не owners window-truth state;
* `sw_prelude.js` — owner service-worker realm-local owner-routes `C.state.__WRK__.bootstrap.__SW_ENV__` и lane markers внутри `C.state.__WRK__.runtime`, но не owner window-truth state.

### Consumer

Consumer читает готовое состояние и использует его. Consumer не должен пересоздавать owner-space.

Запрещённый паттерн для downstream:

```js
const C = window.FernwehContext || (window.FernwehContext = {});
```

Consumer должен либо получить существующий owner-path, либо выполнить controlled skip / fail-fast через диагностический канал, если owner-space отсутствует.

## 11. Owner-transfer

`Owner-transfer` — контролируемый перенос канонического владения.

Это не “скопировать ещё одно зеркало”, а сменить точку истины:

1. Создать новый canonical slot.
2. Наполнить его корректным state.
3. Перевести consumers на новый owner-path.
4. Удалить или санитизировать старый transit path.

Если старый path остаётся как полуканоническое состояние, появляется “призрачное двойное состояние”: вроде owner уже новый, но legacy path всё ещё используется как truth.

В текущем pipeline owner-transfer применяется к bootstrap inputs:

* geo: `window.__LATITUDE__`, `window.__LONGITUDE__`, `window.__TIMEZONE__`, `window.__OFFSET_MINUTES__` -> `C.state.__GEO_STATE__`;
* language: `window.__primaryLanguage`, `window.__normalizedLanguages` -> `C.state.__LANG_STATE__`;
* platform: `window.__NAV_PLATFORM__`, `window.__UA_PLATFORM__`, `window.__UA_PLATFORM_VERSION` -> `C.state.__ENV_PROFILE__.__PLATFORM__`;
* env/profile/client hints/user-agent/vendor/device labels/early scalar values (`dpr`, `colorDepth`)/etc. -> `C.state.__ENV_PROFILE__`;
* screen-domain metrics -> `C.state.__ENV_PROFILE__.__SCREEN__`;
* PRNG seed/bootstrap input -> `Core.__internal.prng` через PRNG producer.

Legacy `window.__*` допускаются только как bootstrap-input или transitional compatibility-read до закрытия migration. После owner-transfer consumer-path должен идти через owner-space.

---

## 12. Hide-pass и hidden-first

`Hide-pass` — когда объект сначала создаётся видимым способом, а потом его пытаются спрятать:

```js
window.X = {};
Object.defineProperty(window, 'X', { enumerable: false, ... });
```

Для owner namespaces это не норма. Hidden namespace должен рождаться hidden-first.

Hidden-first применяется к:

* `window.FernwehContext`;
* `C.state`;
* `C.__logger`;
* `C.__patchState`;
* `C.__hookModeStore`;
* `C.__bootstrapTransitStatus__`;
* `window.Core`;
* `Core.__internal`;
* `Core.__internal.prng`;
* module slots внутри `C.state`;
* nested slots внутри module slots.

Если descriptor уже существует и non-configurable, код не должен ломать его насильно. Это contract problem / cleanup skip / fail-fast по роли конкретного шага.

## 14. `FernwehContext` как bootstrap hidden container

`FernwehContext` выполняет роль bootstrap hidden root / hidden container для module-state и hook-layer related state.
`FernwehContext` допустим как inspection namespace для внутренней диагностики, но его наличие не должно превращаться во внешний API-контракт.

Он не является:

* филиалом `Core`;
* owner-space для guard lifecycle;
* owner-space PRNG;
* logger buffer storage напрямую;
* public browser API;
* универсальным storage для всех helper-объектов;
* доказательством корректности внешнего browser contract.

---

## 15. `C.state` как module-state registry

`C.state` содержит только module-specific stateful slots и marker-slots.

Допустимо:

* slots downstream-модулей;
* nested sub-state конкретного модуля;
* bootstrap-transferred env/profile/lang/geo/screen state;
* worker runtime/bootstrap/hooks state как realm-local owner-routes для worker/service-worker lanes;
* `C.state.__WEBGL_STATE__` как module-state owner-route для WebGL dictionary/storage;
* `C.state.__WEBGPU_WL_STATE__` как module-state owner-route для WebGPU whitelist store;
* marker-slots already-initialized / already-applied, если они принадлежат конкретному module-state path.

Недопустимо:

* logger state;
* core state;
* PRNG canonical owner;
* guard lifecycle;
* global target registry;
* window canonical toString bridge-state (`Core.__internal.coreToStringState`);
* произвольные compatibility mirrors;
* helper-функции без module ownership.

---

## 16. Navigator module-state

Canonical owner-route для navigator-path:

```js
C.state.__NAV_TOTAL_SET__
  __DATA_STORE_STATE__
  __SCALAR_STATE__
  __OBJECT_STATE__
```

Допустимые navigator module slots:

* `C.state.__NAV_TOTAL_SET__`;
* `C.state.__NAV_TOTAL_SET__.__DATA_STORE_STATE__`;
* `C.state.__NAV_TOTAL_SET__.__SCALAR_STATE__`;
* `C.state.__NAV_TOTAL_SET__.__OBJECT_STATE__`;
* worker/env snapshot внутри data-store, если он реально создан как nested state этого модуля.

`C.state.__HIDE_WEBDRIVER__` — отдельный module slot `hide_webdriver.js`. Он не является частью `__NAV_TOTAL_SET__`, и `webdriver` не закрепляется за `nav_total_set.js` как owner-state.

Navigator consumers должны идти owner-first: сначала `C.state.__NAV_TOTAL_SET__...`, а legacy `window.__*` допускается только как transitional compatibility-read на стадии миграции.

---

## 17. Canvas module-state

Текущая актуальная схема canvas-state:

```js
C.state.__CANVAS__.__STATE__
    domReady
    offscreenReady
    domCanvas
    domCanvasHost
    offscreenCanvas
    defaultCtx2dFont
    willReadFrequently
```

`defaultCtx2dFont` относится к canvas owner-state и должен быть получен на bootstrap/runtime этапе без хардкода как основной источник. Если получить значение невозможно, это controlled failure path: diag + fail-fast или controlled skip по роли шага. Хардкод fallback допустим только как явно диагностированный аварийный outcome, а не как молчаливая норма.

`window.canvas`, `window.div`, `window.offscreenCanvas` не являются нормальным owner-path. Внутренние handles должны жить внутри owner-space `C.state.__CANVAS__.__STATE__` или внутри соответствующего module-owned hidden container, если конкретный runtime path требует отдельной поверхности.

---

## 18. Fonts module-state

Текущая актуальная схема fonts-state:

```js
C.state.__FONTS__
  __STATE__
    ready
    error
    awaitReady
    awaitReadyStatus
    awaitReadyResolve
    awaitReadyReject
    familySnapshot
      allowedFamilies
      runtimeFamilies
      platformDom
      versionToken
  __CONFIG__
    configs
```

`__STATE__` отвечает за readiness/lifecycle/snapshot.

`__CONFIG__` отвечает за configs transit/config state.

Fonts state не должен жить в `C.__FONTS_STATE__` как финальном owner-slot и не должен использовать `window.__*` как постоянный source of truth после transfer.

## 19. Screen / env / geo / language state

### Screen

```js
C.state.__SCREEN__
  runtime/module state only
```

Screen-domain metrics живут в `C.state.__ENV_PROFILE__.__SCREEN__`; `C.state.__SCREEN__` является отдельным module-state контейнером coordination/runtime уровня `screen.js`, но не canonical source для profile values.

Lifecycle exception: `dpr` и `colorDepth` также фиксируются как ранние scalars в `C.state.__ENV_PROFILE__`, чтобы `nav_total_set` не зависел от готовности `ScreenPatchModule`.

### Geo

```js
C.state.__GEO_STATE__
  latitude
  longitude
  timezone
  offsetMinutes
```

### Language

```js
C.state.__LANG_STATE__
  primaryLanguage
  normalizedLanguages
```

`normalizedLanguages` после transfer должен быть консистентен с `primaryLanguage`; первый элемент должен соответствовать primary language.

### Env profile

```js
C.state.__ENV_PROFILE__

  vendor
  mem

  colorDepth

  webglVendor
```

`C.state.__ENV_PROFILE__.__PLATFORM__` — canonical owner platform transfer-state.

### WebGL dictionary/storage state

```text
C.state.__WEBGL_STATE__
  paramWhitelist
  extensionsWhitelist
```

`C.state.__WEBGL_STATE__` — canonical WebGL module-state owner-route. `bootstrap_hide.js` создаёт route hidden-first; `WEBGL_DICKts.js` является producer словаря; `webgl.js` / `WebglPatchModule` применяет словарь, отвечает за WebGL domain policy, rollback и обязательный diag. `context.js` является runtime consumer через issued WebGL hook path.

### WebGPU whitelist state

```text
C.state.__WEBGPU_WL_STATE__
  store
    featuresWhitelist
    limitsWhitelist
```

`C.state.__WEBGPU_WL_STATE__` — canonical module-state owner-route для whitelist store, который подготавливает `WebgpuWL.js` и читает `webgpu.js`.

## 20. Worker state

Текущая worker namespace-схема:

```text
C.state.__WRK__
  bootstrap
    __SW_ENV__
  runtime
    __CORE_TOSTRING_STATE__
  hooks
```

Worker/service-worker pieces являются realm-local owners для своих `bootstrap/runtime/hooks` owner-routes, но остаются consumers only относительно `window` truth state. Они не становятся canonical owner для `window` realm state (`C.state.__ENV_PROFILE__`, `C.state.__GEO_STATE__`, `C.state.__NAV_TOTAL_SET__...`).

Worker snapshot / retention readiness может использоваться как gate для cleanup bootstrap inputs. Если worker snapshot ещё не готов, cleanup должен быть deferred/skipped с диагностикой, а не выполнен вслепую.

## 21. Logger / degrade infra

Logger/degrade infra живёт внутри:

```text
C.__logger
  __DEGRADE__
  STORE
  FALLBACK_BUF
```

`set_log.js` — owner logger/degrade infra.

Модули должны вызывать единый diag-channel через module-local adapter:

```js
const __D = C && C.__logger && typeof C.__logger.__DEGRADE__ === 'function'
  ? C.__logger.__DEGRADE__
  : null;
const __diag = (__D && typeof __D.diag === 'function') ? __D.diag.bind(__D) : null;
```

Правила:

* `.diag` вызывается с корректным receiver через `.bind(__D)`;
* adapter never-throw;
* fallback — callable `__DEGRADE__(code, err, extra)`;
* если канала нет — safe-noop, без `console.*` как отдельного канала;
* `catch` не должен быть silent-swallow;
* контролируемый выход должен быть наблюдаем до выхода.

Logger buffer/state не должен храниться в `C.state`.

## 24. Guard lifecycle

Guard lifecycle не принадлежит `FernwehContext`.

Canonical owner:

```text
Core.__internal.guards
Core.__internal.__patchGuardSeq
Core.guardFlag(...)
Core.releaseGuardFlag(...)
```

Правила:

* `window[key]` не используется как guard storage;
* guard storage не уходит в `C.state`;
* guard lifecycle не смешивается с module-state registry;
* успешный apply означает, что guard не снимается;
* release допустим только после rollback-ok;
* guard read/write/release failures должны идти через diag.

## 25. Hook-layer и `C.__patchState`

`context.js` — owner hook-layer и `C.__patchState`.

Текущая базовая форма:

```text
C.__patchState
  canvas
  offscreen
  webgl
  hooksRegistered
```

`C.__patchState` не является module-state registry. Он не должен принимать slots downstream-модулей и не должен смешиваться с `C.state`.

`registerAllHooks` должен жить только на `FernwehContext`. `window.registerAllHooks` запрещён.

`FernwehHooks` и `webglHooks` — export surfaces функций. Их object identity нельзя заменять целиком, потому что consumers могут держать reference. Допустимая операция — обеспечить существующий container и добавлять/обновлять properties на той же identity.

## 26. Bootstrap cleanup / retention gates

`bootstrap_hide.js` создаёт cleanup/status layer:

```text
C.__bootstrapTransitStatus__
  geo
  lang
  platform
  retention
    workerEnvSnapshotReady
    workerEnvSnapshotStage
    cleanup
      requested
      completed
      deferred
      lastTrigger
      reason
```

Bootstrap cleanup должен удалять transit/public `window.__*` только после того, как соответствующий owner-state готов.

Gates:

* geo keys удаляются только если `C.state.__GEO_STATE__` owner-ready;
* language keys удаляются только если `C.state.__LANG_STATE__` owner-ready;
* platform keys удаляются только если `C.state.__ENV_PROFILE__.__PLATFORM__` owner-ready;
* env/client-hints/userAgent/vendor/DPR/cpu/memory keys удаляются только если worker snapshot retention ready;
* non-configurable transit key не ломается, а даёт cleanup skip diag;
* delete failure даёт cleanup delete failed diag.

Cleanup не должен превращаться в silent best-effort.

## 27. Атомарность и наблюдаемость

При ошибке partial state недопустим.

Допустимые исходы:

* apply целиком;
* atomic skip;
* rollback descriptor/state;
* fail-fast для обязательного шага.

Любой controlled exit должен быть наблюдаем через `__DEGRADE__.diag` / fallback callable `__DEGRADE__`.

Любой `catch` должен:

1. записать событие через единый diag-channel;
2. выполнить skip / rollback / fail-fast по policy;
3. не оставлять partial state;
4. не подменять browser-native exception служебной ошибкой в публичном API.

---

## 28. Что snapshot и ручные инспекторы должны читать

Нормативный inspection-path:

* `FernwehContext` exists;
* `FernwehContext.state`;
* `FernwehContext.state.<module-slot>`;
* `FernwehContext.state.<module-slot>.<nested-slot>`;
* `FernwehContext.__logger`;
* `FernwehContext.__patchState`;
* `FernwehContext.__patchState.hooksRegistered`;
* `FernwehContext.__bootstrapTransitStatus__`;
* `Core.__internal`;
* `Core.__internal.prng`;
* `Core.__internal.guards`;
* `Core.__internal.coreToStringState`.

Snapshot должен читать owner/container/slot-path, а не случайные зеркала на `window`.

## 29. Что snapshot не должен считать нормой

Ненормативно как финальное состояние:

* `window.__PATCH_*` как постоянный owner-state;
* logger globals как главный source of truth;
* `FernwehContext.gate` и ручные gate-эвристики как owner-path;
* `set_log.FernwehContext.__SET_LOG_STATE__`;
* `C.state.__PRNG_STATE__`;
* `C.__PRNG_STATE__`;
* `window.__GLOBAL_SEED` как consumer-path после PRNG init;
* direct PRNG mirrors на `window`;
* `C.__GEO_STATE__`, `C.__LANG_STATE__`, `C.__FONTS_STATE__` как финальные owner-slots;
* `window.canvas`, `window.div`, `window.offscreenCanvas` как финальный canvas owner-path;
* downstream recreation `window.FernwehContext = {}` или `|| (window.FernwehContext = {})`.

## 30. Практический порядок создания структуры

### Шаг 1. Создать root hidden-first

```js
function defineHidden(obj, key, value, descriptor) {
  Object.defineProperty(obj, key, Object.assign({
    value,
    writable: true,
    configurable: true,
    enumerable: false
  }, descriptor || {}));
  return value;
}
```

Root создаёт только bootstrap-owner:

```js
const C = defineHidden(window, 'FernwehContext', Object.create(null));
```

Downstream не пересоздаёт root.

### Шаг 2. Создать role-separated containers

```js
defineHidden(C, 'state', Object.create(null));
defineHidden(C, '__logger', Object.create(null));
defineHidden(C, '__patchState', Object.create(null));
```

### Шаг 3. Создать module slot

```js
defineHidden(C.state, '__NAV_TOTAL_SET__', Object.create(null));
```

### Шаг 4. Создать nested slots

```js
defineHidden(C.state.__NAV_TOTAL_SET__, '__DATA_STORE_STATE__', Object.create(null));
defineHidden(C.state.__NAV_TOTAL_SET__, '__SCALAR_STATE__', Object.create(null));
defineHidden(C.state.__NAV_TOTAL_SET__, '__OBJECT_STATE__', Object.create(null));
```

### Шаг 5. Модуль работает только со своим owner-space

Модуль не лезет в:

* чужие module slots;
* `C.__logger`, если он не logger-owner;
* `Core.__internal`, если он не core-owner;
* `Core.__internal.prng`, если он не PRNG producer/consumer по контракту;
* `window.__*`, если owner-transfer уже завершён.

## 31. String keys / Symbol / WeakMap / closure

Для `FernwehContext` string slot keys практичнее, потому что:

* нужна читаемая диагностика;
* нужен ручной inspection;
* нужен стабильный contract wording;
* module slots должны быть видимы в controlled internal snapshot.

`Symbol` полезен для снижения коллизий, но не даёт абсолютной приватности.

`WeakMap` и closure применяются там, где нужно держать настоящее private/internal state без namespace exposure. В Core это особенно важно для wrapper/target registries и callable bridge paths.

## 32. Частые ошибки

### Ошибка 1. Считать hidden = private

Hidden означает “не public API / не owner-path для внешнего кода / не enumerable surface”, но не абсолютную недоступность.

### Ошибка 2. Смешивать container и state

`FernwehContext` не равен `C.state`.

`Core.__internal` не равен `Core.__internal.prng`.

`C.__logger` не равен `C.state`.

### Ошибка 3. Давать consumer-у создавать owner-space

Consumer читает. Bootstrap/core/module-owner создаёт.

### Ошибка 4. Делать один общий storage “на всё”

Это ломает role separation и делает невозможным аудит ownership.

### Ошибка 5. Держать compatibility mirrors как финальную норму

Transitional mirror допустим только как этап owner-transfer.

### Ошибка 6. Делать hide-pass нормой

Owner namespace должен рождаться hidden-first.

### Ошибка 7. Молчаливо проглатывать неполный transfer

Если owner-state не собран, это должно быть отражено в status/diag и вести к skip/defer/fail-fast, а не к silent fallback.

## 33. Финально допустимое состояние

Финально допустимое состояние:

1. `bootstrap_hide.js` создаёт `window.FernwehContext`, `C.state`, `C.__logger`, `window.Core`, `Core.__internal`, `Core.__internal.prng` hidden-first.
2. `C.state` остаётся чистым module-state registry.
3. `C.__logger` содержит logger/degrade infra.
4. `C.__patchState` содержит только hook/apply lifecycle `context.js`.
5. `Core.__internal` содержит только core infra.
6. `Core.__internal.prng` является canonical owner PRNG.
7. `Core.__internal.guards` является canonical owner guard lifecycle.
8. Downstream-модули создают и меняют только свои module slots.
9. `C.state.__WEBGL_STATE__` является WebGL dictionary/storage route, а не отдельным policy-субъектом.
10. Worker/service-worker pieces являются realm-local owners своих `bootstrap/runtime/hooks` путей, но consumers only относительно `window` truth state.
11. Legacy `window.__*` используются только как bootstrap/transitional inputs и удаляются/санитизируются после owner readiness.
12. `window` остаётся public/runtime realm target, но не canonical owner-state, не internal compatibility transit и не operational residue после owner-transfer.
13. Любая ошибка owner/setup/apply/cleanup наблюдаема через diag и не оставляет partial state.

## 34. Короткая методичка применения

1. Сначала определить root: `FernwehContext` или `Core.__internal`.
2. Развести role containers: `C.state`, `C.__logger`, `C.__patchState`, `Core.__internal.prng`, `Core.__internal.guards`.
3. Для каждого модуля выделить свой slot.
4. Внутри slot создать nested slots, если нужны разные sub-state.
5. Назначить owner: кто создаёт, меняет и rollback-ит.
6. Назначить producer: кто наполняет canonical slot.
7. Назначить consumers: кто только читает.
8. При миграции делать owner-transfer, а не вечные зеркала.
9. Создавать hidden-first, не через hide-pass.
10. Не допускать partial state: apply / skip / rollback / fail-fast.
11. Любой controlled exit фиксировать через diag.
12. Проверять каждый модуль против ownership, role separation, atomicity и observed-exit contract.

## 35. Самая короткая шпаргалка по терминам

**Hidden root** — корень внутренней подсистемы.

**Hidden container** — организационный контейнер.

**State container** — контейнер именно для состояния.

**Hidden slot** — именованная ячейка модуля внутри state container.

**Nested slot** — подслот внутри module slot.

**Hidden state** — данные внутри slot.

**Hidden graph state** — вся сеть roots / containers / slots / bridges / owner-path / consumer-path.

**Producer** — производит и записывает данные.

**Owner** — владеет формой и инвариантами.

**Consumer** — читает готовое состояние.

**Owner-transfer** — перенос канонического owner-path.

**Hide-pass** — сначала visible assignment, потом попытка спрятать; для owner namespaces как норма запрещён.
