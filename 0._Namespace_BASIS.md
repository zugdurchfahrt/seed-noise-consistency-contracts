# Basis-Контракт для namespace pipeline

## Назначение и область действия

Настоящий контракт задаёт базовую модель namespace pipeline для актуального `/sunami`: кто владеет bootstrap-инфраструктурой, где живёт hidden state, как downstream-модули получают свои owner-routes, где допустимы runtime-shells и какие пути считаются legacy/contract violation.

Контракт описывает не отдельный файл и не один patch-модуль, а общий operational graph:

```txt
Core
  -> patch/descriptor/toString/guard/PRNG infrastructure

FernwehContext
  -> hidden container, service-layer, lifecycle, hook registration

FernwehContext.state
  -> canonical root для module-state
```

Текущая архитектура не является серверным HTML-контекстом. Это browser runtime pipeline: Python/Selenium/CDP подготавливает profile/bootstrap values, а JavaScript-модули материализуют скрытые owner-routes в window, worker и service-worker realms. Поэтому namespace contract должен регулировать и window-bootstrap, и workerscope mirror/local-state, и CDP/inline delivery, и downstream patch consumers.

Главная норма: модули не создают собственные root-контейнеры. Они либо используют `Core`, либо `FernwehContext`, либо свой module-state под `FernwehContext.state.__MODULE__`.

## Канонические владельцы

### `Core`

`Core` является владельцем bootstrap-механики и patch-infrastructure. Он не является module-state контейнером и не должен превращаться в dump-area для профилей.

Канонические обязанности `Core`:

- guard lifecycle: `guardFlag`, `releaseGuardFlag`;
- descriptor/policy pipeline: `resolveDescriptor`, `preflightTarget`, `applyTargets`, rollback/registration helpers;
- wrapper infrastructure: `__registerToStringWrapper`, `__wrapNativeApply`, `__wrapNativeAccessor`, `__wrapNativeCtor`, `__safeDefine`;
- toString owner-space: `Core.__internal.coreToStringState`;
- PRNG owner-space: `Core.__internal.prng`;
- служебные registries: `__internal.targets`, `__internal.guards`, `__internal.knownWrapped`, `__internal.__patchGuardSeq`.

`Core.__internal` является hidden bootstrap-internal owner-space. Downstream-код может требовать его наличие, но не должен публиковать туда произвольное module-state. Если конкретному модулю нужно состояние, оно должно идти в `FernwehContext.state.__MODULE__`.

### `FernwehContext`

`FernwehContext` является каноническим hidden container текущего realm. Он владеет service-layer и координацией между модулями:

- `__logger`;
- `__READY__`;
- `__patchState`;
- `__hookModeStore`;
- `__KEEP_NATIVE_WL__`;
- `__GATEWAY_METHODS__`;
- `__keptNativeRefs__`;
- `__issuedContextRegistry__`;
- hook arrays и register-functions;
- `registerAllHooks`;
- `applyCanvasElementPatches`;
- `applyOffscreenPatches`;
- `applyWebGLContextPatches`;
- `__prngRuntime__` как runtime shell, но не PRNG state owner;
- `__bootstrapTransitStatus__`;
- `__runBootstrapEnvCleanup__`;
- `__workerEnvSnapshotReady__`.

`FernwehContext` может иметь service-slots, но не должен хранить состояние конкретных patches напрямую, если для этого есть `FernwehContext.state.__MODULE__`.

### `FernwehContext.state`

`FernwehContext.state` является единственным каноническим root для долгоживущего module-state:

```txt
FernwehContext.state.__MODULE__
```

Если module-state нужен downstream-модулю, он должен находиться только там.
Параллельные roots не являются допустимой нормой.

## Актуальная карта module-state

Ниже перечислена рабочая карта module-state, подтверждённая текущим `/sunami`.

### Profile / environment / language / screen

```txt
FernwehContext.state.__ENV_PROFILE__
FernwehContext.state.__ENV_PROFILE__.__PLATFORM__
FernwehContext.state.__LANG_STATE__
FernwehContext.state.__GEO_STATE__
FernwehContext.state.__SCREEN__
```

`__ENV_PROFILE__` хранит профильные/environment values и platform route. `__PLATFORM__` является подпространством `__ENV_PROFILE__`, а не отдельным top-level root. `__LANG_STATE__`, `__GEO_STATE__` и `__SCREEN__` являются отдельными top-level module-state routes, потому что они обслуживают разные public surfaces и разные downstream consumers.

Норма для screen: источник screen metrics - `C.state.__SCREEN__`, не `C.state.__ENV_PROFILE__.__SCREEN__`.

### Navigator

```js
FernwehContext.state.__NAV_TOTAL_SET__
  __DATA_STORE_STATE__
    __WORKER_ENV_SNAPSHOT__
  __SCALAR_STATE__
  __OBJECT_STATE__
    userAgentData
      highEntropy
    plugins
      protoMethods
      pluginRecords
    mimeTypes
      protoMethods
      mimeRecords
    permissions
    storage
      estimate
    performance
```

`__NAV_TOTAL_SET__` является основным module-state для navigator-related surfaces и worker env snapshot source. Он же держит worker snapshot branch:

```txt
__NAV_TOTAL_SET__.__DATA_STORE_STATE__.__WORKER_ENV_SNAPSHOT__
```

Worker local materialization может копировать эту route-form внутрь worker realm, но не становится canonical owner для window truth-state.

### Canvas / WebGL / WebGPU / Audio

```js
FernwehContext.state.__CANVAS__.__STATE__
FernwehContext.state.__WEBGL_STATE__
FernwehContext.state.__WEBGPU__
FernwehContext.state.__WEBGPU_WL_STATE__
FernwehContext.state.__AUDIOCONTEXT__.__STATE__
```

`__CANVAS__.__STATE__` хранит canvas/offscreen operational state и canvas-specific defaults, включая shared ctx2d font и issued-canvas state. Canvas hook implementations живут в `FernwehHooks`, но state принадлежит `FernwehContext.state.__CANVAS__`.

`__WEBGL_STATE__` является текущим WebGL module-state. WebGL hook implementations живут в `webglHooks`, а registries и apply path живут в `FernwehContext`.

`__WEBGPU__` и `__WEBGPU_WL_STATE__` относятся к WebGPU patch/whitelist route. `__WEBGPU_WL_STATE__` хранит whitelist store, а `__WEBGPU__` - module runtime state.

`__AUDIOCONTEXT__.__STATE__` является module-state для AudioContext patch.

### Fonts

```js
FernwehContext.state.__FONTS__
  __STATE__
  __CONFIG__
```

`__FONTS__.__STATE__` хранит runtime status, loaded/ready/error state и related operational fields. `__FONTS__.__CONFIG__` хранит configs generated by font compound. Font module не владеет PRNG root и не создаёт собственный seed; он потребляет состояние/конфиг и зависит от общего seed pipeline.

### Headers

```js
FernwehContext.state.__HEADERS__.__STATE__
```

Headers state материализуется runtime stage в `main.py`/headers window stage и используется `headers_interceptor.js` / `headers_bridge.js`. Он не создаётся как отдельный public global и не является частью navigator state. Это отдельный module-state для outbound/safelisted header coordination.

### Stealth / RTC / webdriver

```js
FernwehContext.state.__HIDE_WEBDRIVER__.__STATE__
```

`hide_webdriver.js` использует `__HIDE_WEBDRIVER__.__STATE__` и профильные values из `__ENV_PROFILE__`. Он не должен создавать собственный hidden root.

`RTCPeerConnection.js` является patch module, но его состояние не формирует отдельный long-lived top-level state-route в текущей карте. Он обязан пользоваться `Core`, `FernwehContext`, logger-root и guard policy.

### Worker

```js
FernwehContext.state.__WRK__
  bootstrap
  runtime
  hooks
```

`__WRK__` является module-state для worker orchestration. Он содержит:

- bootstrap flags/source URLs/inline readiness;
- runtime inline sources (`inlinePatch`, `inlineReflect`, `inlineCoreWindow`, `inlinePrng`, `inlineCanvasPatch`, `inlineFernwehContext`);
- worker patch API;
- service-worker lane markers;
- toString bridge marker/API state;
- hook-related worker API state.

Worker state всегда realm-local. Window owner-state не переносится как object identity в worker. Worker получает bootstrap material, snapshot и seed, после чего строит локальную форму того же namespace.

## Service-layer vs module-state

Контрактно важно различать два уровня:

```js
FernwehContext.<service-slot>
FernwehContext.state.__MODULE__.<module-state>
```

Service-layer допускает только общие координационные поля:

- logger;
- lifecycle;
- hook registries;
- patch apply methods;
- runtime mirrors;
- bootstrap cleanup/retention status.

Module-state допускает только состояние конкретного модуля. Например:

```js
FernwehContext.__patchState
```

это lifecycle контекстного patch-layer, а:

```js
FernwehContext.state.__CANVAS__.__STATE__
```

это state canvas module. Эти роли нельзя смешивать.

## Runtime shell

Runtime shell - это исполняемый служебный слой, который помогает доставить callable/API, но не становится owner-state.

Допустимые runtime shells:

```js
FernwehContext.__prngRuntime__
FernwehContext.state.__WRK__.runtime
```

`FernwehContext.__prngRuntime__` может хранить `RNGsetModule` как callable mirror для orchestration. PRNG state при этом остаётся только в:

```js
Core.__internal.prng
```

`FernwehContext.state.__WRK__.runtime` хранит worker runtime API, inline sources и bridge markers. Он не является альтернативным root для navigator/profile/screen truth-state.

## PRNG namespace

Единственный canonical PRNG owner:

```js
Core.__internal.prng
```

Нормализованная форма:

```js
{
  seed,
  strToSeed,
  mulberry32,
  rand,
  pools,
  marker,
  version
}
```

Window seed input:

```js
window.__GLOBAL_SEED / G.__GLOBAL_SEED
```

разрешён только как bootstrap producer input для `prng_seed.js`. После owner-transfer downstream consumers читают только `Core.__internal.prng`.

Worker seed input:

```js
CDP_GLOBAL_SEED
```

не является env snapshot. Worker realm строит локальный `self.Core.__internal.prng`.


## Function.prototype.toString namespace

`Function.prototype.toString` регулируется как realm-local baseline и bridge system.

Window owner:

```js
Core.__internal.coreToStringState
```

Worker/service-worker bridge marker/API:

```js
FernwehContext.state.__WRK__.runtime.__CORE_TOSTRING_STATE__
```

Синхронизация между Window, DedicatedWorker, SharedWorker и ServiceWorker не является object transfer. У каждого realm свой `Function.prototype`, свои native function objects и свои WeakMap owners. Контракт требует structural parity: одинаковую архитектурную форму, одинаковый public descriptor principle и одинаковые wrapper APIs, но не общий shared object.


## Hook-layer

Hook-layer состоит из двух частей:

```js
FernwehHooks / webglHooks
  -> functional hook implementations

FernwehContext
  -> registries, register-functions, apply methods
```

`FernwehHooks` и `webglHooks` не владеют state. Они публикуют functions, которые `registerAllHooks` валидирует и регистрирует в registries `FernwehContext`.

Canvas/offscreen/ctx2D registries:

```js
htmlCanvasGetContextHooks
htmlCanvasToDataURLHooks
htmlCanvasToBlobHooks
offscreenGetContextHooks
offscreenConvertToBlobHooks
ctx2DGetContextHooks
ctx2DMeasureTextHooks
ctx2DFillTextHooks
ctx2DStrokeTextHooks
ctx2DFillRectHooks
ctx2DDrawImageHooks
```

WebGL registries:

```js
webglGetContextHooks
webglGetParameterHooks
webglGetSupportedExtensionsHooks
webglGetExtensionHooks
webglReadPixelsHooks
webglGetShaderPrecisionFormatHooks
webglShaderSourceHooks
webglGetUniformHooks
```

Apply methods:

```js
FernwehContext.applyCanvasElementPatches()
FernwehContext.applyOffscreenPatches()
FernwehContext.applyWebGLContextPatches()
```

`registerAllHooks` остаётся методом `FernwehContext` и не должен становиться standalone global export.

## Descriptor / patch vocabulary

Нормативные patch terms:

- `descriptor_only`;
- `strict_accessor_gateway`;
- `object_return_gateway`;
- `materialized_accessor_gateway`;
- `core_wrapper`;
- `brand_strict`;
- `promise_method`;
- `meta_primitive`;
- `constructor`;
- `proto_chain`;
- `owner_first`.

Эти термины описывают не стиль кода, а contract surface. Module patching обязан проходить через Core-governed preflight/apply/rollback path. Прямой `Object.defineProperty` допустим только внутри уже оговорённого low-level helper/bootstrap path или при явном создании hidden owner slot.

Если модуль не может выполнить patch без нарушения descriptor/receiver/native semantics, он должен выполнить diag-reported skip/rollback/failure, а не создавать альтернативный namespace.

## Worker namespace и scope parity

Worker lane является продолжением hidden container contract, а не отдельной моделью.

Dedicated/Shared worker path:

```txt
window __WORKER_ENV_SNAPSHOT__
-> wrk.js transport / inline sources
-> worker local FernwehContext
-> worker local FernwehContext.state
-> worker local Core.__internal.prng
-> WORKER_PATCH_SRC.js consumers
```

ServiceWorker path:

```txt
cdp_catapult.py
-> sw_prelude.js
-> service local FernwehContext
-> service local FernwehContext.state
-> service local Core.__internal.prng
```

Worker state is local copy, not shared object identity. `CDP_GLOBAL_SEED`, `inlinePrng`, `inlineReflect`, `inlineCoreWindow`, `inlineCanvasPatch`, `inlineFernwehContext` are transport/inline mechanisms required to build the same architecture inside the worker realm.

Worker rules:

- seed route is `CDP_GLOBAL_SEED`;
- screen route is local `FernwehContext.state.__SCREEN__`;
- env route is local `FernwehContext.state.__ENV_PROFILE__`;
- snapshot route is local `FernwehContext.state.__NAV_TOTAL_SET__.__DATA_STORE_STATE__.__WORKER_ENV_SNAPSHOT__`;
- toString route is local `FernwehContext.state.__WRK__.runtime.__CORE_TOSTRING_STATE__` plus local `Core.__internal.coreToStringState`;
- service worker uses its own `sw_prelude.js` lane and must not enter generic Dedicated/Shared bootstrap lane.

## Bootstrap transit and cleanup

Bootstrap input globals are transit values. They are not long-lived public API.

`bootstrap_hide.js` owns:

```js
FernwehContext.__bootstrapTransitStatus__
FernwehContext.__runBootstrapEnvCleanup__
```

Cleanup must respect worker snapshot readiness:

```js
FernwehContext.__workerEnvSnapshotReady__
FernwehContext.__bootstrapTransitStatus__.retention.workerEnvSnapshotReady
FernwehContext.__bootstrapTransitStatus__.retention.workerEnvSnapshotStage
```

Если worker snapshot retention ещё не готов, cleanup должен быть deferred/diagnostic-aware, а не silent destructive cleanup. Это особенно важно для worker bootstrap, потому что часть transit values нужна до materialization worker-local owner graph.

## Диагностика

Единый diagnostic route:

```js
FernwehContext.__logger.__DEGRADE__
FernwehContext.__logger.__DEGRADE__.diag
```

Module-local adapters (`__emit`, `degrade`, `__navDiag`, `__wrkDiag`, `__swDiag`, etc.) являются разрешёнными wrappers, если они маршрутизируют события в logger-root и не превращаются в самостоятельный logging root.

Прямой `console.*` не является нормативным diagnostic route.

Failure classes:

- `pipeline missing data`;
- `browser structure missing data`;
- `contract violation`;
- `pipeline telemetry`;
- `ok`.

Silent swallow нарушает namespace contract, если ошибка относится к owner-route, seed, descriptor, toString, worker bootstrap, hook registration или module-state readiness.

## Нормативный lifecycle

Актуальный lifecycle читается так:

1. Python/main stage формирует profile/bootstrap values, `global_seed`, headers, font manifest, CDP seed/service-worker bootstrap.
2. `init_params` публикует bootstrap inputs.
3. `bootstrap_hide.js` создаёт `FernwehContext`, `FernwehContext.state`, base module-state routes, `Core.__internal.prng`, logger owner, patch state, hook mode store и bootstrap transit status.
4. `set_log.js` поднимает logger/degrade route.
5. `core_window.js` валидирует `Core`, `Core.__internal`, `Core.__internal.prng`, строит descriptor/toString/guard/wrapper infrastructure.
6. `prng_seed.js` переносит seed из bootstrap input в `Core.__internal.prng`.
7. Domain modules заполняют свои `FernwehContext.state.__MODULE__` routes и регистрируют functions/hooks.
8. `context.js` нормализует service-layer, hook registries, register-functions и apply methods.
9. `registerAllHooks()` связывает `FernwehHooks` / `webglHooks` с registries `FernwehContext`.
10. `applyCanvasElementPatches`, `applyOffscreenPatches`, `applyWebGLContextPatches` применяют issued/contextual patches.
11. `wrk.js`, `WORKER_PATCH_SRC.js`, `sw_prelude.js` строят worker-local namespace и не переносят window owner identity.
12. Bootstrap cleanup выполняется только после retention gate.

Порядок может иметь технические inline-вставки, но owner dependencies не должны нарушаться: consumer не запускается до появления своего owner-route.

## Запрещённые namespace patterns

Запрещено:

- создавать module-state вне `FernwehContext.state.__MODULE__`;
- использовать `window.rand`, `window.strToSeed`, `window.mulberry32` как normative API;
- перевозить worker seed через env snapshot или `window.__GLOBAL_SEED`;
- публиковать `registerAllHooks` как standalone global;
- использовать hook namespaces как state owners;
- создавать отдельный logging root вне `FernwehContext.__logger`;
- смешивать service-layer `FernwehContext.__patchState` и module-state `__STATE__`;


## Практическая карта файлов

Основные файлы, которые формируют текущий namespace contract:

- `bootstrap_hide.js` - hidden owner graph, module-state roots, PRNG owner skeleton, transit cleanup;
- `set_log.js` - logger/degrade owner route;
- `core_window.js` - Core infrastructure, descriptors, toString, guards, wrappers;
- `context.js` - service-layer, hooks, registries, apply methods;
- `prng_seed.js` - PRNG producer into `Core.__internal.prng`;
- `nav_total_set.js` - navigator module-state and worker snapshot source;
- `screen.js` - `C.state.__SCREEN__` consumer/patch route;
- `font_module.js` - `C.state.__FONTS__` consumer;
- `canvas.js` - `C.state.__CANVAS__`, `C.state.__SCREEN__`, `Core.__internal.prng`, hooks;
- `webgl.js` - `C.state.__WEBGL_STATE__`, `C.state.__ENV_PROFILE__`, `Core.__internal.prng`, `webglHooks`;
- `webgpu.js` / `WebgpuWL.js` - `__WEBGPU__` and `__WEBGPU_WL_STATE__`;
- `audiocontext.js` - `__AUDIOCONTEXT__.__STATE__`;
- `hide_webdriver.js` - `__HIDE_WEBDRIVER__.__STATE__`;
- `headers_interceptor.js` / `headers_bridge.js` - `__HEADERS__.__STATE__`;
- `wrk.js`, `WORKER_PATCH_SRC.js`, `worker_bootstrap.js`, `set_reflect.js`, `sw_prelude.js` - worker-local namespace, seed, snapshot, toString and service-worker lane;
- `cdp_catapult.py` - CDP service-worker seed/prelude delivery.

## Проверочный чек-лист

Namespace contract выполнен, если:

- `Core` существует до downstream patches и имеет `Core.__internal`;
- `Core.__internal.prng` существует до `RNGsetModule`;
- `Core.__internal.coreToStringState` строится realm-local;
- `FernwehContext` существует как hidden container;
- `FernwehContext.state` является единственным root для module-state;
- screen source is `C.state.__SCREEN__`;
- headers source is `C.state.__HEADERS__.__STATE__`;
- fonts source is `C.state.__FONTS__`;
- worker source snapshot is `C.state.__NAV_TOTAL_SET__.__DATA_STORE_STATE__.__WORKER_ENV_SNAPSHOT__`;
- worker local state не претендует на ownership window state;
- service-worker использует `sw_prelude.js` lane;
- PRNG consumers читают `Core.__internal.prng`;
- worker seed route is `CDP_GLOBAL_SEED`;
- hook implementations живут в `FernwehHooks` / `webglHooks`, а registration/apply lives on `FernwehContext`;
- diagnostics идут через `FernwehContext.__logger.__DEGRADE__`;
- нет legacy roots, public helper globals или ad-hoc namespace, конкурирующих с `Core` / `FernwehContext` / `FernwehContext.state`.
